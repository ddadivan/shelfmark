# libs/ui

Shelfmark's own component library: tokens, themes, `ui-*` components and Storybook. Consumed by `apps/web` from source through the `@shelfmark/ui` path alias; it also builds as a library with ng-packagr (`nx build ui`). Design source: `docs/design/` (`BRAND.md`, `components/<Name>/README.md`, `components/Motion/README.md`). Decision record: `docs/adr/0017-libs-ui-foundation.md`.

## Presentational only

- No HTTP, no stores, no routing, no Transloco. Every visible string and every `aria-label` comes in through an input (or projected content); the feature translates it.
- Components know nothing about links, folders or users. Data in via inputs, events out via `output()`.
- Only `libs/ui` components are used by features; a missing component is added here first.

## Layout

```
libs/ui/
  .storybook/            main.ts, preview.ts, foundations.scss and illustration-stories.scss (styles of the docs pages and stories only)
  src/
    index.ts             public API, re-exports only
    assets/icons/        sprite.svg (served as /assets/ui/icons/sprite.svg)
    styles/              _functions, _media, _breakpoints, _focus, _utilities, _motion, _typography, tokens/*, _ui (Sass API), global.scss
    foundations/         Storybook "Foundations" docs stories (colours, type, spacing, motion, ...); not exported
    testing/axe.ts       axe-core helper for specs
    lib/<name>/          <name>.component.ts|html|scss|spec.ts|stories.ts, index.ts, models/
```

## Component rules

- One component (or directive) per folder, selector `ui-<name>`, standalone, `OnPush`, `host: {}` (no `@HostBinding` / `@HostListener`), signal `input()` / `output()` / `model()`, `inject()`.
- Variants, sizes and kinds are `as const` objects with a derived union type (ADR 0024, no TS `enum`): `models/<name>.const.ts` (`BUTTON_VARIANT = { Primary: 'primary', … } as const`) and `models/<name>.type.ts` (`ButtonVariant`, the union). The input keeps the union type, so `variant="primary"` still compiles in templates; in TypeScript, host expressions and bound template expressions use the constant (`input<ButtonVariant>(BUTTON_VARIANT.Secondary)`, `protected readonly CHIP_VARIANT = CHIP_VARIANT;`, stories `argTypes.options: Object.values(BUTTON_VARIANT)`). `KeyboardEvent.key` values come from the shared `KEYBOARD_KEY` (`lib/keyboard`). Numeric unions, catalogue tuples (`ICON_NAMES`), `Record` keys and ARIA / DOM / CDK identifiers stay literal. Booleans use `booleanAttribute`.
- Behaviour (keyboard, focus, ARIA, overlays) comes from native elements first, then Angular Aria / CDK. No Angular Material, no Tailwind, no third-party icon sets, no `@angular/animations`.
- Templates in `.html`, styles in `.scss` files (stylelint does not see inline `styles:`).
- Follow `.claude/skills/create-ui-component` and `angular-v22-rules`.

## Styles

- Colours, spacing, radii, durations and easings only through CSS custom properties from the tokens; no hard-coded colours, no `!important`, no `::ng-deep`.
- Component SCSS starts with `@use '../../styles/ui' as *;` (relative path, works in every builder). It gives `rem($px)`, `type($style)`, `hover`, `reduced-motion` and the mixins below.
- Sizes in `rem` via `rem(24px)`. Plain `px` is allowed only for border widths, `outline`, `outline-offset` and `box-shadow` (and `--shadow-*` tokens). Breakpoints in `em`. stylelint enforces this (`npm run lint:styles`).
- The 2px top progress bar is the one other `px` exception and needs a described disable: `/* stylelint-disable-next-line unit-disallowed-list -- 2px progress bar per spec */` (descriptionless disables are reported).
- Class names are BEM (`ui-button--primary`, `ui-icon__svg`).
- `:hover` only through the `hover` mixin (`@media (hover: hover)`); `:focus-visible` uses `@include focus-ring`; wrap movement and scale in `@include reduced-motion`.
- Type styles come from the `type($style)` mixin (display, title, heading, body, label, caption, mono); there are no global type classes.

## Shared mixins, keyframes and breakpoints

All come from `@use '../../styles/ui' as *;` and are tested in `src/styles/styles.spec.ts` (the spec compiles the Sass and checks the output, including the reduced-motion fallbacks).

| Mixin                                     | Use                                                                                                                                                                                                                                                                                                                                                                               |
| ----------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `focus-ring($offset: 2px)`                | Declarations for `&:focus-visible`: 2px solid `focus-ring` outline, 2px offset. Never hand-write the ring.                                                                                                                                                                                                                                                                        |
| `field-focus`                             | On a text-field wrapper (required for every field): 120 ms transition, `:focus-within` turns the border `focus-ring` and adds the soft 3px halo (transparent outline stays for forced colours). It also removes the global outline from the bare `input` / `textarea` / `[contenteditable]` inside, so there is one indicator; a field without the wrapper keeps the global ring. |
| `visually-hidden`                         | Screen-reader-only text: live regions, "Step N of M".                                                                                                                                                                                                                                                                                                                             |

| `phone`, `tablet`, `tablet-up`, `desktop` | Breakpoints in `em`: phone `< 40em`, tablet `40em` to `< 64em` (63.99em), desktop `>= 64em`; `tablet-up` is `>= 40em`. Range syntax: no gaps, no overlaps.                                                                                                                                                                                                                        |
| `enter($name)`, `leave($name)`            | Animation presets (below) with duration and easing tokens and a built-in reduced-motion fallback.                                                                                                                                                                                                                                                                                 |

Reduced motion: spinner and bar slower, shimmer stops.                                                                                                                                                                                                                                                                                 |

| `hit-area($inset, $coarse-inset: null)`   | Invisible hit area around a small control: the host becomes `position: relative` and an absolute `::after` grows the target by the negative `rem` offsets (1 to 4 values, as `inset`); `$coarse-inset` replaces them under `pointer: coarse`. The visible size does not change.                                                                                                   |
| `touch-target($size: 44px)`               | `min-width` / `min-height` of `$size` (default 44px) in `rem`, for controls that must grow on coarse pointers.                                                                                                                                                                                                                                                                    |

**Keyframes** are defined once, in `global.scss` (`@include keyframes`), prefixed `ui-`: `pop-in`, `pop-out`, `fade-out`, `reveal`, `sheet-in`, `sheet-out`, `slide-up`, `toast-out`, `spin`, `spinner-in`, `spinner-grow`, `spinner-out`, `spinner-shrink`, `shimmer`, `progress`, `ripple-grow`, `ripple-fade`. Components never declare `@keyframes`; they use a preset or, for a new moment, add the keyframes to `_motion.scss`.

**Presets** (duration, easing): `enter(pop)` 200 ms `ease-out` (menus, listboxes, dialogs), `enter(fade)` 200 ms (skeleton to content), `enter(toast)` 320 ms `ease-out`, `enter(sheet)` 320 ms `ease-drawer`, `enter(spinner)` / `enter(spinner-grow)` 200 ms (plus the spin). `leave(pop)` / `leave(fade)` 120 ms `ease-out`, `leave(toast)` 120 ms `ease-in`, `leave(sheet)` 200 ms `ease-in`, `leave(spinner)` / `leave(spinner-shrink)` 120 ms. Presets are finite (no `infinite`), so `animate.leave` can finish; a spinner's rotation is `@include loop(spin)` on the inner element, never on the element that has `enter` / `leave`. Under `prefers-reduced-motion: reduce` every `enter` becomes `ui-reveal` (200 ms fade) and every `leave` a `ui-fade-out`; movement and scale are gone (so `enter(spinner-grow)` loses its margin growth and the label does not slide).

**Convention for Angular animations.** Put the preset in a modifier class and bind it with `animate.enter` / `animate.leave` on the element that appears and disappears:

```scss
.ui-menu--enter {
  @include enter(pop);
  @include origin;
}

.ui-menu--leave {
  @include leave(pop);
}
```

```html
<div class="ui-menu" animate.enter="ui-menu--enter" animate.leave="ui-menu--leave">…</div>
```

Angular keeps the element until the leave animation ends and a second toggle mid-animation reverses it. Menus and listboxes scale from their trigger: the overlay sets `--ui-origin` (for example `100% 0`) on the panel from its anchor; dialogs keep `center`. The ripple is the `uiRipple` directive (below). The FLIP helper, the "card lands" moment, View Transitions and the logo animation are not part of this foundation.

## Trigger API and ripple (ADR 0021)

`ui-button` stays a wrapper around a native `<button>` (or an `<a>` with `href`). Attributes and directives on `<ui-button>` land on the non-focusable host, so:

- **ARIA inputs** on `ui-button` go to the inner element and render nothing when unset: `ariaLabel`, `ariaExpanded`, `ariaControls`, `ariaHaspopup`, `ariaDescribedby`, `ariaPressed`.
- **Focus target**: `focus(options?)` and the `element` signal (inner native element). `UI_FOCUS_TARGET` (`UiFocusTarget`) is provided by `ui-button`; a trigger directive (tooltip, menu trigger, overlay origin) does `inject(UI_FOCUS_TARGET, { optional: true, self: true })` and falls back to its host `ElementRef`. Any new wrapper component with an inner native control provides it too.
- **Links**: `href` renders an inner `<a>` with the same classes; `(linkClick)` fires for plain left clicks (no modifier key), the feature calls `preventDefault()` and routes (`routerLink` is not available here). A disabled link has no `href`, `role="link"`, `aria-disabled="true"` and swallows clicks.
- **`uiRipple`** works on any host (rows, menu items, chips): pointer origin, Enter / Space from the centre, cancelled by a move over 10 px, no ripple when `disabled` / `aria-disabled`, `[uiRipple]="false"` opts out, `uiRippleIgnore=".selector"` (or, for a host directive, the `UI_RIPPLE_IGNORE` token) skips pointer and Enter / Space events whose target is inside a matching region without stopping them from bubbling, no ripple under reduced motion. Colour `currentColor` at 6% / 10% (dark); a host raises it with `--ui-ripple-opacity` (filled buttons: 0.2). Its styles are the global `ripple` mixin in `global.scss` (the span is created at runtime, outside view encapsulation). The host class `ui-ripple-host` sets `position: relative`, `overflow: hidden`, `isolation: isolate` through `:where()` (zero specificity), so a host that needs `absolute` or `sticky` just sets its own `position`; the ripple only needs a positioned host. `ui-button` applies it on the inner element; `[ripple]="false"` opts out.

## Illustrations, logo and empty states

- `ui-illustration` draws the 8 scenes as inline SVG in its template (no `innerHTML`, no inline `style`, fills are token-bound classes). `motion` is `loop` (3-5 s cycle, landing / welcome / sign-in), `once` (plays, then holds the final frame; empty states and errors) or `none`; the caller picks it and each scene has a default (`ILLUSTRATION_DEFAULT_MOTION`: welcome scenes loop, the rest play once). Resting styles are the final frame, so `none` and `prefers-reduced-motion` just remove the animation.
- Scene keyframes (`ui-ill-*`) and the two durations live in `styles/_illustration.scss` (`@include illustration-keyframes` in `global.scss`), apart from the shared presets; offsets are percentages of the element box, set through `--ill-*` custom properties on the scene classes.
- Loops run continuously. The app may later pause off-screen ones (for example with an `IntersectionObserver` toggling `motion` to `none`); the component does not do that itself.
- `ui-logo`: `variant` `lockup` / `mark`, `tone` `color` (theme tokens) / `mono` (`currentColor`), mark size through `--ui-logo-size`.
- `ui-empty-state`: `illustration` or `icon`, `heading` (not `title`: that would add a native tooltip), `text`, `headingLevel`; the action is projected content.

## Overlays and tooltip (issue #26)

- **CDK overlay CSS** is included once in `global.scss` (`@use '@angular/cdk' as cdk; @include cdk.overlay` — the CDK exports Sass only from its root entry), so overlays are styled before the CDK loads anything. This does not remove runtime styles: the CDK `OverlayContainer` and component `styleUrl`s still add `<style>` elements, so under the strict CSP `apps/web` needs the nonce from ADR 0022 before an overlay renders. Storybook adds `node_modules` to the Sass `loadPaths` for that bare `@use`; the Angular builder resolves it itself. `@angular/cdk` is a peer dependency of `libs/ui`.
- **`UiOverlay.connect({ origin, positions, layer, panelClass? }, { injector?, onPositionChange? })`** returns a `ConnectedOverlay` (flexible position with flip, push on screen, reposition on scroll, no backdrop). `--ui-origin` is set on the pane from the resolved position (`overlayTransformOrigin`, `setOverlayOrigin`, `connectedSide`; `sidePositions(side)` gives preferred plus opposite). The owner renders content that appears and disappears with `@if` + `animate.enter` / `animate.leave` (a `pop` preset with `@include origin`), then calls `release()`: it detaches after the leave animations end (`getAnimations`), `cancelRelease()` / a new `attach()` makes a second open mid-animation work. Pass the owner's `injector` so the overlay is disposed with it.
- **Layers** (z-index, class `ui-overlay-layer--<layer>` on the CDK host element `overlayRef.hostElement`, the stacking context): dialog 1000 (scrim and panel), menu 1010, toast 1020, tooltip 1030. Floating panel surface: `@include popover`.
- **`uiTooltip`** (`uiTooltip`, `position`, `delay` 400, `uiTooltipShortcut`): hover and keyboard focus, closes on blur, pointer leave, activation and Esc (capture on `document`, stops propagation so a surrounding dialog or menu keeps its own Esc, focus does not move); hoverable (the gap is padding of the panel); never on `(hover: none)` or touch pointers. `aria-describedby` goes on the `UI_FOCUS_TARGET` element (inner button of `ui-button`) or the host, merged with an existing value, and skipped when the text equals the target's `aria-label` (no double announcement on icon-only buttons; re-checked when the text changes and each time the tooltip opens); it points at a visually hidden description in `<body>` and the visible panel is `aria-hidden`. Do not also bind `ariaDescribedby` on a `ui-button` with a tooltip. An overlay lives in `<body>`, so it takes the theme of `<html>`, not of a nested `data-theme` wrapper.

## Menu (issue #27)

- `ui-menu` (Angular Aria `ngMenu` as a host directive), `ui-menu-item` (`icon`, `shortcut`, `danger`, `disabled`, `selected`, `type` `item | checkbox | radio`, output `activated`; the host is always `role="none"`, the inner element carries the menuitem role and `aria-checked`), `ui-menu-separator`, and the `uiMenuTrigger` directive. Open with `uiMenuTrigger` on a `ui-button`, or in code: `menu.openFrom(element, { focus })`, `menu.openAt({ x, y })` (context menu; focus returns to the previously focused element), `close()`; `isOpen`, `anchor`, `opened` / `closed`. `align` `start | end`, `ariaLabel`; `inline` renders in place and always open for Storybook and docs only (features must not use it).
- **Trigger decision:** Aria `MenuTrigger` writes its attributes and tabindex on its own host, which for `<ui-button>` is not the focusable element, so `uiMenuTrigger` implements the trigger half itself (click, ArrowDown / ArrowUp, Enter / Space on non-buttons) on the `UI_FOCUS_TARGET` element and writes `aria-haspopup`, `aria-expanded`, `aria-controls` there directly (a directive cannot set another component's inputs; do not also bind those inputs on the button). The popup, arrows, Home / End, Enter / Space and typeahead stay Aria's.
- The host element of `ui-menu` is moved into the overlay pane with a `DomPortal` (`ConnectedOverlay.attachElement`) so Aria's host listeners keep seeing the items; closed, it is hidden and empty. Initial focus is set by dispatching Home / End to the menu, so Aria's active item matches DOM focus. Esc, Tab, an outside press and a choice close it; Esc and a choice return focus first, then `activated` emits. `ConnectedOverlayConfig.origin` also takes a viewport point.

## Chip, avatar, notice, steps (issue #25)

- `ui-chip`: `variant` `tag | neutral`, `clickable` (inner `<button>` with `uiRipple`, output `clicked`), `removable` (separate remove button named by `removeLabel`, output `removed`; Delete / Backspace anywhere in a removable chip also emits it), `disabled`, `icon`. The label is projected; there is no ripple on a non-clickable chip or on the remove button. `focus()` focuses the clickable body, else the remove button. After `removed` the removed chip is gone and focus is lost: the feature must move focus (to a sibling chip via `focus()`, or to the input in a TagInput).
- `ui-avatar`: `src`, `name`, `size` `sm | md | lg`, `label`. Initials (`initialsOf`, grapheme-safe, first and last word; it upper-cases first, so `ß` gives `S`) when `src` is absent or fails (the CSP blocks external hosts; `linkedSignal` retries on a new `src`), a user icon without a name. Decorative (`aria-hidden`) unless `label` gives it `role="img"`.
- `ui-notice`: `kind` `warning | danger`, `icon` override. `warning` is `role="status"`, `danger` `role="alert"`. `ViewEncapsulation.None` with `.ui-notice` selectors so projected links are styled. A live region announces reliably only when content appears in it, so render a notice on demand (`@if`) when an announcement is wanted; one present at page load is not announced.
- `ui-steps`: `count`, `current` (1-based), `label` ("Step N of M", visually hidden, polite live region); dots are `aria-hidden`; earlier dots look like upcoming ones, as in the spec.
- Story layout for these lives in `.storybook/display-stories.scss` (`ds-` classes).

## Dialog (issue #28)

- `DialogService.open<C, R, D>(Component, { size, data, dismissible, scrimClose, role, describedBy, autoFocus })` returns a `UiDialogRef<R, C>` (`close(result?)`, `afterClosed()`, `result` promise, `leaving`, `componentInstance`, `hostElement`). `confirm({ title, message, confirmLabel, cancelLabel, closeLabel?, destructive? })` resolves a boolean: true for confirm; false for Cancel, the close button, Esc and the scrim. All strings come in.
- The content component renders `<ui-dialog title="…" closeLabel="…" [size]>` with the body as content and footer buttons as `slot="footer"` (secondary first, main action last), reads `injectDialogData<T>()` and closes through the injected `UiDialogRef`. A `<form>` may wrap `ui-dialog`. The close button exists only with `closeLabel`; an overflowing body becomes a focusable region.
- Built on CDK `Dialog` (focus trap, focus restore, `aria-modal`, scroll lock, page hidden from AT). The service sets `disableClose` and handles Esc and the scrim itself, so every close plays the leave animation first (`UiDialogRef.close()`: `leaving` signal, `getAnimations`, 800 ms safety timer); focus returns when the overlay is removed. `dismissible: false` turns Esc and scrim off; `scrimClose: false` only the scrim (destructive confirm).
- **Layer:** `ui-overlay-layer--dialog` goes on `overlayRef.hostElement` (`setOverlayLayer`); the scrim is the CDK backdrop with `ui-dialog-scrim` (+ the layer class: a sibling of the host unless the CDK uses a popover host, as in 22). `ui-dialog-scrim` and the wrapper placement (centred; bottom edge below 40em) are global (`styles/_dialog.scss`, `@include dialog-layout` in `global.scss`).
- **Phone sheet** (`< 40em`): `enter(sheet)` / `leave(sheet)`, grip, 44px close button; dragging the grip or header sets `--ui-sheet-drag` (CSSOM, no `style` attribute); release past 30% of the height or a flick over 0.5 px/ms closes (`shouldCloseSheet`), else snaps back. Reduced motion: fade only, the drag still works. Desktop: `enter(pop)` / `leave(pop)` from the centre.
- Confirm focus: confirm button, or Cancel when destructive (`confirm` sets this itself). **`autoFocus` defaults to `first-tabbable`, which is the header close button**, so every form dialog must pass `autoFocus: '<selector>'` (for example `'input'`) to land on its first field; the form story does. `_recaptureFocus` (scrim click on a non-closing dialog) is internal CDK API, checked against 22.2.x.
- Sheet release speed: the last 3 pointer samples; a pause of 100 ms or more before the release counts as speed 0 (no flick). The phone sheet width stays `100vw` (the pane is shrink-to-fit, so `100%` would collapse to the content width).

## Loading (issue #23)

- Pick the indicator by what loads (Loading spec): `ui-button [loading]` for an action the user started, `ui-progress-bar` for navigation and background requests, `ui-meter` for known progress, `ui-load-more` under a list, `ui-save-status` for autosave, skeletons for first loads.
- **`ui-spinner`** (`size` `sm | md | lg`, optional `label`): ring in `currentColor`, rotation on the inner `__ring` (`loop(spin)`), `enter(spinner)` on the host when it is created. Without `label` it is `aria-hidden`; with it, an indeterminate `progressbar`. It leaves only when its owner removes it with `animate.leave` and a class using `@include leave(spinner)` (`spinner-shrink` inside a button); the components below do that already.
- **`ui-button [loading]`**: spinner with `enter(spinner-grow)` (label makes room), `aria-busy="true"`, no ripple, `cursor: progress`. Activation (clicks, Enter / Space, form submit) is blocked by `preventDefault()` plus a capture-phase host listener that calls `stopImmediatePropagation()` only while loading: `(click)` on `<ui-button>` does not fire; document capture listeners (the CDK overlay's outside-press) still see the event, bubble listeners above the button do not. A loading `href` button renders like a disabled link (no `href`, `role="link"`, `aria-disabled="true"`, not dimmed), so middle-click and the context menu cannot navigate. The button stays focusable (not `disabled`). The width is locked in px on the inner element: a `ResizeObserver` keeps the rest width (fallback without one: read after each render), the lock is set when `loading` turns true and released after the leaving spinner's animations finish. The feature changes the label to the -ing form itself. The spinner replaces `iconLeft`; icon-only buttons show a solo spinner (`enter(spinner)`).
- **`ui-progress-bar`** (`active`, `variant` `fixed | inline`, optional `label`): presentational, the app binds `active`. `fixed` is the 2px sage bar at the top of the viewport (z-index 900, below overlays), shown only after 300 ms of `active`; `inline` is a 3px track in a box, shown at once. On finish it fills to 100% and fades (`ui-fade-out`, removed on `animationend`). The 2px height is the described stylelint disable. A finished bar is removed on `animationend` / `animationcancel` of the fade or, as a fallback, after 450 ms; `inline` skips the 300 ms helper. Without `label` it is `aria-hidden`.
- **`ui-meter`** (`value` 0-100, clamped; required `label`): `role="progressbar"`, `aria-valuenow`; percent text is the feature's. **`ui-load-more`** (`text`, `loading`): the host is a persistent `role="status"` live region (keep it rendered, bind `loading`; a region inserted already filled is often not announced), the spinner `sm` plus text row exists only while `loading`. **`ui-save-status`** (`state` `saving | saved | error`, `savingText`, `savedText`, `errorText`): icon plus words in a polite status region; the icons share one 16px slot.
- **`loaderVisible(busy, { delay?, minVisible?, injector? })`** (`lib/loader-timing`): turns a `busy` signal into a `visible` signal that goes true after 300 ms and stays true for at least 400 ms once shown (`LOADER_SHOW_DELAY_MS`, `LOADER_MIN_VISIBLE_MS`); a response faster than the delay shows nothing. Call it in an injection context; timers are cleared on destroy. Features bind loaders to its result, never to the raw request state.

## Tree (issue #33)

- `ui-tree` (`nodes`, `fixedNodes`, `activeId`, `heading`, `ariaLabel`, `menuLabel`, `menuNodeId`; outputs `selected`, `toggled`, `contextMenu`) on Angular Aria `ngTree` in `nav` mode (`aria-current`, not `aria-selected`) with `ngTreeItem` / `ngTreeItemGroup` in one recursive template. `UiTreeNode` is `{ id, name, icon?, count?, expanded?, children? }`; `expanded` is only the initial state. Fixed rows are flat and have no button; folder rows get a chevron slot, a default `folder` icon and the "..." button (only with `menuLabel`; `{name}` is replaced by the folder name).
- The tree only emits. `contextMenu` carries `{ node, trigger, anchor, position }` (`trigger` is `UiTreeContextMenuTrigger`, values in `UI_TREE_CONTEXT_MENU_TRIGGER`: `pointer`, `button`, `keyboard`): the feature calls `menu.openAt(position)` for a right click and `menu.openFrom(anchor)` otherwise (the button's inner element, or the row for Shift+F10 / the context-menu key), and binds `menuNodeId` while the menu is open (`aria-expanded` on that button). **Keyboard routes to the folder menu** (folder rows, also from the "..." button): the context-menu key, Shift+F10 and Alt+Enter (laptops without a context-menu key) emit `contextMenu` with `trigger: 'keyboard'` and the row as anchor. A held key emits once; the browser's echoed `contextmenu` event is swallowed through a one-shot flag (cleared by the first echo, 100 ms after keyup, on blur, or after a 1 s safety timeout); a `contextmenu` at 0, 0 is treated as keyboard. Other keys pressed on the "..." button never reach the Aria tree (the row stops them), so Enter and Space only click the button. Pressing the button does not ripple the row. The "..." button is `tabIndex` -1 (a new `ui-button` input) so rows stay one tab stop.
- Aria specifics: the `treeitem` is the row `div` (roving focus, ring, active background, ripple); its `li` is `role="none"` and the child group is a sibling `ul role="group"` linked by `aria-owns`, so the row's accessible name never includes its children (axe `label-content-name-mismatch` fails on a treeitem that contains its group). A row click chooses and toggles (Aria), the chevron only toggles. **Tab-stop limitation:** Aria 22.2.5 nav mode has no selected row and no public API to set the active item, so Tab lands on the first row, not on the current one (arrows then move from there). Mitigation: the feature can offer a "skip to current" control that focuses the current row (`document.getElementById`-free: query `[aria-current]` inside the tree and call `focus()`; Aria follows focus on the next key press only after a click, so prefer a click-free, visible link next to the tree). `preserveContent` keeps closed groups rendered so they can animate; they are `visibility: hidden` after the close. The section heading is an `aria-hidden` `role="presentation"` list item (decorative; give `ariaLabel` the context). Each row is named through `aria-labelledby` (name and count), never by its children.
- Motion: chevron 120 ms, children by `grid-template-rows` 200 ms `ease-in-out`, both off under reduced motion; ripple on rows; level indent is `--ui-tree-level` (CSSOM, 16px per level).

## Form fields (issue #24)

- **Signal Forms binding.** The Angular 22 directive is `[formField]` (`FormField` from `@angular/forms/signals`; there is no `[field]`). A field component implements `FormValueControl<T>`: a `value` `model()`, plus optional inputs the directive fills (`disabled`, `required`, `errors`, `touched`, `maxLength`, `name`) and a `touch` output (emit on blur) that marks the field touched. Features write `<ui-input label="Link" [formField]="form.url" />`; messages come from the validators (`required(p.url, { message })`), already translated. Without a form use `[(value)]` and the manual `error` input. Reactive and template-driven forms are not used.
- **`UiFieldControl`** (abstract directive, `lib/field`): the shared half of a field: `label`, `hint`, `error` (manual, always wins), `disabled`, `required` (`aria-required`, no native `required`), `errors`, `touched`, `touch`, plus protected `controlId`, `message` (first message of a touched field), `showInvalid`, `describedBy` and an overridable `counterText()`. `ui-select` and `ui-tag-input` extend it, add their `value` model and render the shell.
- **`ui-field-shell`** (`controlId`, `label`, `hint`, `error`, `invalid`, `disabled`, `counter`, `counterLabel`, `mono`, `multiline`): label above, bordered control box with `field-focus` (projected content goes inside), message row. The error is a persistent `aria-live="polite"` element; while an error shows, the hint stays in the DOM, visually hidden, so `aria-describedby` (`fieldDescribedBy(controlId, parts)`: error, hint, counter) still reads both. Ids come from `nextFieldId()`, `fieldHintId()`, `fieldErrorId()`, `fieldCounterId()`.
- **Projected parts are styled by the hosting field**, not the shell (view encapsulation): include `field-native` (bare `input` / `textarea`, no own border or outline) and `field-icon-button` from `lib/field/_field-parts.scss` (`@use '../field/field-parts' as *;`).
- **`ui-input`** (`type` `text | url | search`, `placeholder`, `icon`, `clearable` + `clearLabel`, `shortcut`, `loading`): `url` is mono with a URL keyboard; `search` defaults to the search icon and swaps it for `ui-spinner` in the same 16px slot while `loading`. The clear button keeps focus in the field and is rendered only when `clearable` and `clearLabel` is non-empty (no nameless button). The search spinner swap is visual only: the feature owns any live announcement of loading. **`ui-textarea`** (no native `maxlength`: the Signal Forms `maxLength` rule reports overflow, including pasted or loaded text; `rows` 3, grows to `TEXTAREA_MAX_ROWS` 8 through CDK `cdkTextareaAutosize`, `maxLength` with counter `n / max`, `counterLabel`). **`ui-radio-group`** (`options` `{ value, title, description? }`, `orientation`, `ariaLabel` / `ariaLabelledby`, `name`): native radios, arrows move and select, Tab enters the checked option; `touch` fires when focus leaves the group. It has no required/error display yet; add it through `UiFieldControl` when a feature needs it.
- **Validators must carry a `message`**: an error without one puts the field in the invalid state (`aria-invalid`, danger border) but shows no text.

## Toast (issue #29)

- **`ToastService.show({ text, kind?, action?: { label, run }, duration? })`** returns `{ dismiss(), closed }` (`dismiss()` on the service closes the current one). `closed` is a `Promise<ToastCloseReason>` that resolves exactly once and never rejects: `action` (the action button was used, even if it threw), `timeout` (the hover/focus-paused timer ended), `dismissed` (`dismiss()` on the ref or the service), `replaced` (a newer toast took its place); values are `TOAST_CLOSE_REASON`. The action dismisses first and then runs, so an action that shows another toast still settles `action`. If the injector is destroyed with a toast pending, it settles `dismissed` (never pending forever). `kind` `info | success | error` (default `info`, own icon each); text and action label are already translated by the feature. 4 s, 8 s with an action (`TOAST_DURATION_MS`); the timer pauses while the toast is hovered or has focus and resumes with the time left. Running the action dismisses (even if it throws). One toast at a time: a newer one replaces the older (Feedback screen shows no stack).
- Rendered through `UiOverlay.global({ layer: 'toast', edge? })`: a full-width pane on the viewport edge with `ui-overlay-pane--passthrough` (`pointer-events: none`), the toast takes pointer events itself; bottom-centre below 40em, bottom-left from `tablet-up`. `ToastService` creates the region when it is first injected and never detaches it: ONE `role="status"` / `aria-live="polite"` region (`ui-toast-region`, internal), toasts are added and removed inside it with `animate.enter` / `animate.leave` (`enter(toast)` / `leave(toast)`), so a region is never inserted already filled. Inject the service early in the feature. Focus is never moved.
- `duration: 0` keeps the toast until it is dismissed. An action that throws goes to the `ErrorHandler`; the toast is dismissed either way. A toast that replaces another under a resting pointer starts paused until the pointer leaves.
- **Keyboard reach:** the toast is outside the tab order of the page, and its timer can end before a keyboard user tabs to it. `ToastService.focusAction()` moves focus to the current toast's action (only on that explicit call; the timer pauses while focused; no-op without a toast or action). (a) The app must bind a global shortcut that calls it (decided with the app shell in stage 2/3). (b) Where feasible an action should also have a persistent alternative in the UI (for example Undo in the item's menu).
- `ui-toast` is the exported view (`kind`, `text`, `actionLabel`, outputs `action`, `pausedChange`); features use the service, not the component. State and timer are in the internal `ToastStore`.

## Select (issue #30)

- **`ui-select`** extends `UiFieldControl` and implements `FormValueControl<string | null>`: `options` (`SelectOption` tree `{ id, name, children? }`), `searchable`, `emptyLabel` (text of the `null` option; no default and no empty option without it: the "Unsorted" of the design comes from the app through Transloco), `placeholder`, `searchLabel` (name and placeholder of the search box, required with `searchable`), `noResultsLabel`; plus the field inputs. All strings come in. `focus()` focuses the trigger.
- **Aria wiring:** trigger is a native `<button ngCombobox>` (role `combobox`, so `<label for>` names it and a disabled field is natively disabled: `softDisabled` false); the popup is `ngComboboxPopup` + `ngComboboxWidget` + `ngListbox` (`focusMode="activedescendant"`, `selectionMode="explicit"`, `tabindex="-1"`) with `ngOption` rows. DOM focus stays on the trigger, or in the search box; Aria relays arrows, Home / End, Enter, Space and typeahead from the trigger. The search box relays ArrowUp / ArrowDown / Enter itself (Home / End only while the box is empty or with Ctrl / Cmd, so they still edit text). Aria's own focus-out close is kept: the popup wrapper forwards `focusin` / `focusout` to the public `ComboboxWidget.onFocusin` / `onFocusout`, and a press inside the popup is `preventDefault`ed so focus never leaves the trigger or the search box. The search box is a `role="combobox"` (`aria-expanded="true"`, `aria-haspopup="listbox"`, `aria-controls`, `aria-activedescendant`); with a search box the widget's `activeDescendant` input (which feeds the trigger's `aria-activedescendant`) is left undefined, so only the search box points at the active option. A focus-out without a related target while `document.hasFocus()` is false (window or tab switch) keeps the popup open and fires no `touch`; Aria's resulting close is undone.
- **Popup:** the wrapper element (empty `ng-template ngComboboxPopup` inside) is moved into a `UiOverlay` pane (layer `menu`, `menuPositions('start')`) with `attachElement`, as `ui-menu` does; its content is rendered by Aria while expanded, with `animate.enter` / `animate.leave` (`pop`, `--ui-origin`). The pane's `min-width` follows the trigger width (CSSOM) on open, on every reposition and through a `ResizeObserver` on the trigger (disconnected on close and destroy); the wrapper grows to it. Long lists scroll inside the panel (max 20rem), the search box stays above. There is no separate phone sheet (the spec has none): the popup keeps the trigger width and flips above when there is no room.
- **Nesting:** rows are the tree flattened (`selectRows`), indent `calc(10px + level * 16px)` through `--ui-select-level` (CSSOM, no `style` attribute); nested rows also get `aria-label` = path (`Work / Angular`). Filtering keeps matches with their ancestors. A `role="status"` region (persistent) shows `noResultsLabel`.
- **Aria quirks handled:** Aria prunes a selected value whose option the filter removed (`valueChange` with `[]`): ignored unless the current option is still visible (then it is a repeated choice, which Aria toggles off: value kept, popup closes). `touch` fires when the popup closes or the closed trigger blurs. Esc is stopped while open so a surrounding dialog keeps its own.

## Tag input (issue #31)

- **`ui-tag-input`** extends `UiFieldControl` and implements `FormValueControl<string[]>`: `suggestions` (`TagSuggestion` `{ name, countLabel? }`; the count text, "12 links", comes from the feature), `maxTags` (unlimited when unset), `placeholder`, `maxTagsLabel` (replaces the placeholder and is announced at the limit), `createLabel` (`Create tag “{name}”`; without it there is no create row), `removeLabel` (`Remove tag {name}`), `addedLabel` / `removedLabel` / `duplicateLabel` (`Tag {name} added`, `Tag {name} removed`, `Tag {name} is already added`; announced through a persistent visually hidden `role="status"`), `listLabel` (accessible name of the suggestion list, "Tag suggestions"; `label` when empty), plus the field inputs. `focus()` focuses the input. Chips are removable `ui-chip`s inside the field box, which wraps.
- **Adding:** Enter or a comma (`TAG_SEPARATOR`) adds the typed text; it is trimmed, cut to `TAG_MAX_LENGTH` 50 and ignored when the tag exists (compared ignoring case) or `maxTags` is reached. Pasting `a, b, c` adds each part. Tab is not a separator (it moves on). An Enter in an empty input is not swallowed (form submit). Backspace in the empty input removes the last tag; the chip's button (or Delete / Backspace on it) removes it and focus goes to the chip now at that place, else the previous one, else the input. The pure logic is `tagRows`, `normalizeTag`, `includesTag`, `fillName` (`tag-input-rows.ts`).
- **Aria wiring:** the input is the `ngCombobox` (editable: Aria opens on typing and ArrowDown, writes `aria-activedescendant`, `aria-controls`, `aria-expanded`, relays arrows and Enter to the listbox); DOM focus never leaves the input. The popup is `ngComboboxPopup` + `ngComboboxWidget` + `ngListbox` in a `UiOverlay` pane like `ui-select` (layer `menu`, pane `min-width` = field box width through a `ResizeObserver`). Aria's `expanded` is kept equal to `wanted && rows exist` by an effect (a `syncing` flag keeps that write from counting as a user close), so an empty result never shows `aria-expanded="true"`. **Enter semantics:** Aria activates the first option on open, so after every row change the option Enter adds is activated and announced: the exact existing tag, else the "Create tag" row (`gotoIndex` in a microtask, after Aria re-sorts its options). Arrows move to a suggestion, Enter then chooses it. The listbox value is reset to `[]` after each choice, so the same row can be chosen again. Blank-only text offers nothing.
- **Esc** is stopped while the list is open. A press on the box padding or a chip label is `preventDefault`ed (the input keeps focus, no early `touch`); the focus-out of a chip button destroyed by a removal has no related target and is ignored. `touch` fires when focus leaves the whole field (chips and input), not for a window or tab switch. At `maxTags` the input is read-only and nothing is offered.
- **Signal Forms:** `required()` does not treat an empty array as empty; use `minLength(p.tags, 1, { message })` for "at least one tag".

## Segmented control and breadcrumbs (issue #32)

- **`ui-segmented-control`** (`options` `{ value, label, icon?, disabled? }` 2 to 4, `iconOnly`, `disabled`, `ariaLabel` / `ariaLabelledby`, `name`; `FormValueControl<string>` with `value` model, `touch` output): a `radiogroup` of native `<input type="radio">` (like `ui-radio-group`; Angular Aria 22 has no radio group and its toolbar would announce toggle buttons, not one choice). Tab enters the checked option, arrows move and select, disabled options are skipped; the native radios carry the role `radio` and checked state the design audit asks for (`role="radio"` + `aria-checked`), so no ARIA is added by hand. The invisible radio covers its item, so ripple, `uiTooltip` (icon-only: the label) and focus all meet there. The thumb is `::before` driven by `--seg-n` / `--seg-i` host styles; no transition under reduced motion. Dev mode throws for a bad option count or icon-only without icons.
- **`ui-breadcrumbs`** (`items` `{ label, href? }` last = current, `ariaLabel` and `collapsedLabel` required, `maxItems` default 4, output `linkClick` `{ item, event }`): `nav` + `ol`, real `<a href>`; plain click emits `linkClick` (call `event.preventDefault()` to route), modified clicks stay native. Over `maxItems` the root, a "…" `ui-button` with `ui-menu` (`event: null` on choice; menu items are not links, so hidden levels cannot open in a new tab) and the last `maxItems - 2` levels show; on a phone (`matchMedia` `width < 40em`) only "…", parent and current show, the root moves into the menu. A level without `href` renders a `<button>` (keyboard reachable, still emits `linkClick`). Targets are at least 24px, 44px on `(pointer: coarse)` (segmented items, crumb links, the "…" button turns `lg`). Tooltip with the full name only when the text is cut (measured on hover / focus).

## Card, list item, favicon, skeleton (issue #35)

- **One activation target (stretched link).** `ui-card` and `ui-list-item` project the title (`slot="title"`, plus `slot="meta"` in the row) into one native `<a href>` (with `href`, `newTab` adds `target="_blank"` and `rel="noopener noreferrer"`) or `<button type="button">` (without). Its `::after` is stretched over the whole card / row (z-index 1), so the surface has one tab stop and no interactive element is nested in another; `favorite` / `actions` (card) and `trailing` (row) sit above it (z-index 2) and never activate it. `activated` emits the `MouseEvent` (the feature may `preventDefault()` an `href` click to route). `selected` sets `aria-current="true"` on the control; `description` is visually hidden text outside the link, referenced by `aria-describedby` ("opens in a new tab"), so the link name is the title only. Slots are `slot="..."` attributes, never nested links or buttons in `title` / `meta`.
- **`ui-card`** slots: `title`, `meta` (favicon and domain), `favorite`, `actions` (the "..." trigger, top right), `overlay` (bar over the image, `aria-hidden`), `fallback` (site letter on `accent-bg`; with none a picture icon), default = body below the title. Inputs `image` (16:9, falls back on error via `linkedSignal`), `href`, `newTab`, `selected`, `description`, `actionsPinned` (keep actions visible while their menu is open), `reveal` (200 ms fade after a skeleton). Hover (inside `@media (hover: hover)`): `--shadow-card-spread`, `--card-hover-bg`, `--card-hover-border`, image zoom 1.06 (only with `prefers-reduced-motion: no-preference`), overlay and actions in; press: `--shadow-card-press` in 80 ms. Never lifts or scales, no ripple. Actions show on hover, `:has(:focus-visible)` (keyboard focus, so a mouse click does not pin them), `actionsPinned` and always under `@media (hover: none)`. The focus ring is on the host through `:has(.ui-card__link:focus-visible)`; the host clips (`overflow: hidden`) and its own outline and shadow stay whole. New tokens: `--shadow-card-spread`, `--shadow-card-press`, `--card-hover-bg`, `--card-hover-border` (dark brightens the surface and adds a light glow) and `--skeleton-shimmer`.
- **`ui-list-item`** slots `leading` (a `ui-favicon`), `title`, `meta`, `trailing`; inputs `href`, `newTab`, `selected` (`accent-bg`), `compact`, `thumb` (set, even `''`, reserves a 56 x 40 thumb: image, else a picture icon), `description`, `reveal`, `ripple`. `RippleDirective` is a host directive (`ripple` input) and the row provides `UI_RIPPLE_IGNORE` = `.ui-list-item__trailing`, so a press on a trailing control never ripples the row while the events still bubble (outside-click closers keep working). Reduced motion: no ripple, the pressed row shows `surface-pressed`.
- **Images and CSP:** the app CSP is `img-src 'self' data:`, so external preview images and favicons are blocked and the fallbacks (letter / icon, picture icon) show until stage 3 decides on an image proxy or a CSP change (image-sources issue #57, milestone 3).
- **`ui-favicon`** (`src`, `letter`): 16px `radius-sm` square, fixed size (no layout shift); image bound as `src` only with `loading="lazy"`, `decoding="async"`, `referrerpolicy="no-referrer"`, then the letter, then the `link` icon on error or when missing. Always `aria-hidden`.
- **`ui-skeleton`** (`shape` `SKELETON_SHAPE`: `card | row | tree | preview | line`, `count` 0-50): `aria-hidden`; the consumer sets `aria-busy` on its container. `card` is `display: contents` so cards sit in the consumer's grid. Widths vary through `:nth-child` (no inline style). The shimmer is `loop(shimmer)`, off under reduced motion.
- Specs check the compiled component CSS (`testing/scss.ts`: `compileScss`, `mediaBlocks`, `withoutMedia`) for hover-only-under-`(hover: hover)`, the touch rule and the reduced-motion rules, since jsdom does not evaluate media queries. Story layout lives in `.storybook/card-stories.scss` (`cs-` classes).

## Target size, opacity and roles (issue #62, WCAG 2.2)

- **Hit areas.** Every pointer target is at least 24 x 24 CSS px (2.5.8) and 44 x 44 on `pointer: coarse`. A control that is visually smaller keeps its look and gets `hit-area` (chip remove `-6px -4px`, coarse `-14px -10px`, inline-end clamped to `-3px` because the tag-input gap is 6px, coarse inline-start clamped to `-6px`: the 44px target overlaps the chip body by at most ~6px, so a tap near the label edge can hit remove (the trade-off for a 44px target in a 24px chip); input clear button, coarse only). Icon buttons use `touch-target` under `@include coarse`. Tree rows are 44px under `phone` or `coarse`; the tree chevron stays small (2.5.8 equivalent-control exception: the row toggles too).
- **`ui-button hitArea`** (`BUTTON_HIT_AREA`: `grow | overlay`, default `grow`): `grow` makes the coarse icon button 44 x 44 in layout; `overlay` keeps the visual size and adds an invisible `::after` (inset `-6px`, coarse `-10px`), ripple off, `pointer-events: none` when disabled. Use `overlay` where growth would break the layout (the card favorite star).
- **Opacity rule.** `opacity` only for disabled controls and for enter / leave animations. Never to express busy, stale or secondary text: secondary text is `--text-muted` (`#67676c` light, contrast checked on all five backgrounds in both themes), a stale block gets `aria-busy` on its container. Non-text glyphs (chip remove icon) may stay dimmed. Do not mix `text-muted` with `color-mix` to fake a lighter tone; a lighter on-colour tone is `color-mix` of the two tokens (tooltip `__kbd`).
- **Native radios** carry no `role="radio"` or `aria-checked`; the native input already exposes both.
- **`ui-steps`** is `role="img"` named by `label` ("Step N of M"), with no live region: the feature moves focus to the new step heading instead.
- **`ui-spinner`** with `label` is `role="status"` with visually hidden text filled after render (so it is announced); without `label` it is `aria-hidden`. `ui-input` forwards its optional `loadingLabel` to the spinner it shows while loading.
- **`ui-card headingLevel`** (`HeadingLevel` 1-6, shared in `lib/heading`, default 2; `ui-empty-state` uses the same type): the title link is wrapped in `<hN class="ui-card__heading">`, so a grid of cards is a list of headings at the level the page needs.

## Checkbox, long press and chip menu (issues #74, #76)

- **`ui-checkbox`** extends `UiFieldControl` and implements `FormCheckboxControl` (`checked` model, no `value`): `label` (required), `hint`, `error`, `required`, `disabled`, `name`, `indeterminate` (model, visual dash, cleared by the next toggle), `touch` on blur, `focus()`. Bind `<ui-checkbox label="…" [formField]="form.favorite" />` or `[(checked)]`. A native `<input type="checkbox">` (visually hidden) with the box drawn next to it; the label is inside the hit area (24px, 44px on `pointer: coarse`); hint and error are linked through `aria-describedby`, the error is a persistent polite live region. There is no design spec for it: it follows the radio group tokens (accent fill, `border-control`, `focus-ring`).
- **`uiLongPress`** (`(uiLongPress)` output of `UiLongPressEvent` `{ origin, x, y }`, `uiLongPressDisabled`): touch and pen held for `LONG_PRESS_DURATION_MS` (500); cancelled by a move over `LONG_PRESS_MOVE_TOLERANCE_PX` (10), pointer up / cancel or any scroll. Mouse and keyboard are ignored (keep Shift+F10 and the menu button). Only when it fired, the following click (for `LONG_PRESS_CLICK_GUARD_MS`) and the native `contextmenu` are swallowed. The host gets `-webkit-touch-callout: none` through CSSOM. iOS Safari fires no `contextmenu` on a long press, so features open the menu from `(uiLongPress)`: `menu.openAt({ x, y })` or `menu.openFrom(origin)`. Android Chrome may also fire its own `contextmenu` at about the same moment; a feature that handles both should open the menu idempotently.
- **`ui-chip` menu button**: `menuLabel` (accessible name; the button renders only when it is non-empty) and `menuRequested` (emits the button element for `ui-menu.openFrom`). A trailing "…" `<button aria-haspopup="menu">` between the body and the remove button, so the order is body, menu, remove. On hover-capable pointers it is clipped (`clip-path`, no `opacity` or `visibility`) until the chip is hovered or has focus inside or the button has `:focus-visible` (it keeps its width, so nothing shifts, and stays a tab stop; while clipped it has `pointer-events: none`, so its hit area never catches a click); on touch it is always visible. Its click does not reach the chip body, so `clicked` does not fire, and Delete / Backspace on it never remove the chip. Hit areas: the menu stops at its inline-end edge and the remove button, when a menu is present, at its inline-start edge, so they never overlap (on touch the menu box is wider to keep 44px). Specs check the compiled CSS for all of this. `pointerType` values are `POINTER_TYPE` (`lib/long-press/models`); a `pointercancel` ends a press like a release (Android sends `contextmenu`, then `pointercancel`), so the swallow guard always expires.

## Highlight and command list (issue #77)

- **`ui-highlight`** (`text`, `query`: a string split on whitespace into terms, or a list of terms): case-insensitive, literal (regex characters are escaped), overlapping and touching matches merge into one `<mark>`; runs are rendered with `@for` as text nodes, never `innerHTML`. At most 20 terms (`HIGHLIGHT_MAX_TERMS`). Mark colours are the tokens `--highlight-bg` / `--highlight-text` (light `#d3e4cf` / `#1f3a1c`, dark `#3a5a34` / `#eaf3e7`; contrast 9.38:1 light and 6.86:1 dark, WCAG AA; `styles.spec.ts` computes it from the compiled tokens), distinct from the `accent-bg` of the selected row. **Deviation from `Search.dc.html`:** the design marks with `accent-bg` / `accent-text`, which vanishes on the selected row (also `accent-bg`), so the mark has its own tokens. The tag-chip variant of the design (bold, transparent mark inside a chip) is deferred: `ui-highlight` has only the one mark style. Pure logic: `highlightParts`, `queryTerms`.
- **`ui-command-list`** (`query` model, required `inputLabel` and `listLabel` (the listbox name, different from the input's), `placeholder`, `busy`; output `selected` of `CommandSelection` `{ value, background }`; `focus()`), with `ui-command-group` (`heading`) and `ui-command-item` (`value`, `disabled`; slots default = title, `leading`, `meta`, `trailing`). Slots of the list: `input-end` (for example an `Esc` `kbd`), `status` (always rendered inside the one persistent `role="status"` region, for "3 results"), `empty` (inside that region only while there are no items; the listbox is `hidden` then, an empty listbox fails axe), `footer` (keyboard hints). The status region is visually hidden (`visually-hidden`) and becomes visible with padding only in the empty state (`--empty`), so it is never `display: none` and its changes are announced. The list does not filter: the feature owns the query, the request and the items; `busy` is `aria-busy` on the listbox. `ViewEncapsulation.None`: the slotted and item-rendered rows are styled from `.ui-command-list`, and `kbd` there has the keyboard-hint style (also in `trailing` and `footer`).
- **Aria wiring.** The input is an `ngCombobox` with `alwaysExpanded` (`aria-expanded` stays true, focus never leaves it, `aria-activedescendant` / `aria-controls` come from Aria); the popup template holds `ngComboboxWidget` + `ngListbox` (`focusMode="activedescendant"`, `selectionMode="explicit"`, `wrap`, `softDisabled` false so arrows skip disabled rows). Aria relays Up / Down (wrapping) and Home / End; Home / End therefore also move the caret natively. **The options are rendered by the list, not by the items:** `ngOption` injects the listbox through DI, and projected content sees only the declaring (consumer) injector tree, so a `ui-command-item` could never reach a listbox inside the list's own view. Items only register (`contentChildren`, grouped by neighbouring items of one `ui-command-group`) and hand over their row as a template (`body`), which the list renders in an `ngOption` element under `ngListbox`, groups as `role="group"` + `aria-labelledby` the heading. An empty group is not drawn. The item and group host elements are `hidden`. Ids come from CDK `_IdGenerator`.
- **Active row.** After the items or the query change, an effect makes the first enabled row active when the active one is gone or disabled, and always on a new query (`gotoIndex` in a microtask, Aria sorts new options then). `aria-activedescendant` goes through `liveActive`, which drops an id whose row no longer exists. The active row is kept in view by scrolling only the list element (`scrollIntoList`), never the page or the dialog.
- **Choosing.** Aria's own selection is not used (its `valueChange` is reset to `[]` so the same row can be chosen again). `Enter` in the input emits for the active option, with `background: true` when Ctrl or Cmd is held (Aria does not relay modified Enter); a click does the same with `ctrlKey` / `metaKey`; IME composition (`isComposing` or `keyCode` 229) and disabled rows are ignored. A press in the list is `preventDefault`ed so focus stays in the input. The option `click` has a described eslint-disable (the keyboard path is the input).
- **Dialog and phone.** Put the list in a `ui-dialog` body; open the dialog with `autoFocus: 'input'` so focus lands in the search field (the header close button is the first tabbable). The list scrolls inside (`ui-command-list__list`, cap its height in the host with `max-height`; the sheet already limits the dialog to the viewport). Options are 44px on `pointer: coarse` (`touch-target`). Stories: `Components/CommandList` (results, empty, busy, without groups, in a dialog, in a phone sheet, both themes) and `Components/Highlight`; layout in `.storybook/command-list-stories.scss` (`cls-`).

## Themes

`global.scss` defines the tokens: scale tokens on `:root`, light on `:root, [data-theme='light']`, dark on `[data-theme='dark']`, and dark again under `@media (prefers-color-scheme: dark)` for `:root:not([data-theme])`. An explicit `data-theme` always wins; without one the OS decides. Every component must work in both; check both in Storybook. The theme names and the attribute are `THEME` (`light`, `dark`) and `THEME_ATTRIBUTE` (`data-theme`) from `lib/theme`, used by Storybook, the a11y runner and the app; Sass cannot import them, so `styles/styles.spec.ts` checks the compiled CSS has a `[data-theme=…]` selector for every `THEME` value. Stories show both themes with `Object.values(THEME)`.

## Icons

- `ui-icon name="…"` draws a symbol from `src/assets/icons/sprite.svg` via `<use href="…#sm-<name>">`. Icons are filled outlines: colour comes from `currentColor`; never ship `stroke`. Sizes 16, 20 or 24 only.
- The sprite is an external file, not inlined, so the CSP needs no `unsafe-inline`. Its URL is the `ICON_SPRITE_URL` token (default `assets/ui/icons/sprite.svg`); the app maps `libs/ui/src/assets` to `assets/ui`.
- Add an icon: (1) export a filled-outline SVG, (2) add a `<symbol id="sm-<name>" viewBox="0 0 24 24">` to `sprite.svg` with no `fill`/`stroke`, (3) add `<name>` to `ICON_NAMES` in `lib/icon/models/icon-names.const.ts`. A unit test fails if the two drift apart. Update `docs/design/assets/icons/` too: `libs/ui/src/assets/icons/sprite.svg` must equal `docs/design/assets/icons/sprite.svg` except for the removed root `style="display:none"`, and a unit test fails on drift.
- Brand-mark exception: `google` and `github` are the only symbols allowed to differ from `docs/design/assets/icons/sprite.svg` and to carry `fill`, and only fixed brand colours, confined to the sprite (GitHub stays `currentColor`, Google has four fixed fills that ignore the host colour). They are listed as `PROVIDER_SYMBOLS` in `lib/icon/icon-names.spec.ts`, which strips them before the design comparison. The large button draws them at 20px (the design draws 18px; sizes stay 16 / 20 / 24).

## Fonts

Onest (variable) is self-hosted through `@fontsource-variable/onest` (SIL OFL 1.1, credit Onest by Sergey Shabanov / Onest Project Authors) and loaded by the app styles and `.storybook/preview.ts`; no Google Fonts requests. The mono token falls back to `ui-monospace` until JetBrains Mono is added.

## Storybook

- `npx nx storybook ui` serves, `npx nx build-storybook ui` builds (Vite, `@storybook/angular-vite`). The toolbar switches light and dark (`data-theme` on `html`).
- `Foundations/*` docs pages (`src/foundations/*.stories.ts`): colours and shadows in both themes side by side, type styles, spacing, radii, the Motion tables with live demos (`animate.enter` / `animate.leave`), breakpoints and focus. Page styles live in `.storybook/foundations.scss`; token lists in `src/foundations/models/`.
- Published as the Vercel project `shelfmark-ui` (`libs/ui/vercel.json`, ADR 0023, `docs/SETUP.md` 5.7). `nx test-storybook ui` builds it, serves `storybook-static` with the headers from `vercel.json` and runs axe-core (including colour contrast) on every story and every docs page (the auto-generated component docs and the `Foundations/*` pages, all `type: "docs"` entries of `index.json`) in both themes in Chromium; a CSP violation fails the run. A docs page is checked once all its inline stories have rendered. The only exclusion is `.rejt-tree` (Storybook's JSON control, `<li>` rows without a list parent), listed with its reason in `DOCS_AXE_EXCLUDES` in `a11y/storybook.a11y.mts`; never exclude our components. On docs pages only, `landmark-unique` is off (`DOCS_AXE_DISABLED_RULES`): autodocs renders the primary story twice, so a component with a landmark duplicates it; every story page still checks it. Storybook paints its docs chrome (props table, boolean switch) with a fixed light theme, so `.storybook/foundations.scss` re-skins those parts with tokens; when a new docs page fails on `.docblock-argstable` or a control, fix it there.
- Every component has a story file with one story per variant and state plus an "All variants" story that shows both themes. The a11y addon runs axe in a real browser (including colour contrast) and fails the story on violations.

## Tests

- Vitest through `@angular/build:unit-test`; coverage thresholds 80% (statements, branches, functions, lines).
- Every component spec checks variants/host classes, inputs and outputs, keyboard where relevant, disabled behaviour, and runs axe with `axeViolations()` from `src/testing/axe.ts` (colour contrast is off in jsdom; Storybook covers it).

## Commands

```bash
npx nx storybook ui
npx nx build-storybook ui
npx nx test-storybook ui           # axe on every story and docs page, light and dark, under the production CSP (libs/ui/a11y); it never reuses a running server, so parallel runs need different `STORYBOOK_PORT` values (default 6007)
npx nx test ui --coverage
npx nx run-many -t lint typecheck test build -p ui
npm run lint:styles
```
