# libs/ui

Shelfmark's own component library: tokens, themes, `ui-*` components and Storybook. Consumed by `apps/web` from source through the `@shelfmark/ui` path alias; it also builds as a library with ng-packagr (`nx build ui`). Design source: `docs/design/` (`BRAND.md`, `components/<Name>/README.md`, `components/Motion/README.md`). Decision record: `docs/adr/0017-libs-ui-foundation.md`.

## Presentational only

- No HTTP, no stores, no routing, no Transloco. Every visible string and every `aria-label` comes in through an input (or projected content); the feature translates it.
- Components know nothing about links, folders or users. Data in via inputs, events out via `output()`.
- Only `libs/ui` components are used by features; a missing component is added here first.

## Layout

```
libs/ui/
  .storybook/            main.ts, preview.ts, foundations.scss and illustration-stories.scss (styles of the docs pages and stories only)
  src/
    index.ts             public API, re-exports only
    testing/index.ts     test entry `@shelfmark/ui/testing`: the component harnesses only (specs; never in index.ts)
    icons/               one SVG per icon (source); assets/icons/sprite.svg is generated from it (served as /assets/ui/icons/sprite.svg)
    styles/              _functions, _media, _breakpoints, _focus, _utilities, _motion, _typography, tokens/*, _ui (Sass API), global.scss
    foundations/         Storybook "Foundations" docs stories (colours, type, spacing, motion, ...); not exported
    testing/axe.ts       axe-core helper for specs (internal, with scss.ts; not exported)
    lib/                 by kind (ADR 0042, #318); each folder: files, spec, stories, index.ts, models/
      components/<name>/ one component per folder; sub-components in sub-folders (components/menu/menu-item/)
      directives/<name>/ ripple, long-press, pointer-shadow, tooltip (panel in tooltip/tooltip-panel/), menu-trigger, focus-target
      services/<name>/   dialog, drawer, toast (split from their components), overlay, motion
      utils/<name>/      pure functions shared beyond one component: media, loader-timing, colour-contrast, custom-accent, reorder-drop-line
      models/<domain>/   constants and types with no component: keyboard, heading, theme
```

- A helper used by one component stays in its folder (`select-rows.ts`, `sheet-drag.ts`); it moves to `utils/` when a second user appears. A component and the service that opens it live apart (`components/dialog/`, `services/dialog/`); a model goes with the side that uses it, a union type next to its `as const` object.
- `src/index.ts` re-exports one `index.ts` per top folder, grouped by kind; `@shelfmark/ui` is the only public entry for app code. Specs also have `@shelfmark/ui/testing` (Harnesses, below).

## Component rules

- One component (or directive) per folder (`components/<name>/`, `directives/<name>/`), selector `ui-<name>`, standalone, `OnPush`, `host: {}` (no `@HostBinding` / `@HostListener`), signal `input()` / `output()` / `model()`, `inject()`.
- Variants, sizes and kinds are `as const` objects with a derived union type (ADR 0024, no TS `enum`): `models/<name>.const.ts` (`BUTTON_VARIANT = { Primary: 'primary', … } as const`) and `models/<name>.type.ts` (`ButtonVariant`, the union). The input keeps the union type, so `variant="primary"` still compiles in templates; in TypeScript, host expressions and bound template expressions use the constant (`input<ButtonVariant>(BUTTON_VARIANT.Secondary)`, `protected readonly CHIP_VARIANT = CHIP_VARIANT;`, stories `argTypes.options: Object.values(BUTTON_VARIANT)`). `KeyboardEvent.key` values come from the shared `KEYBOARD_KEY` (`lib/models/keyboard`). Numeric unions, catalogue tuples (`ICON_NAMES`), `Record` keys and ARIA / DOM / CDK identifiers stay literal. Booleans use `booleanAttribute`.
- Behaviour (keyboard, focus, ARIA, overlays) comes from native elements first, then Angular Aria / CDK. No Angular Material, no Tailwind, no third-party icon sets, no `@angular/animations`.
- Templates in `.html`, styles in `.scss` files (stylelint does not see inline `styles:`).
- Follow `.claude/skills/create-ui-component` and `angular-v22-rules`.

## Styles

- Colours, spacing, radii, durations and easings only through CSS custom properties from the tokens; no hard-coded colours, no `!important`, no `::ng-deep`.
- Component SCSS starts with `@use '../../../styles/ui' as *;` (relative path, works in every builder; one `../` more in a sub-component folder). It gives `rem($px)`, `type($style)`, `hover`, `reduced-motion` and the mixins below.
- Sizes in `rem` via `rem(24px)`. Plain `px` is allowed only for border widths, `outline`, `outline-offset` and `box-shadow` (and `--shadow-*` tokens). Breakpoints in `em`. stylelint enforces this (`npm run lint:styles`).
- The 2px top progress bar is the one other `px` exception and needs a described disable: `/* stylelint-disable-next-line unit-disallowed-list -- 2px progress bar per spec */` (descriptionless disables are reported).
- Class names are BEM (`ui-button--primary`, `ui-icon__svg`).
- `:hover` only through the `hover` mixin (`@media (hover: hover)`); `:focus-visible` uses `@include focus-ring`; wrap movement and scale in `@include reduced-motion`.
- Type styles come from the `type($style)` mixin (display, title, heading, body, label, caption, mono); there are no global type classes.
- **Scale properties (#352):** unitless custom properties (default 1) that a feature sets on an ancestor to show a component bigger without new variants (the landing uses them instead of `zoom`): `--ui-button-scale` multiplies the box, padding, gap, text and icons of every `ui-button` size (it passes itself on as `--ui-icon-scale`); `--ui-icon-scale` multiplies the `ui-icon` size (`--ui-icon-size` still picks the base); `--ui-chip-scale` the `ui-chip` height, padding and text; `--ui-favicon-scale` the `ui-favicon` box, letter and image. `button/button-scale.spec.ts` checks the compiled rules.

**Keyframes** are defined once, in `global.scss` (`@include keyframes`), prefixed `ui-`: `pop-in`, `pop-out`, `fade-out`, `reveal`, `sheet-in`, `sheet-out`, `toast-in`, `toast-out`, `toast-count`, `spin`, `spinner-in`, `spinner-grow`, `spinner-out`, `spinner-shrink`, `shimmer`, `progress`, `ripple-grow`, `ripple-fade`, `land`, `land-ring`. Components never declare `@keyframes`; they use a preset or, for a new moment, add the keyframes to `_motion.scss`.

**Presets** (duration, easing): `enter(pop)` 200 ms `ease-out` (menus, listboxes, dialogs), `enter(fade)` 200 ms (skeleton to content), `enter(toast)` 320 ms `ease-spring`, `enter(sheet)` 320 ms `ease-drawer`, `enter(spinner)` / `enter(spinner-grow)` 200 ms (plus the spin). `leave(pop)` / `leave(fade)` 120 ms `ease-out`, `leave(toast)` 120 ms `ease-in`, `leave(sheet)` 200 ms `ease-in`, `leave(spinner)` / `leave(spinner-shrink)` 120 ms. Presets are finite (no `infinite`), so `animate.leave` can finish; a spinner's rotation is `@include loop(spin)` on the inner element, never on the element that has `enter` / `leave`. Under `prefers-reduced-motion: reduce` every `enter` becomes `ui-reveal` (200 ms fade) and every `leave` a `ui-fade-out`; movement and scale are gone (so `enter(spinner-grow)` loses its margin growth and the label does not slide).

**Convention for Angular animations.** Put the preset in a modifier class and bind it with `animate.enter` / `animate.leave` on the element that appears and disappears:

```scss
.ui-menu--enter {
  @include enter(pop);
  @include origin;
}

.ui-menu--leave {
  @include leave(pop);
}
```

```html
<div class="ui-menu" animate.enter="ui-menu--enter" animate.leave="ui-menu--leave">…</div>
```

Angular keeps the element until the leave animation ends and a second toggle mid-animation reverses it. Menus and listboxes scale from their trigger: the overlay sets `--ui-origin` (for example `100% 0`) on the panel from its anchor; dialogs keep `center`. The ripple is the `uiRipple` directive (below). The FLIP helper, the "card lands" moment, View Transitions and the logo animation are not part of this foundation.

## Trigger API and ripple (ADR 0021)

`ui-button` stays a wrapper around a native `<button>` (or an `<a>` with `href`). Attributes and directives on `<ui-button>` land on the non-focusable host, so:

- **ARIA inputs** on `ui-button` go to the inner element and render nothing when unset: `ariaLabel`, `ariaExpanded`, `ariaControls`, `ariaHaspopup`, `ariaDescribedby`, `ariaPressed`.
- **Focus target**: `focus(options?)` and the `element` signal (inner native element). `UI_FOCUS_TARGET` (`UiFocusTarget`) is provided by `ui-button`; a trigger directive (tooltip, menu trigger, overlay origin) does `inject(UI_FOCUS_TARGET, { optional: true, self: true })` and falls back to its host `ElementRef`. Any new wrapper component with an inner native control provides it too.
- **`wrap`** (#274): a long (translated) label wraps and the button grows in height instead of being cut; the host never gets wider than its container. Use it where a label can outgrow its place (the sidebar How-it-works card).
- **Links**: `href` renders an inner `<a>` with the same classes; `(linkClick)` fires for plain left clicks (no modifier key), the feature calls `preventDefault()` and routes (`routerLink` is not available here). A disabled link has no `href`, `role="link"`, `aria-disabled="true"` and swallows clicks.
- **`uiRipple`** works on any host (rows, menu items, chips): pointer origin, Enter / Space from the centre, cancelled by a move over 10 px, no ripple when `disabled` / `aria-disabled`, `[uiRipple]="false"` opts out, `uiRippleIgnore=".selector"` (or, for a host directive, the `UI_RIPPLE_IGNORE` token) skips pointer and Enter / Space events whose target is inside a matching region without stopping them from bubbling, no ripple under reduced motion. Colour `currentColor` at 6% / 10% (dark); a host raises it with `--ui-ripple-opacity` (filled buttons: 0.2). Its styles are the global `ripple` mixin in `global.scss` (the span is created at runtime, outside view encapsulation). The host class `ui-ripple-host` sets `position: relative`, `overflow: hidden`, `isolation: isolate` through `:where()` (zero specificity), so a host that needs `absolute` or `sticky` just sets its own `position`; the ripple only needs a positioned host. `ui-button` applies it on the inner element; `[ripple]="false"` opts out.

## Illustrations, logo and empty states

- `ui-illustration` draws the 14 scenes as inline SVG (the 8 of `docs/design/assets/illustrations/` plus the #315 empty-state scenes `empty-trash`, `empty-recent`, `empty-favorites`, `empty-unsorted`, `empty-tags`, `empty-filter`, drawn in the same style from the same parts and play-once moves) in its template (no `innerHTML`, no inline `style`, fills are token-bound classes). `motion` is `loop` (3-5 s cycle, landing / welcome / sign-in), `once` (plays, then holds the final frame; empty states and errors) or `none`; the caller picks it and each scene has a default (`ILLUSTRATION_DEFAULT_MOTION`: welcome scenes loop, the rest play once). Resting styles are the final frame, so `none` and `prefers-reduced-motion` just remove the animation.
- Scene keyframes (`ui-ill-*`) and the two durations live in `styles/_illustration.scss` (`@include illustration-keyframes` in `global.scss`), apart from the shared presets; offsets are percentages of the element box, set through `--ill-*` custom properties on the scene classes.
- Loops run continuously. The app may later pause off-screen ones (for example with an `IntersectionObserver` toggling `motion` to `none`); the component does not do that itself.
- `ui-logo`: `variant` `lockup` / `mark`, `tone` `color` (theme tokens) / `mono` (`currentColor`), mark size through `--ui-logo-size`.
- `ui-empty-state`: `illustration` or `icon`, `heading` (not `title`: that would add a native tooltip), `text`, `headingLevel`, `layout` (`EMPTY_STATE_LAYOUT`: `inline` default, `page`); the action is projected content. `page` (#315) is the page-level state of every app page (library feeds, Trash, Recently opened, the phone Tags tab, the public collection): a surface card (`shadow-card`, `radius-lg`, at least 27.5rem / 23.75rem on a phone) that grows into the free height of a flex-column parent (`flex: 1 0 auto`), the content centred both ways, the scene 300px (240px on a phone) on a soft disc (`--illustration-disc`: `surface-hover` in light, one step stronger than the page, `bg` in dark), where the scene takes stronger edges through `--ui-illustration-edge` (`border-control` on white parts and the offline break marks) and `--ui-illustration-key-edge` (an `accent` outline on the pale sage bodies marked `ui-illustration__tint--key`: folder, tray, filter chip), so key shapes keep 3:1 on the disc (WCAG 1.4.11, checked in `styles.spec.ts`); without those properties (landing, onboarding, inline) the scenes keep the soft look, the heading 28/34 (24/30 on a phone), the text 16/24 up to 460px. The page host must be a flex column that fills the shell column for the card to centre in the content area.

## Overlays and tooltip (issue #26)

- **CDK overlay CSS** is included once in `global.scss` (`@use '@angular/cdk' as cdk; @include cdk.overlay` — the CDK exports Sass only from its root entry), so overlays are styled before the CDK loads anything. This does not remove runtime styles: the CDK `OverlayContainer` and component `styleUrl`s still add `<style>` elements, so under the strict CSP `apps/web` needs the nonce from ADR 0022 before an overlay renders. Storybook adds `node_modules` to the Sass `loadPaths` for that bare `@use`; the Angular builder resolves it itself. `@angular/cdk` is a peer dependency of `libs/ui`.
- **`UiOverlay.connect({ origin, positions, layer, panelClass? }, { injector?, onPositionChange? })`** returns a `ConnectedOverlay` (flexible position with flip, push on screen, reposition on scroll, no backdrop). `--ui-origin` is set on the pane from the resolved position (`overlayTransformOrigin`, `setOverlayOrigin`, `connectedSide`; `sidePositions(side)` gives preferred plus opposite). The owner renders content that appears and disappears with `@if` + `animate.enter` / `animate.leave` (a `pop` preset with `@include origin`), then calls `release()`: it detaches after the leave animations end (`getAnimations`), `cancelRelease()` / a new `attach()` makes a second open mid-animation work. Pass the owner's `injector` so the overlay is disposed with it.
- **Layers** (z-index, class `ui-overlay-layer--<layer>` on the CDK host element `overlayRef.hostElement`, the stacking context): dialog 1000 (scrim and panel), menu 1010, toast 1020, tooltip 1030. Floating panel surface: `@include glass` for menus, the select and tag-input listboxes (18px corners, 6px padding, items 12px corners and 9px / 12px padding); `@include popover` for tooltips only (the toast is glass too). The command list sits inside a dialog: the plain dialog surface, or the glass of the command dialog (below).
- **`uiTooltip`** (`uiTooltip`, `position` default `bottom` (flips to top), `delay` 400, `uiTooltipShortcut`, `uiTooltipPointerTarget`: an element whose hover drives it instead of the host, for a control stretched over a card — `ui-card` passes its title text, #314): hover and keyboard focus, closes on blur, pointer leave, activation and Esc (capture on `document`; it stops propagation only while focus is on the trigger, so a surrounding dialog or menu keeps its own Esc, and a tooltip left open by the pointer never swallows the Esc of a field focused elsewhere; focus does not move); hoverable (the gap is padding of the panel); never on `(hover: none)` or touch pointers. The description is the `aria-description` attribute on the `UI_FOCUS_TARGET` element (inner button of `ui-button`) or the host (axe 4.14 knows it; Chromium, Firefox and Safari expose it), skipped when the text equals the target's `aria-label` (no double announcement on icon-only buttons; re-checked when the text changes and each time the tooltip opens). The directive creates no DOM node of its own: the overlay exists only while shown and is disposed on hide and on destroy, and nothing is appended to `<body>` (a unit test renders 50 hosts, destroys them and checks). The visible panel is `aria-hidden`. An overlay lives in `<body>`, so it takes the theme of `<html>`, not of a nested `data-theme` wrapper.

## Menu (issue #27)

- `ui-menu` (Angular Aria `ngMenu` as a host directive), `ui-menu-item` (`icon`, `shortcut`, `danger`, `disabled`, `selected`, `type` `item | checkbox | radio`, output `activated`; the host is always `role="none"`, the inner element carries the menuitem role and `aria-checked`), `ui-menu-separator`, and the `uiMenuTrigger` directive. Open with `uiMenuTrigger` on a `ui-button`, or in code: `menu.openFrom(element, { focus })`, `menu.openAt({ x, y })` (context menu; focus returns to the previously focused element), `close()`; `isOpen`, `anchor`, `opened` / `closed`. `align` `start | end`, `ariaLabel`; `inline` renders in place and always open for Storybook and docs only (features must not use it).
- **Trigger decision:** Aria `MenuTrigger` writes its attributes and tabindex on its own host, which for `<ui-button>` is not the focusable element, so `uiMenuTrigger` implements the trigger half itself (click, ArrowDown / ArrowUp, Enter / Space on non-buttons) on the `UI_FOCUS_TARGET` element and writes `aria-haspopup`, `aria-expanded`, `aria-controls` there directly (a directive cannot set another component's inputs; do not also bind those inputs on the button). The popup, arrows, Home / End, Enter / Space and typeahead stay Aria's.
- `ui-menu-label` (projected text) is a small heading (`caption`, `text-muted`, 600) over a group of items, such as the phone's "View" menu (Sort by, View, Export); `role="presentation"`, not an item, so arrow keys skip it; put a `ui-menu-separator` between groups.
- The host element of `ui-menu` is moved into the overlay pane with a `DomPortal` (`ConnectedOverlay.attachElement`) so Aria's host listeners keep seeing the items; closed, it is hidden and empty. Initial focus is set by dispatching Home / End to the menu, so Aria's active item matches DOM focus. Esc, Tab, an outside press and a choice close it; Esc and a choice return focus first, then `activated` emits. `ConnectedOverlayConfig.origin` also takes a viewport point.

## Badge (issue #265)

- `ui-badge` (`tone` `BADGE_TONE`: `neutral | accent | warning | danger`, optional `icon`): small status pill; the label is projected and always carries the meaning (words first, colour second), the icon is decorative, no role, not interactive. One badge per card or row ("Already saved" in the paste-many list is `warning`). The component is identical to the one on the trash branch (#262), so both merge cleanly.

## Chip, avatar, notice, steps (issue #25)

- `ui-chip`: `variant` `tag | neutral`, `clickable` (inner `<button>` with `uiRipple`, output `clicked`), `removable` (separate remove button named by `removeLabel`, output `removed`; Delete / Backspace anywhere in a removable chip also emits it), `disabled`, `icon`. The label is projected; there is no ripple on a non-clickable chip or on the remove button. `focus()` focuses the clickable body, else the remove button. After `removed` the removed chip is gone and focus is lost: the feature must move focus (to a sibling chip via `focus()`, or to the input in a TagInput).
- `ui-avatar`: `src`, `name`, `size` `sm | md | lg`, `label`. Initials (`initialsOf`, grapheme-safe, first and last word; it upper-cases first, so `ß` gives `S`) when `src` is absent or fails (the app CSP allows only `*.googleusercontent.com` and `avatars.githubusercontent.com`, #352; `linkedSignal` retries on a new `src`); the image is `referrerpolicy="no-referrer"`, `decoding="async"` (not lazy: a lazy image in a closed menu failed to load), in the fixed box of its size, a user icon without a name. Decorative (`aria-hidden`) unless `label` gives it `role="img"`.
- `ui-notice`: `kind` `warning | danger | info`, `icon` override, `banner` (boolean: full-width centred strip, no radius, wraps on a phone, default icon hidden unless `icon` is set), trailing action projected with `uiNoticeAction` (a small `ui-button` or link; own slot after the text). `warning` and `info` (accent tint) are `role="status"`, `danger` `role="alert"`. The demo banner is `<ui-notice kind="info" banner>`. `ViewEncapsulation.None` with `.ui-notice` selectors so projected links are styled. A live region announces reliably only when content appears in it, so render a notice on demand (`@if`) when an announcement is wanted; one present at page load is not announced.
- `ui-steps`: `count`, `current` (1-based), `label` ("Step N of M", visually hidden, polite live region); dots are `aria-hidden`; earlier dots look like upcoming ones, as in the spec.
- Story layout for these lives in `.storybook/display-stories.scss` (`ds-` classes).

## Dialog (issue #28)

- `DialogService.open<C, R, D>(Component, { size, data, dismissible, scrimClose, role, describedBy, autoFocus })` returns a `UiDialogRef<R, C>` (`close(result?)`, `afterClosed()`, `result` promise, `leaving`, `componentInstance`, `hostElement`). `confirm({ title, message, confirmLabel, cancelLabel, closeLabel?, destructive? })` resolves a boolean: true for confirm; false for Cancel, the close button, Esc and the scrim. All strings come in. `size` is `DIALOG_SIZE`: `sm` 440px (default), `md` 560px, `lg` 860px (media such as the How it works video, #315).
- The content component renders `<ui-dialog title="…" closeLabel="…" [size]>` with the body as content and footer buttons as `slot="footer"` (secondary first, main action last), reads `injectDialogData<T>()` and closes through the injected `UiDialogRef`. A `<form>` may wrap `ui-dialog`. The close button exists only with `closeLabel`; an overflowing body becomes a focusable region. The footer sits `space-6` (24px) under the body in every dialog: the panel `gap` (`space-4`) plus a `space-2` margin on `.ui-dialog__foot` (#350); an empty footer is `display: none` and adds nothing.
- A width the three sizes lack: set `--ui-dialog-custom-width` on the `ui-dialog` element from the feature's own stylesheet (Keyboard shortcuts 55rem, How it works 73.5rem for a 70rem video, #335); it wins over `--ui-dialog-width`, and the viewport limit and the phone sheet stay.

## Loading (issue #23)

- Pick the indicator by what loads (Loading spec): `ui-button [loading]` for an action the user started, `ui-progress-bar` for navigation and background requests, `ui-meter` for known progress, `ui-load-more` under a list, `ui-save-status` for autosave, skeletons for first loads.
- **`ui-spinner`** (`size` `sm | md | lg`, optional `label`): ring in `currentColor`, rotation on the inner `__ring` (`loop(spin)`), `enter(spinner)` on the host when it is created. Without `label` it is `aria-hidden`; with it, an indeterminate `progressbar`. It leaves only when its owner removes it with `animate.leave` and a class using `@include leave(spinner)` (`spinner-shrink` inside a button); the components below do that already.
- **`ui-button [loading]`**: spinner with `enter(spinner-grow)` (label makes room), `aria-busy="true"`, no ripple, `cursor: progress`. Activation (clicks, Enter / Space, form submit) is blocked by `preventDefault()` plus a capture-phase host listener that calls `stopImmediatePropagation()` only while loading: `(click)` on `<ui-button>` does not fire; document capture listeners (the CDK overlay's outside-press) still see the event, bubble listeners above the button do not. A loading `href` button renders like a disabled link (no `href`, `role="link"`, `aria-disabled="true"`, not dimmed), so middle-click and the context menu cannot navigate. The button stays focusable (not `disabled`). The width is locked in px on the inner element: a `ResizeObserver` keeps the rest width (fallback without one: read after each render), the lock is set when `loading` turns true and released after the leaving spinner's animations finish. The feature changes the label to the -ing form itself. The spinner replaces `iconLeft`; icon-only buttons show a solo spinner (`enter(spinner)`).
- **`ui-progress-bar`** (`active`, `variant` `fixed | inline`, optional `label`): presentational, the app binds `active`. `fixed` is the 2px sage bar at the top of the viewport (z-index 900, below overlays), shown only after 300 ms of `active`; `inline` is a 3px track in a box, shown at once. On finish it fills to 100% and fades (`ui-fade-out`, removed on `animationend`). The 2px height is the described stylelint disable. A finished bar is removed on `animationend` / `animationcancel` of the fade or, as a fallback, after 450 ms; `inline` skips the 300 ms helper. Without `label` it is `aria-hidden`.
- **`ui-meter`** (`value` 0-100, clamped; required `label`): `role="progressbar"`, `aria-valuenow`; percent text is the feature's. **`ui-load-more`** (`text`, `loading`): the host is a persistent `role="status"` live region (keep it rendered, bind `loading`; a region inserted already filled is often not announced), the spinner `sm` plus text row exists only while `loading`. **`ui-save-status`** (`state` `saving | saved | error`, `savingText`, `savedText`, `errorText`): icon plus words in a polite status region; the icons share one 16px slot.
- **`loaderVisible(busy, { delay?, minVisible?, injector? })`** (`lib/utils/loader-timing`): turns a `busy` signal into a `visible` signal that goes true after 300 ms and stays true for at least 400 ms once shown (`LOADER_SHOW_DELAY_MS`, `LOADER_MIN_VISIBLE_MS`); a response faster than the delay shows nothing. Call it in an injection context; timers are cleared on destroy. Features bind loaders to its result, never to the raw request state.

## Form fields (issue #24)

- **Signal Forms binding.** The Angular 22 directive is `[formField]` (`FormField` from `@angular/forms/signals`; there is no `[field]`). A field component implements `FormValueControl<T>`: a `value` `model()`, plus optional inputs the directive fills (`disabled`, `required`, `errors`, `touched`, `maxLength`, `name`) and a `touch` output (emit on blur) that marks the field touched. Features write `<ui-input label="Link" [formField]="form.url" />`; messages come from the validators (`required(p.url, { message })`), already translated. Without a form use `[(value)]` and the manual `error` input. Reactive and template-driven forms are not used.
- **`UiFieldControl`** (abstract directive, `lib/components/field`): the shared half of a field: `label`, `hint`, `error` (manual, always wins), `disabled`, `required` (`aria-required`, no native `required`), `errors`, `touched`, `touch`, plus protected `controlId`, `message` (first message of a touched field), `showInvalid`, `describedBy` and an overridable `counterText()`. `ui-select` and `ui-tag-input` extend it, add their `value` model and render the shell.
- **`ui-field-shell`** (`controlId`, `label`, `hint`, `error`, `invalid`, `disabled`, `counter`, `counterLabel`, `mono`, `multiline`): label above, bordered control box with `field-focus` (projected content goes inside), message row. The error is a persistent `aria-live="polite"` element; while an error shows, the hint stays in the DOM, visually hidden, so `aria-describedby` (`fieldDescribedBy(controlId, parts)`: error, hint, counter) still reads both. Ids come from `nextFieldId()`, `fieldHintId()`, `fieldErrorId()`, `fieldCounterId()`.
- **Projected parts are styled by the hosting field**, not the shell (view encapsulation): include `field-native` (bare `input` / `textarea`, no own border or outline) and `field-icon-button` from `lib/components/field/_field-parts.scss` (`@use '../field/field-parts' as *;`).
- **`ui-input`** (`type` `text | url | search`, `placeholder`, `icon`, `clearable` + `clearLabel`, `shortcut`, `loading`, `readonly`): `url` is mono with a URL keyboard; `search` defaults to the search icon and swaps it for `ui-spinner` in the same 16px slot while `loading`. The clear button keeps focus in the field and is rendered only when `clearable` and `clearLabel` is non-empty (`spellcheck`, default on, #274 Spell-check notes; no nameless button). `readonly` keeps the value focusable and selectable at full contrast (no clear button); `select()` focuses it and selects the whole value (the copy-link fallback of the share dialog). The search spinner swap is visual only: the feature owns any live announcement of loading. **`ui-textarea`** (no native `maxlength`: the Signal Forms `maxLength` rule reports overflow, including pasted or loaded text; `rows` 3, grows to `TEXTAREA_MAX_ROWS` 8 through CDK `cdkTextareaAutosize`, `maxLength` with counter `n / max`, `counterLabel`). **`ui-radio-group`** (`options` `{ value, title, description? }`, `orientation`, `ariaLabel` / `ariaLabelledby`, `name`): native radios, arrows move and select, Tab enters the checked option; `touch` fires when focus leaves the group. - **Validators must carry a `message`**: an error without one puts the field in the invalid state (`aria-invalid`, danger border) but shows no text.

## Toast (issues #29, #228)

- **`ToastService.show({ title, detail?, kind, thumb?, folder?, action?, secondary?, duration?, actionHint? })`** returns `{ dismiss(), closed }` (`dismiss()` on the service closes the newest). `kind` is required: `saved | moved | success | danger | warn | info` (`TOAST_KIND`). `title` is what happened, `detail` what it happened to (second line, one line, truncates with an ellipsis); `action` / `secondary` are `{ label, run }`; title, detail and labels are already translated by the feature. `closed` is a `Promise<ToastCloseReason>` that resolves exactly once and never rejects: `action` (the action or secondary button was used, even if it threw), `timeout` (the hover/focus-paused timer ended), `dismissed` (`dismiss()` on the ref or the service, the close button, Esc), `replaced` (a fourth toast pushed it out); values are `TOAST_CLOSE_REASON`. The action dismisses first and then runs, so an action that shows another toast still settles `action`. If the injector is destroyed with a toast pending, it settles `dismissed`.
- **Leads (by kind):** `saved` is the link preview (`thumb`, a same-origin URL; without it the `saved-link` icon) with a sage check badge; `moved` is a `ui-folder-icon` tile (`folder: { colour?, icon? }`, graphite by default, 2rem); `success`, `danger`, `warn`, `info` are a 2rem tinted icon tile (sage `accent-bg`, `danger-bg`, `warning-bg`, neutral), each kind has its own glyph. Close button (`TOAST_DISMISS_LABEL`, a provider of a function returning the translated name; the app provides it from Transloco, default `Dismiss`).
- **Durations** (`TOAST_DURATION_MS`, `toastDefaultDuration(kind, hasAction)`): `saved` 5 s; `success` 3 s (quick confirmation); `info` and `moved` 4 s (status); with an action `success`, `info` and `moved` get 8 s (Undo); `danger` and `warn` stay until handled (`0`, also with an action). An Undo after a delete is `danger` and passes `duration: TOAST_DURATION_MS.Undo` itself. A toast with an action and `duration === Undo` is an **Undo toast**: it shows the countdown line (`ui-toast__timer`, `--ui-toast-duration`, a keyframe from `_motion.scss`, paused with the timer through `ui-toast--paused`, not drawn under reduced motion) and answers Ctrl/Cmd+Z. Hover, focus or touch pauses that toast's own timer and it resumes with the time left. `duration: 0` keeps it until dismissed. An action that throws goes to the `ErrorHandler`; the toast is dismissed.
- **Stack:** up to `TOAST_STACK_MAX` (3), oldest first in `ToastStore.items`; each has its own timer. A fourth pushes the oldest out (`replaced`). All toasts share one grid cell: the newest in front, older ones peek above it (`data-depth` 1 and 2: 0.75 / 0.45 opacity, scale 0.95 / 0.9, only the front one takes pointer events), `--ui-toast-index` is the stacking order. `:host:hover` / `:focus-within` fans them out into a column (newest at the edge, so it does not move under the pointer; an 8px `::before` bridge keeps the hover between toasts). Not implemented: collapsing many saves into one summary toast (needs a caller-side rule to group; open question).
- **Surface and position:** `@include glass` (not popover), 18px corners, `width: max-content` up to 540px (min 300px), 14/20 medium title and 12/16 detail. Rendered through `UiOverlay.global({ layer: 'toast' })`: a full-width pane on the viewport edge with `ui-overlay-pane--passthrough` (`pointer-events: none`), the toasts take pointer events themselves; bottom centre on every screen, 24px up (`space-6`). **Author decision, overriding the old bottom-left.** The region's bottom inset is `max(var(--ui-toast-offset, var(--space-6)), safe-area)`: the app sets `--ui-toast-offset` to bar height plus 12px above a bottom bar (`apps/web/src/styles.scss` does it on phones for the tab bar; the bulk bar comes later; the `mobile` e2e checks toasts stay above the bar). Actions are 44px on coarse pointers; the shortcut key caps (`ui-toast__kbd`, from `tablet-up`, `toastShortcutKeys()`) stay before the action when `actionHint` is set.
- **Motion:** enter `enter(toast)` = `ui-toast-in` (rises 18px, scale 0.96, `duration-slow` 320 ms, `ease-spring`), leave `leave(toast)` = `ui-toast-out` 120 ms `ease-in`; reduced motion fades (200 ms in, fade out). The spec's 420 ms is not a token and Motion forbids anything above 320 ms, so the token `slow` is used (open question for the design owner).
- **Live regions:** `ToastService` creates `ui-toast-region` when it is first injected and never detaches it. It holds TWO persistent regions (both `display: contents`, so the toasts still share one stack): a polite `role="status"` for every kind except `danger`, and an assertive `role="alert"` for `danger` errors (a red `danger` Undo toast after a delete is a confirmation of the user's own action and goes to the polite region); toasts are added and removed inside them with `animate.enter` / `animate.leave`, so a region is never inserted already filled (no pre-filled alert). A toast moves between regions never. Inject the service early in the feature. Focus is never moved by a toast.
- **Keyboard:** the service listens on `document` keydown (removed with the injector): Ctrl/Cmd+Z (matched by `code` `KeyZ`, no Shift/Alt) runs the newest Undo toast; Esc dismisses the newest toast. Both are ignored when the key was already handled (`defaultPrevented`), while composing, and when the event target is in an editable field (`input`, `textarea`, `select`, `contenteditable`, `role=textbox|combobox`) or in a `dialog`, `alertdialog`, `menu` or `listbox`. The toast is outside the page tab order and its timer can end before a keyboard user tabs to it, so `ToastService.focusAction()` moves focus to the action of the newest toast that has one (only on that explicit call; the timer pauses while focused; focus returns where it was when the toast closes by action or dismiss). The app binds `handleShortcut(event)` (Alt+Shift+T, Option+Shift+T on macOS, `TOAST_SHORTCUT`) to it from its shell. Where feasible an action should also have a persistent alternative in the UI (for example Undo in the item's menu).
- `ui-toast` is the exported view (`kind`, `title`, `detail`, `thumb`, `folder`, `actionLabel`, `secondaryLabel`, `dismissLabel`, `countdown`, `actionHint`, `shortcut`, outputs `action`, `secondaryAction`, `dismiss`, `pausedChange`); features use the service, not the component. State and timers are in the internal `ToastStore` (`items`, `stack`).

## Select (issue #30)

- **`ui-select`** extends `UiFieldControl` and implements `FormValueControl<string | null>`: `options` (`SelectOption` tree `{ id, name, lang?, children? }`; `lang` puts the attribute on the option and the trigger text, for a language list in its own names), `searchable`, `emptyLabel` (text of the `null` option; no default and no empty option without it: the "Unsorted" of the design comes from the app through Transloco), `placeholder`, `searchLabel` (name and placeholder of the search box, required with `searchable`), `noResultsLabel`; plus the field inputs. All strings come in. `focus()` focuses the trigger.
- **Aria wiring:** trigger is a native `<button ngCombobox>` (role `combobox`, so `<label for>` names it and a disabled field is natively disabled: `softDisabled` false); the popup is `ngComboboxPopup` + `ngComboboxWidget` + `ngListbox` (`focusMode="activedescendant"`, `selectionMode="explicit"`, `tabindex="-1"`) with `ngOption` rows. DOM focus stays on the trigger, or in the search box; Aria relays arrows, Home / End, Enter, Space and typeahead from the trigger. The search box relays ArrowUp / ArrowDown / Enter itself (Home / End only while the box is empty or with Ctrl / Cmd, so they still edit text). Aria's own focus-out close is kept: the popup wrapper forwards `focusin` / `focusout` to the public `ComboboxWidget.onFocusin` / `onFocusout`, and a press inside the popup is `preventDefault`ed so focus never leaves the trigger or the search box. - **Popup:** the wrapper element (empty `ng-template ngComboboxPopup` inside) is moved into a `UiOverlay` pane (layer `menu`, `menuPositions('start')`) with `attachElement`, as `ui-menu` does; its content is rendered by Aria while expanded, with `animate.enter` / `animate.leave` (`pop`, `--ui-origin`). The pane's `min-width` follows the trigger width (CSSOM) on open, on every reposition and through a `ResizeObserver` on the trigger (disconnected on close and destroy); the wrapper grows to it. Long lists scroll inside the panel (max 20rem), the search box stays above. There is no separate phone sheet (the spec has none): the popup keeps the trigger width and flips above when there is no room.

## Tag input (issue #31)

- **`ui-tag-input`** extends `UiFieldControl` and implements `FormValueControl<string[]>`: `suggestions` (`TagSuggestion` `{ name, countLabel? }`; the count text, "12 links", comes from the feature), `maxTags` (unlimited when unset), `placeholder`, `maxTagsLabel` (replaces the placeholder and is announced at the limit), `createLabel` (`Create tag “{name}”`; without it there is no create row), `removeLabel` (`Remove tag {name}`), `addedLabel` / `removedLabel` / `duplicateLabel` (`Tag {name} added`, `Tag {name} removed`, `Tag {name} is already added`; announced through a persistent visually hidden `role="status"`), `listLabel` (accessible name of the suggestion list, "Tag suggestions"; `label` when empty), plus the field inputs. `focus()` focuses the input. ## Target size, opacity and roles (issue #62, WCAG 2.2)

- **Hit areas.** Every pointer target is at least 24 x 24 CSS px (2.5.8) and 44 x 44 on `pointer: coarse`. A control that is visually smaller keeps its look and gets `hit-area` (chip remove `-6px -4px`, coarse `-14px -10px`, inline-end clamped to `-3px` because the tag-input gap is 6px, coarse inline-start clamped to `-6px`: the 44px target overlaps the chip body by at most ~6px, so a tap near the label edge can hit remove (the trade-off for a 44px target in a 28px chip); input clear button, coarse only). Icon buttons use `touch-target` under `@include coarse`. Tree rows are 44px under `phone` or `coarse`; the tree chevron stays small (2.5.8 equivalent-control exception: the row toggles too).
- **`ui-button hitArea`** (`BUTTON_HIT_AREA`: `grow | overlay`, default `grow`): `grow` makes the coarse icon button 44 x 44 in layout; `overlay` keeps the visual size and adds an invisible `::after` (inset `-6px`, coarse `-10px`), ripple off, `pointer-events: none` when disabled. Use `overlay` where growth would break the layout (the card favorite star).
- **Opacity rule.** `opacity` only for disabled controls and for enter / leave animations. Never to express busy, stale or secondary text: secondary text is `--text-muted` (`#636368` light, contrast checked on all five backgrounds in both themes), a stale block gets `aria-busy` on its container. Non-text glyphs (chip remove icon) may stay dimmed. Do not mix `text-muted` with `color-mix` to fake a lighter tone; a lighter on-colour tone is `color-mix` of the two tokens (tooltip `__kbd`).
- **Native radios** carry no `role="radio"` or `aria-checked`; the native input already exposes both.
- **`ui-steps`** is `role="img"` named by `label` ("Step N of M"), with no live region: the feature moves focus to the new step heading instead.
- **`ui-spinner`** with `label` is `role="status"` with visually hidden text filled after render (so it is announced); without `label` it is `aria-hidden`. `ui-input` forwards its optional `loadingLabel` to the spinner it shows while loading.
- **`ui-card headingLevel`** (`HeadingLevel` 1-6, shared in `lib/models/heading`, default 2; `ui-empty-state` uses the same type): the title link is wrapped in `<hN class="ui-card__heading">`, so a grid of cards is a list of headings at the level the page needs.

- **`ui-checkbox`** extends `UiFieldControl` and implements `FormCheckboxControl` (`checked` model, no `value`): `label` (required), `hint`, `error`, `required`, `disabled`, `name`, `indeterminate` (model, visual dash, cleared by the next toggle), `touch` on blur, `focus()`. ## Highlight and command list (issue #77)

- **`ui-highlight`** (`text`, `query`: a string split on whitespace into terms, or a list of terms): case-insensitive, literal (regex characters are escaped), overlapping and touching matches merge into one `<mark>`; runs are rendered with `@for` as text nodes, never `innerHTML`. At most 20 terms (`HIGHLIGHT_MAX_TERMS`). Mark colours are the tokens `--highlight-bg` / `--highlight-text` (light `#d3e4cf` / `#1f3a1c`, dark `#3a5a34` / `#eaf3e7`; contrast 9.38:1 light and 6.86:1 dark, WCAG AA; `styles.spec.ts` computes it from the compiled tokens), distinct from the `accent-bg` of the selected row. **Deviation from `Search.dc.html`:** the design marks with `accent-bg` / `accent-text`, which vanishes on the selected row (also `accent-bg`), so the mark has its own tokens. The tag-chip variant of the design (bold, transparent mark inside a chip) is deferred: `ui-highlight` has only the one mark style. Pure logic: `highlightParts`, `queryTerms`.
- **`ui-command-list`** (`query` model, required `inputLabel` and `listLabel` (the listbox name, different from the input's), `placeholder`, `busy`; output `selected` of `CommandSelection` `{ value, background }`; `focus()`), with `ui-command-group` (`heading`) and `ui-command-item` (`value`, `disabled`; slots default = title, `leading`, `meta`, `trailing`). The status region is visually hidden (`visually-hidden`) and becomes visible with padding only in the empty state (`--empty`), so it is never `display: none` and its changes are announced. The list does not filter: the feature owns the query, the request and the items; `busy` is `aria-busy` on the listbox. `ViewEncapsulation.None`: the slotted and item-rendered rows are styled from `.ui-command-list`, and `kbd` there has the keyboard-hint style (also in `trailing` and `footer`).
- **Aria wiring.** The input is an `ngCombobox` with `alwaysExpanded` (`aria-expanded` stays true, focus never leaves it, `aria-activedescendant` / `aria-controls` come from Aria); the popup template holds `ngComboboxWidget` + `ngListbox` (`focusMode="activedescendant"`, `selectionMode="explicit"`, `wrap`, `softDisabled` false so arrows skip disabled rows). - **Active row.** After the items or the query change, an effect makes the first enabled row active when the active one is gone or disabled, and always on a new query (`gotoIndex` in a microtask, Aria sorts new options then). `aria-activedescendant` goes through `liveActive`, which drops an id whose row no longer exists. - **Choosing.** Aria's own selection is not used (its `valueChange` is reset to `[]` so the same row can be chosen again). `Enter` in the input emits for the active option, with `background: true` when Ctrl or Cmd is held (Aria does not relay modified Enter); a click does the same with `ctrlKey` / `metaKey`; IME composition (`isComposing` or `keyCode` 229) and disabled rows are ignored. - **2027 look (issue #247).** The input row has no box: a 20px search icon, the bare input (19/26, 16px on a phone) and the `input-end` slot, a divider below it (`--ui-command-divider`, default `--border`); on a phone the field is the mobile-search pill (`radius-full`, `surface`, `shadow-card`, 52px). ## Themes

`global.scss` defines the tokens: scale tokens on `:root`, light on `:root, [data-theme='light']`, dark on `[data-theme='dark']`, and dark again under `@media (prefers-color-scheme: dark)` for `:root:not([data-theme])`. An explicit `data-theme` always wins; without one the OS decides. Every component must work in both; check both in Storybook. The theme names and the attribute are `THEME` (`light`, `dark`) and `THEME_ATTRIBUTE` (`data-theme`) from `lib/models/theme`, used by Storybook, the a11y runner and the app; Sass cannot import them, so `styles/styles.spec.ts` checks the compiled CSS has a `[data-theme=…]` selector for every `THEME` value. Stories show both themes with `Object.values(THEME)`.

**Custom theme (issue #273, BRAND.md Colour).** Light and Dark stay fixed. Custom starts from one of them and only swaps token values: `tokens/_custom.scss` holds SCSS maps (`$custom-accents` per base: `accent`, `accent-bg`, `accent-text`, `focus-ring`; `$custom-backgrounds` per base: `bg`; `$custom-corners`: `radius-sm|md|lg|xl|fab`, never `radius-full`) and `@include custom-themes` in `global.scss` generates `[data-theme='custom']` (light base), `[data-theme='custom'][data-custom-base='dark']` (dark base) and one rule per option on `data-custom-accent` / `data-custom-background` / `data-custom-corners`. The attributes work on `html` (the app's ThemeService) or on any wrapper (stories, `ui-theme-picker` drawings), since custom properties inherit; no inline styles. TypeScript names: `THEME_CUSTOM`, `CUSTOM_THEME_ATTRIBUTE`; the option names are the contracts' `CUSTOM_THEME_*` allow-lists; an own accent colour has no rule (see below). `styles/custom-theme-contrast.spec.ts` compiles the rules and checks every contract combination for WCAG AA (text and muted 4.5:1 on bg, surfaces and accent-bg; accent-text 4.5:1 on accent-bg, surface, bg; accent 4.5:1 on bg and surface, 3:1 on hover, pressed, accent-bg; focus-ring 3:1; border-control 3:1). A new option needs values there first; the spec fails otherwise.

**Animations setting.** `reduced-motion` applies under `@media (prefers-reduced-motion: reduce)` OR `html[data-motion='reduced']` (`MOTION_ATTRIBUTE`, `MOTION_REDUCED`): it emits `:root[data-motion='reduced'] &` for global styles and `:host-context([data-motion='reduced']) &` for component styles (Angular's emulated encapsulation scopes a `:root` ancestor; `styles.spec.ts` checks the encapsulated output). "Full" adds nothing: it never overrides a device request. Script-driven motion asks `ReducedMotion` (`lib/services/motion`, signal `reduced`: device query, followed live, OR the app setting from `setAppReduced`), never its own `matchMedia`; `uiRipple` and `uiPointerShadow` do.

**Own accent colour (#315, ADR 0041).** `customAccentTokens(hex, base, background)` (`lib/utils/custom-accent/custom-accent.ts`) derives the four accent tokens of an own colour: the nearest shade of the same hue and saturation that keeps 4.5:1 on the page and panels and 3:1 on hovered and pressed rows and its own tint (`nearestAccessibleAccent`, `isAccessibleAccent`, `accentContrast`), a ~14% tint that keeps text and muted text at 4.5:1, a deeper or paler `accent-text` and the focus ring. It reads `CUSTOM_THEME_SURFACES` (surfaces, text and backgrounds per base), which `custom-theme-contrast.spec.ts` checks against the compiled Sass, and the spec runs the full AA criteria for a spread of colours. The app applies them as custom properties on `html` with `data-custom-accent="own"` (`CUSTOM_ACCENT_OWN`; CSSOM, CSP-safe); `ThemePickerOption.tokens` sets them on a thumbnail. `contrastRatio` and `parseHex` (`lib/utils/colour-contrast/colour-contrast.ts`) are the WCAG helpers.

**Colour picker (rebuilt in #335).** `ui-color-picker` (`value` model `#rrggbb` or empty, `open` model, `selected`, required `label`, `pickerLabel` (the area's group name), `saturationLabel`, `brightnessLabel`, `hueLabel`, `hexLabel`, `invalidMessage`, `disabled`; required `addLabel` ("Add colour") and `cancelLabel` ("Cancel"); outputs `committed` (the explicit choice) and `touch`; `FormValueControl<string>`): a 36px round swatch button (44px on coarse pointers; a colour wheel from the folder colour tokens with "+", or the chosen colour; the checked ring when `selected`) with `aria-expanded` / `aria-controls`, disclosing a panel (`role="group"`, `enter(disclose)` / `leave(disclose)`: the height opens through `grid-template-rows` 0fr to 1fr with a fade, a plain fade under reduced motion) with a saturation / brightness area (pointer and touch drag with pointer capture, `touch-action: none`; the keyboard uses two visually hidden range inputs, brightness and saturation, one drawn handle), a hue slider (a native range input with a rainbow track, 44px tall on coarse pointers), a colour preview and the hex field (accepts `#rrggbb` or `rrggbb` in any case, `aria-invalid` and a message otherwise). Every slider has its label and an `aria-valuetext` (`NN%`, `NNN°`). The model is HSV (`hexToHsv` / `hsvToHex` in `colour-contrast`) and keeps the hue while the colour is grey. Opening moves focus to the hex field; Esc closes and returns to the swatch. `value` follows every change as a **preview only** (dragging in the area, the hue slider and a typed valid hex change the swatch, the preview and the handles, nothing else; Enter in the hex field or a slider never submits a surrounding form and chooses nothing). `committed` fires once, from the explicit **Add colour** button (a primary `ui-button`, disabled while the hex text is not a colour) and is the moment the caller saves and applies; **Cancel**, Esc and the swatch (closing the panel) discard the preview and put `value` back to what it was when the panel opened (#350). The host is `display: contents`: the swatch sits in the surrounding wrapping row and the open panel takes a line of its own; projected content shows under the fields (the app's contrast warning). Story: `Components/ColorPicker`.

**Own page background (#335).** `customBackgroundTokens(hex, base)` (`lib/utils/custom-background`) returns `--bg`: the nearest shade of the colour (hue and saturation kept, lightness towards white on the light base and towards black on the dark base) on which text and muted text keep 4.5:1 (`nearestReadableBackground`, `isReadableBackground`, `backgroundContrast`); `customAccentTokens` counts an own background as that readable shade. The app sets `data-custom-background="own"` (`CUSTOM_BACKGROUND_OWN`) and `--bg` on `html` through CSSOM.

**Theme picker and preview.** `ui-theme-picker` (`kind` theme | accent | background, `THEME_PICKER_KIND`) is a radiogroup of native radios whose drawings carry each option's theme attributes (`ThemePickerOption`: `theme` incl. `system` for the split thumb, `base`, `accent`, `background`, `corners`), so they show the real tokens; frame, ring, focus and caption use the page's tokens. `ui-theme-preview` is a static sample (sidebar, cards) in the tokens of its ancestors, one `role="img"`. Stories: `Components/ThemePicker`, `Components/ThemePreview` (light, dark and custom panes).

## Icons

- `ui-icon name="…"` draws a symbol from `src/assets/icons/sprite.svg` via `<use href="…#sm-<name>">`. Icons are filled outlines: colour comes from `currentColor`; never ship `stroke`. Sizes 16, 20 or 24 only; **24 is the default** (the set is drawn on a 24px grid, so strokes stay crisp). 20 is kept only where 24 does not fit: chips (28px high), small buttons (32px), segmented control, select options, tag-input options, breadcrumb chevrons, notices, save status; the checkbox tick and favicon fallback stay 16.
- **Icon-only `ui-button`** shows a tooltip with its `ariaLabel` automatically (an explicit `uiTooltip` on the host wins; toggles set a `uiTooltip` with the current action). The chip menu/remove and input clear buttons do the same.
- **Scrollbars** are global (`styles/_scrollbar.scss`): thin, rounded muted thumb, transparent track, stronger on hover (`::-webkit-scrollbar*` for Chromium/Safari, `scrollbar-width` / `scrollbar-color` for Firefox).
- Sizes are tokens too: `--icon-size-sm|md|lg` (16 / 20 / 24px) and `ICON_SIZE.Sm|Md|Lg` in TypeScript; `Lg` is the size of menu item icons and of every icon inside a dialog (`ui-dialog` sets `--ui-dialog-icon-size`, read by `ui-button`, `ui-select`, `ui-chip`; `--ui-icon-size` on any element overrides the size of the `ui-icon`s below it).
- A moved overlay element (menu, select and tag-input popups) is hidden by `ConnectedOverlay` (inline `display: none`) in the same task the CDK puts it back into the page on detach, so it never takes room in the layout while the owner's "shown" class is still set.
- The sprite is an external file, not inlined, so the CSP needs no `unsafe-inline`. Its URL is the `ICON_SPRITE_URL` token (default `assets/ui/icons/sprite.svg`); the app maps `libs/ui/src/assets` to `assets/ui`.
- **Add an icon (issue #210):** drop one filled-outline SVG on the 24px grid in `libs/ui/src/icons/<name>.svg` and run `npx nx run ui:icons` (`node scripts/build-icon-sprite.mjs`). It optimises every file with a strict allowlist (hand-written, no SVGO: the sources are trusted, filled paths only; it strips `fill` and `stroke`, sets `viewBox="0 0 24 24"`, drops comments, titles, metadata and ids, and fails on strokes, styles, scripts, links or unknown elements and attributes), then writes `src/assets/icons/sprite.svg` (`<symbol id="sm-<name>">`, sorted, deterministic) and `lib/components/icon/models/icon-names.const.ts` (`ICON_NAMES`, sorted). Never edit those two files by hand. Both are committed; `ui` and `web` `build`, `serve`, `test`, `storybook` and `build-storybook` depend on `ui:icons` (inputs `libs/ui/src/icons/**`). Drift check: `node scripts/build-icon-sprite.mjs --check` runs in CI before Nx and in `icon-names.spec.ts`; `scripts/build-icon-sprite.test.mjs` covers the optimiser (`node --test scripts/`). `docs/design/assets/icons/sm-*.svg` stays the design reference: `icon-names.spec.ts` compares each design file with its source and its symbol, per file.
- Brand-mark exception: `google` and `github` are the only symbols allowed to carry `fill`, and only fixed brand colours (GitHub stays `currentColor`, Google has four fixed fills that ignore the host colour); the script keeps `fill` for those two names only (`BRAND_MARKS`) and the spec checks it. They have no design file. The large button draws them at 20px (the design draws 18px; sizes stay 16 / 20 / 24).
- **App glyphs** without a design file (`APP_ICONS` in `icon-names.spec.ts`): `play` (#270), `pin` (#312, the sidebar and card pin of the Main mockup) and `message` (#315, the speech bubble of every "Send feedback" entry: the account menu, the sidebar row, the phone You list and Settings › Your feedback), plus `code` (JSON) and `globe` (#335, a ring, a meridian and the equator: a web page, "Bookmarks HTML"), which tell the export formats apart in the Export menus and the Settings › Export rows; the `bookmark` ribbon stays for saving a link. They are drawn from the mockup's 1.75px strokes, expanded to filled outlines (round caps and joins), like the rest of the set.
- **Key glyph icons** `key-command`, `key-option`, `key-shift`, `key-enter` (drawn for this app, no design file) are the modifier caps for `kbd` hints: Onest has no glyph for the command, option or shift signs (its subsets stop short of U+2318, U+2325, U+21E7) and the `kbd` falls back to `--font-mono` system fonts, where they sit high and small, so caps draw them as `ui-icon` (16px) centred in the cap. Arrows and plain letters stay text. Put the spoken name next to the icon (`ui-command-list__sr`); the icon is `aria-hidden`.

- Angular CDK component harnesses (`@angular/cdk/testing`) for the shared interactive components live next to them: `components/<name>/testing/<name>.harness.ts` (sub-harnesses beside it, for example `menu-item.harness.ts`, `tree-item.harness.ts`, `choice.harness.ts`; `select/testing/option.harness.ts` is shared by select, tag-input and command-list), filter interfaces and slot constants in `testing/models/`, and a `<name>.harness.spec.ts` that drives the harness against a small TestBed host with `TestbedHarnessEnvironment`.
- Existing: button, menu / menu item, select / option, dialog, sheet, tree / tree item, card, command-list, tag-input, choice-grid / choice, color-picker, emoji-picker (APIs in `docs/test-rebalance-349.md` 4.1). A new interactive component that features test gets one.
- Rules: `hostSelector` is the component selector (a row harness may use a role, `ui-tree [role="treeitem"]`); a static `with()` returns a `HarnessPredicate` with the filters users need (text, label, name, disabled, ...); methods are user actions and states (click, open, choose, isDisabled, getText), never raw `TestElement`s of the inner DOM; content-projecting components extend `ContentContainerComponentHarness` (areas as an `as const` slot map, `DIALOG_HARNESS_SLOT`, `CARD_HARNESS_SLOT`). Overlay content is reached with `documentRootLocatorFactory()`, through `aria-controls` where the component writes it.
- Export each harness and its types from `src/testing/index.ts`, never from `src/index.ts`. `tsconfig.lib.json` excludes every `testing/` folder and lint bans `@shelfmark/ui/testing` outside specs and `testing/` folders, so harnesses never reach a bundle. `**/testing/**` is outside the coverage count; the harness specs still run.
- Component specs may keep querying their own DOM (they test the internals); specs of composites (a component that uses another one) and app specs use the harnesses. E2e stays on role locators (ADR 0043, D6).
