# apps/api

NestJS REST API, mounted under `/api` (port 3000). Source of truth: `docs/PROJECT.md` 5.2–5.4, 5.8 and 6.

## Stack

- NestJS 12 (`@nestjs/common|core|platform-express` 12.3.3, ESM-only), Express, `@nestjs/swagger` 12, `class-validator` + `class-transformer`, `helmet`.
- Build: webpack (`webpack-cli build`, tsc loader, ESM output, all dependencies external) into `dist/apps/api` (`main.mjs`, `vercel-handler.mjs`; `.mjs` so the module type is never guessed). No esbuild: it does not emit decorator metadata, which Nest DI needs. No `@nx/nest` (no Nest 12 support), no `@nx/node`, no `@nestjs/cli`, no `@nestjs/config`.
- `@nx/webpack` 24 has no `webpack` executor, so `build` and `serve` are `nx:run-commands` around `webpack-cli`.
- Database: Prisma 7 (`prisma-client` generator, ESM, output `src/generated/prisma`, git-ignored, built by the cached `prisma-generate` target) with the `pg` driver adapter (`@prisma/adapter-pg`); no native engine at runtime. Local dev and tests use embedded Postgres (PGlite) instead of Docker (ADR 0025). Prisma's install scripts are denied (ADR 0020): the CLI downloads its schema engine on first use.
- Tests: Vitest with SWC (`unplugin-swc`, Vite's own TS transform disabled with `oxc: false`) so decorator metadata works. Supertest on `createApp()`.

## Layout

- `src/main.ts` - bootstrap and `listen` only.
- `src/vercel-handler.ts` - second webpack entry (`vercel-handler.mjs`): Vercel Function handler, one Nest app per instance (`createApp()` + `init()`, no `listen`), cached promise reset on failure. Re-exported by the root `api/index.mjs` (ADR 0019).
- `src/app/create-app.ts` - `NestFactory` (explicit `ExpressAdapter`) + `configureApp`; reused by `main.ts`, the Vercel handler and tests.
- `src/app/configure-app.ts` - request id, helmet, 100kb JSON limit, `/api` prefix, global `ValidationPipe` (whitelist, forbidNonWhitelisted, transform), `AllExceptionsFilter`, Swagger at `/api/docs` (public in every environment, by decision).
- `src/monitoring/` - Sentry (ADR 0032): `initMonitoring` (no-op without `SENTRY_DSN`, minimal integrations, `scrubEvent` as `beforeSend`), `reportException` (called by the error filter for 5xx), `GET /api/monitoring/config` and `POST /api/monitoring/tunnel` (envelope must name our own DSN, 64 KiB limit, no cookies upstream). Web scrubber twin: `apps/web/src/app/core/monitoring/scrub-event.ts`, keep in sync.
- `src/config/` - typed readers for `PORT`, `NODE_ENV`, `DATABASE_URL` and the Better Auth variables (`readAuthConfig`), validated at boot; errors name the variable and never echo a value. Never loads `.env` files.
- `src/prisma/` - global `PrismaModule` and `PrismaService` (lazy connect: boot and `/api/health` never touch the database). Imported by `AppModule` (auth needs it), so boot validates `DATABASE_URL`.
- `prisma/` - `schema.prisma` and `migrations/` (checked in); `prisma.config.ts` reads the URLs from the environment only.
- `scripts/` - `local-db.mjs` (PGlite + socket server, runs a command with the database URLs set), `db-check.mjs`, `migrate-deploy.mjs` (Vercel build only: production of `main` or preview). The persistent data dir `tmp/pglite/api` is locked by a pid file (`.lock`): one process at a time; the shadow database starts only with `--shadow`.
- `test-utils/test-database.ts` - per test file in-memory PGlite with all migrations applied (`createTestDatabase()`, `truncateAll()`, `close()`; loads the `pg_trgm` and `vector` (pgvector 0.8, `@electric-sql/pglite-pgvector`) extensions, as does `local-db.mjs`; a spec that builds its own PGlite for a migration must load both); served by `exchange-socket-server.ts`, not `PGLiteSocketServer` (that one queues single protocol messages, so parallel pooled connections interleave Parse/Bind/Execute on the one shared session and fail with P2039 / "Failed to get session"). Ours runs a whole exchange (up to Sync/Query) as a unit and keeps the session with one connection while its transaction is open. Never add test-level `retry` to hide such flakes.
- `test-utils/auth-test-app.ts`, `oauth-provider-stub.ts`, `sign-in-as.ts` - auth harness: `createAuthTestApp()` boots `AppModule` on PGlite with per-run random secrets; `stubOAuthProviders()` fakes GitHub/Google on `globalThis.fetch` (any other URL throws); `signInAs(app, baseUrl, { email, name, provider? })` drives the real flow and returns `{ userId, cookie }`: call it twice for the two users of a data-isolation test.
- `test-utils/awaitable-deferrer.ts` - `AwaitableDeferrer`, the test double for `AiBackgroundService` (override the provider with it): deferred AI tasks wait until the spec calls `flush()`, which runs them (and what they defer in turn) in order and rethrows the first failure, so a spec decides when "after the response" happens; `size`, `clear()`.
- `test-utils/isolation/` - data-isolation harness (ADR 0029): `createIsolationUsers`, `asUser` / `anonymous`, `expectIsolated`, plus test-only `NotesFixtureModule` and `LeakyNotesFixtureModule` (pass them as `createAuthTestApp({ imports })`, never into `AppModule`).
- `src/auth/` - Better Auth on `/api/auth/*` (ADR 0030): `auth.module.ts` (community Nest integration, no CORS, our JSON parser, its own guard off; `SessionAuthGuard` is registered as `APP_GUARD` in `AppModule` after the throttler and `CsrfGuard`), `session-auth.guard.ts` (public check first, read-only session lookup, 4xx to 401, ADR 0029), `create-auth.ts` (factory from `AuthConfig` + the Prisma client), `strip-oauth-tokens.ts` (provider tokens are never stored), `to-auth-session-response.ts` (HTTP `get-session` returns only the contract), `auth-logger.ts` (message only), `auth-allow-list.middleware.ts` + `models/allowed-auth-route.const.ts` (allow-list in `configureApp`: only POST sign-in/social, GET callback/{google,github}, GET get-session, POST sign-out reach Better Auth; everything else under `/api/auth` is 404) and `models/disabled-auth-path.const.ts` (second layer). Auth responses bypass `ValidationPipe` and `AllExceptionsFilter`: errors there are Better Auth's `{ code, message }`, not `ApiError`.
- `src/common/` - cross-cutting pieces (request id, error filter, `auth/`: `@AllowAnonymous`, `@CurrentUser()` in `current-user.decorator.ts`, `models/public-route.const.ts` = `PUBLIC_ROUTES`, the only allowed public routes; `scan-routes.ts` + `route-protection.spec.ts` enforce it).
- `src/common/rate-limit/` (`RATE_LIMIT` presets, `@RateLimit`, `clientIp`, auth middleware), `src/common/interceptors/` (`LoggingInterceptor`: method, route pattern, status, duration, request id only; `TimeoutInterceptor`: `REQUEST_TIMEOUT_MS` below the Vercel `maxDuration`, 504), `src/common/csrf/` (`CsrfGuard`: foreign `Origin` 403, non-JSON body 415 on unsafe methods; the one exemption from the 415 rule is exactly `POST /api/monitoring/tunnel`, `models/csrf-content-type-exempt-route.const.ts`, because Sentry sends text/plain).
- `src/<domain>/` - one module per domain (`auth`, `users`, `links`, `folders`, `tags`, `metadata`, ...) with `*.module.ts`, `*.controller.ts`, `*.service.ts`, `dto/`.
- `src/links/` (ADR 0033): `LinksService` (list, recent, get, preview), `LinksWriteService` (create, update, open, delete), `LinkPreviewService` (fetch through `SafeFetcherService`, one fallback for every failure), `link-where.ts` (shared filter builder: user, folder = direct children, unsorted, favorite, tags AND, search words AND over title, note and URL; the export reuses it), `common/util/escape-like.ts` (every search word and every insensitive tag-name match is escaped: Prisma emits `ILIKE` for both), `common/validation/` (control characters, NUL included, are a 400 in text fields), `link-cursor.ts` (keyset cursor `{v,s,o,k,id}`; a cursor for another sort or order is a 400). `faviconUrl` / `imageUrl` in responses are same-origin paths (`/api/links/:id/favicon|image?v=<hash>`) when an image was captured (or a capture is pending), else `null`; the remote source URLs are stored but never returned. Create is idempotent through `idempotencyKey` (replay answers 200 with the first link) and capped at `LINK_LIMIT.PerUserMax`.
- `src/links/images/` (#149, ADR 0027): `LinkImageCaptureService` (best effort, never throws, after the create transaction, 5 s budget capped by the rest of the request, confirms the link is the user's before writing), `processLinkImage` (sniff by magic bytes, `sharp` first frame, metadata stripped, WebP: preview 640x360 cover <= 64 KB, favicon 32x32 contain <= 8 KB, 16 MP input limit; SVG/HTML/damaged -> `null`), `decodeIco` (libvips has no ICO), `LinkImagesService.find` (userId filter, 404 for foreign or missing), `sendLinkImage` (stored type, `nosniff`, CORP same-origin, inline, `private, max-age=31536000, immutable`, ETag). `sharp` has no install script (ADR 0020) and must stay imported in `api/index.mjs` with `node_modules/@img/**` in `vercel.json` `includeFiles`. `PATCH` with a new URL deletes the images and the source hints and sets `links.capture_attempted_at` to `NULL` (pending); the link response then carries `?v=pending` image paths (`LINK_IMAGE_PENDING_VERSION`). `POST /api/links/:id/images/capture` (#189, `LinkImageRecaptureService`, `RATE_LIMIT.AddLink`, covered by the global `CsrfGuard`) re-captures: atomic claim (`capture_attempted_at IS NULL OR older than RECAPTURE_COOLDOWN_MS`, plain SQL so `updated_at` stays), page load for new hints (3 s) when none are stored, the normal capture of both kinds, a re-check that the URL did not change meanwhile, all within the request budget (1.5 s margin), no transaction, no lock, only `SafeFetcherService`. It always answers 200 with the `LinkResponse` as it is afterwards (a call that lost the claim or found nothing changes nothing); a foreign or missing link is 404 and claims nothing. `GET /api/links/:id/favicon|image` stay pure reads.
- `src/feedback/` (#100): `FeedbackService` (`prompt` reads `createdAt` / `isDemo` / `onboardingCompletedAt` from the database and applies `dueFeedbackMilestone`; `record` creates the row or appends the comment under the per-user advisory lock `feedback:<userId>`). The comment is user text and is never logged.
- `src/shares/` (#276, ADR 0040): public collections. `FolderSharesService` (owner: get, enable with the `folders:` lock, the 10-per-user cap and 403 for demo users, `showNotes`, reset, disable; a token collision on the unique index is retried) behind `FolderSharesController` (`/api/folders/:id/share`); `PublicCollectionsService` + `PublicCollectionsController` (`/api/public/collections/:token` and its `links/:linkId/favicon|image`, all three in `PUBLIC_ROUTES`, `RATE_LIMIT.PublicCollection` / `PublicCollectionImage`): a token of the wrong shape is refused before any query, then one `findUnique` on the token; the subtree comes from a recursive query restricted to the owner; every miss is the same `SHARE_ERROR_MESSAGE.NotFound` 404; `X-Robots-Tag: noindex, nofollow` and `Cache-Control: no-store` are set before the service runs, so errors carry them too. The token is a capability: never log it.
- `src/trash/` (#262, ADR 0036): deletes of links and folders are soft (`deleted_at`); every live read and write filters `deletedAt: null` (`link-where.ts`, folder lookups, counts, tags counts, export, recent, duplicate check, image capture), except the link image GET routes (a trashed link keeps its previews), tag merge (moves tags on trashed links too), `clearHistory` and idempotent create replay. A folder delete sets one shared timestamp on the live subtree (and its live links in `delete-links` mode), which is what makes a Trash entry. `TrashService` (list, restore, delete forever, empty; plain SQL so `updated_at` stays; under the `folders:` lock) and `TrashCleanupService` (`GET /api/cron/trash-cleanup`, `CronSecretGuard`, 500 rows per batch, 5 s budget, one `now` per run). Limits (links, folders, demo cap) count trashed rows. `GET`/`PATCH /api/me/settings` (`trashRetentionDays`) live in `src/users/`.
- `src/pins/` (#263, ADR 0037): sidebar pins (`GET`/`POST /api/pins`, `PUT /api/pins/order`, `DELETE /api/pins/:kind/:id`) are `pinned_position` columns on folders and links, max 7 live ones per user, written under the `folders:` lock with plain SQL (`updated_at` stays). Trashing clears the pin. Folder `colour`/`icon` (allow-lists `FOLDER_COLOUR`/`FOLDER_ICON`), `description` (#418: trimmed, blank is `null`, at most `FOLDER_LIMIT.DescriptionMax`, no control characters, a CHECK), `highlighted` (#440, boolean, default false: the folder's sidebar row and page header wear a tint of its colour) and `coverLinkId` (#418: a live own link directly in that folder, else 404 `CoverNotFound`; no foreign key, `loadFolderCovers` answers `coverLinkId` / `coverUrl` only while that still holds) go through `PATCH /api/folders/:id`; links pin to the top of their folder with `PATCH {pinnedInFolder}` and `GET /api/links?folderId=` returns them as `pinned` on page one only (the keyset list holds the unpinned). `folderColours` joins `/api/me/settings`. `pauseHistory` (#269, `users.history_paused`) joins it too: `LinksWriteService.open` reads it in the same `UPDATE … FROM users` statement and keeps `last_opened_at` while paused (`recorded: false`). The appearance (#273) joins it as well: `theme`, `customTheme` (`users.custom_theme_base|accent|background|corners`, always written whole) and `motion`, columns with CHECKs that mirror the contract allow-lists (a background must belong to its base); `CustomThemeDto` validates the nested object strictly. `users.appearance_saved_at` (nullable) is set by the first write of any of the three and answered as `appearanceSaved`, so the web keeps a theme the browser had before; `toAppearanceSettings` falls back to the defaults for anything a hand edit put past the CHECKs. The appearance extras (#285) belong to it: `textSize`, `font`, `density`, `cardPreview` (text columns with CHECKs) and `cardSite`, `cardNotes` and `cardTags` (`folderHighlight` of #418 is retired in #440: the column is dropped and the DTO refuses the field); any of them sent sets `appearance_saved_at` too. Settings › Library (#284) joins it too: `defaultView`, `defaultSort`, `openLinksIn` (text columns with CHECKs), `showFolderCounts`, `fetchPreviews` and `newLinksFolderId` (`warn_duplicates` / `keep_query` are retired in #315: never read or written, unknown fields in the DTO, dropped by a later migration) (no FK: `PATCH` needs a live own folder via `FoldersService.requireOwned`, 404 otherwise; `getSettings` answers `null` once it is trashed or gone; `toLibrarySettings`). Settings › Language (#274) joins it too: `language`, `dateFormat`, `timeFormat`, `weekStart` (text columns with CHECKs; `spellcheck` is retired in #326: spell-check in the note field is always on, the column is never read or written, an unknown field in the DTO, dropped by a later migration); any of them sent sets `users.language_saved_at`, answered as `languageSaved` (`toLanguageSettings` falls back to the defaults past the CHECKs). `links/link-save-prefs.ts` (`readLinkSavePrefs`, `savedUrl`) is read by create, update and preview: tracking parameters are always stripped (#315) (`stripTrackingParams` and the deny list in contracts) before normalising; `fetchPreviews` off skips `LinkPreviewService` and the image capture of a new link and ignores the client's image hints (the SSRF path itself is unchanged).
- `src/views/` (#264, ADR 0038): saved views (`GET`/`POST /api/views`, `PATCH`/`DELETE /api/views/:id`, `PUT /api/views/order`), `query` is `jsonb` validated by a strict nested DTO and read back with `parseStoredQuery`; at most 20 per user under the `views:<userId>` lock (never taken with another lock), `RATE_LIMIT.ViewWrite`. Counts and the total come from one `COUNT(*) FILTER` statement (`saved-view-counts.ts`, the SQL twin of `buildLinkWhere`, `Prisma.sql` only). A folder view needs a live own folder on write; later it is `available: false` with count 0 while the folder is gone. Starter views come from the `users_seed_saved_views` trigger of the migration. `links.kind` (ADR 0038): `deriveLinkKind` in contracts, `og:type` read by `extractPreview`, host recompute on a URL change, `?kind=` on list and export.
- `src/rules/` (#398): domain rules (`GET`/`POST /api/rules`, `PATCH`/`DELETE /api/rules/:id`, `GET /api/rules/:id/matches`), `link_rules` with a unique `(user_id, domain)`, the domain normalised by `RuleDomain` (`normalizeRuleDomain` in contracts), at most `RULE_LIMIT.PerUserMax` under the `rules:<userId>` lock (never taken with another lock), `RATE_LIMIT.RuleWrite`. `RulesService.matcher(db, userId)` is what link creates use: `LinksWriteService.create` and `LinksBatchService` call it on their transaction after the `folders:` lock and fill the folder (only a live own one) and tags the request left open, unless `applyRules: false`; `findMatchingRule` (contracts) picks the most specific domain.
- `src/links/links-bulk.service.ts` (#267): `POST /api/links/batch/delete` (`{ ids }` → `{ deleted }`, the contract of #265, here a Trash soft delete with one shared `deleted_at`, plain SQL, pins cleared) and `POST /api/links/batch/update` (`folderId`, `addTags`, `removeTags`, `isFavorite` for up to `LINK_LIMIT.BatchMax` own live links in one transaction; folders lock before tags lock; a link past `TagsMax` fails all with 409; foreign, missing and trashed ids are ignored, so nothing tells whether an id exists). Rate limits `DeleteLinksBatch`, `UpdateLinksBatch`.
- `src/users/me-stats.service.ts` (#352): `GET /api/me/stats` (`MeStatsResponse`): counts of live links, folders and tags (a tag only while it is on a live link, like the top tags), top 5 hosts (lower case, `www.` dropped by SQL regex, favicon path of the newest link with a captured favicon), top 5 tags on live links, live links per week of UTC days starting on the ISO weekday `?firstDay=` (1 Monday … 7 Sunday, default 1, `MeStatsQueryDto`; the 12 weeks of `statsWeekStarts(now, firstDay)` in contracts, the SQL subtracts `(isodow - firstDay + 7) % 7` days), member since, oldest live link and the connected providers (`accounts.provider_id` + `created_at` only, never tokens or provider ids). Prisma counts plus tagged-template `$queryRaw`, every query on the session user, ties ordered `COLLATE "C"` like the web mock (`build-mock-stats.ts`). Global rate limit like the other `/api/me` reads.
- `src/feedback/` messages (#272): same table, rows with `kind` set. `FeedbackMessagesService` (`send` counts `PerHourMax` per rolling hour in Postgres under the advisory lock `feedback-message:<userId>`, 429 + `Retry-After`; `attachScreenshot` (#352) under the per-user lock `feedback-screenshot:<userId>`: 3 per message, 10 minutes after sending, and the screenshot bytes on the user's messages of the last 24 hours at most `ScreenshotBytesPerDayMax` / `DemoScreenshotBytesPerDayMax`, else 429 + `Retry-After`; `list`; `findScreenshot` with the userId filter), `dto/is-screenshot-data.decorator.ts` (canonical base64, size, magic bytes), `feedback-screenshot-body-parser.ts` (3 MB JSON parser for `POST /api/feedback/messages/:id/screenshots` only, mounted before the global 100kb parser in `configureApp`; the message route keeps 100kb), `sendFeedbackScreenshot` (`nosniff`, inline, `private, no-store`; both screenshot GET routes use `PrivateNoStoreInterceptor` from `common/interceptors`, so their errors carry it too). Never select `screenshot` outside the screenshot routes; ratings read `kind: null`.
- `src/admin/` (#272): `AdminGuard` (session email in `ADMIN_EMAILS`, read per request by `config/admin-config.ts`, demo never, else 404) on `GET /api/admin/status`, `GET|PATCH /api/admin/feedback`, `GET /api/admin/feedback/:id/screenshot`; `SessionAuthGuard` answers a missing session below `/api/admin` with 404. Admin queries are the only ones not filtered by the session `userId`: the inbox touches message rows only. `GET /api/admin/stats` (#333, ADR 0045, `RATE_LIMIT.Admin`, `no-store`): `AdminStatsService` computes usage aggregates over real users (not demo, email not in `ADMIN_EMAILS`) on request in one read-only transaction with a 5 s statement timeout (tagged `$queryRaw` only, nothing stored); every distribution goes through `suppressSmallGroups` and every share through `toAdminStatsRate` (`ADMIN_STATS_LIMIT.MinGroup`; hidden with a base below it or a group of 1 to 2 on either side), rating score groups through `suppressSmallGroups`, sign-up series zero below the minimum number of real users; the response allow-list is checked by `expectAdminStatsShape` (`@shelfmark/contract-tests`). `UserActivityService` (`src/users/`, provided in `AppModule`): `SessionAuthGuard` calls `touch` without waiting for every resolved non-demo session; it writes `users.last_active_on` (UTC day) at most once per user and day, in plain SQL so `updated_at` stays; a failure is logged without the user and never fails the request.
- `src/reminders/` (#275): in-app reminders, one `links.remind_at` per link (nullable, partial index `(user_id, remind_at)`); due = `remind_at <= now()`, computed on read (no cron). `RemindersService`: `list` (due longest first, upcoming soonest first, `REMINDER_LIMIT.ListMax` each), `count` (one indexed count), `set` (`null` clears), `setMany` (foreign, missing and trashed ids ignored); writes are plain SQL so `updated_at` stays, every statement on the session user and live links; the time is checked by `remindAtProblem` (contracts, shared with the web mock: future with `PastToleranceMs` skew, at most `MaxAheadDays`), the DTO only checks an ISO time with an offset (`IsRemindAt`). `RATE_LIMIT.ReminderWrite` on the writes. A trashed link keeps its reminder and leaves the list and the count. The demo seed's `remindInHours` sets one due and one upcoming reminder.
- `src/ai/` (#389–#391, ADR 0047 / 0048): `AiModule` imports `FetcherModule`, `FoldersModule`, `RulesModule` (Tidy apply re-checks domain rules, AI-2) and `TagsModule` and exports the registry, settings, usage, jobs, suggestions and link hooks services. `LinksModule` imports it (enqueue and draft attach inside the create transaction), so **`AiModule` must never import `LinksModule`**. Layout:
  - `config/` - `readAiConfig` (`ANTHROPIC_API_KEY`, `VOYAGE_API_KEY`, `AI_PROVIDER`; read once at boot through the `AI_CONFIG` provider, never at import time; errors name the variable only; `useRealProvider` / `useRealEmbeddings` only with the respective key, in production, not a Vercel preview, not `AI_PROVIDER=mock`) and `readAiFullAccessEmails` (`AI_FULL_ACCESS_EMAILS`, per request, `readEmailList` like `ADMIN_EMAILS`; like `AdminGuard`, the email counts only when verified and never for a demo user).
  - `providers/` - `AiProviderRegistry.for(user)` (mock unless `useRealProvider` and not a demo user; the real provider is built lazily once through `REAL_AI_PROVIDER_FACTORY`) and `forBatch(provider)` (`null` when a stored real batch cannot be read here: the caller fails its jobs, the mock never answers a real batch); `anthropic-ai.provider.ts` (structured output, refusal handling, Message Batches; 15 s timeout, SDK retries off), `mock-ai.provider.ts` (deterministic, stateless, batches complete at once); `embeddingsFor(user)` (ADR 0050, same rule with `useRealEmbeddings`): `voyage-embedding.provider.ts` (plain HTTPS, see Outbound HTTP) or `mock-embedding.provider.ts` (feature hashing of light word stems plus `MOCK_EMBEDDING_SYNONYMS` into 1,024 dimensions, L2-normalised; a query containing `ai-fail` fails retryably for e2e). Both implement the server-only `EmbeddingProvider` (`models/embedding-provider.interface.ts`: `model`, `dimensions`, `minSimilarity`, `embed(texts, 'document' | 'query')` answering an `EmbedOutcome`, never throwing, never logging texts, vectors or key).
  - `excerpt/` (page text through `SafeFetcherService` with `EXCERPT_FETCH_LIMITS`, `extractExcerpt` with parse5, at most 6,000 characters, never stored), `prompt/` (`buildLinkUserPrompt`: untrusted data in delimited blocks with `<` escaped, folders as short keys, the note only with `includeNotes`; `LINK_OUTPUT_SCHEMA`; `parseLinkOutput`, the narrowing validator: own tags and folders only, one new tag, plain-text summary).
  - Services: `settings/` (`AiSettingsService`: get, update, progress; entitlements), `usage/` (reserve in one statement, refund, backfill allowance), `jobs/` (`AiJobsService`: enqueue in the save transaction, drafts (no row without quota room or past `AI_DRAFT_LIMIT` open drafts a day: a synthetic `skipped`), `lockDraft` and attach (a requeued draft starts its attempts over), `supersede` on a URL change, poll; while AI is off every job reads `skipped`/`off`), `runner/` (`AiRunnerService`: claim with `FOR UPDATE SKIP LOCKED` and a 60 s lease that must outlast excerpt + model call + `LeaseMarginMs` (spec-checked), excerpt, provider call, retry backoff 30 s / 2 min, at most 3 attempts; a run that throws gives its month count back; a missing account fails the job), `apply/` (`AiApplyService`: summary unless the user's, suggestions skipping dismissed, Automatic mode only for `save` / `draft` jobs), `suggestions/` (dismiss, `afterUserEdit` from `PATCH /api/links/:id`), `link-ai/` (state, rewrite under the link row lock, undo), `link-hooks/` (`AiLinkHooksService`: the AI steps of `LinksWriteService.update`), `data/` (`DELETE /api/ai/data`), `backfill/` (`AiBackfillService`: start, stop, claim chunks of 40 with a 5 min chunk lease and submit one provider batch, recorded under the settings row lock only while the chunk's jobs still run (a stop or AI off meanwhile skips and refunds them, and the batch is cancelled); `AiBackfillResultsService`: poll, apply, and `failOrphans` for chunks whose instance died before the batch was recorded (tick per user, sweep for all; failed, refunded, counted done); the runner never claims backfill jobs), `background/` (`AiBackgroundService.defer`: `waitUntil` from `@vercel/functions`, a plain promise outside Vercel; failures logged by error name only), `catch-up/` (`AiCatchUpService`: `tick` and `sweep` answer at once and run the work after the response, 6 s and 25 s budgets).
  - `embeddings/` (AI-3, ADR 0050): search by meaning. `link_embeddings` (one `halfvec(1024)` per link, same-user composite FK with cascade, `model`, `with_note`, `input_hash` = SHA-256 of the text, `stale`; the HNSW index is a partial index in the migration, `WHERE model <> ''`, which every KNN query repeats as `HNSW_INDEX_PREDICATE` so the planner may use it). Read and written only through tagged `$queryRaw` / `$executeRaw`, always with the session `userId`; vectors are bound as text parameters cast `::halfvec` (`toVectorLiteral` validates 1,024 finite numbers). `build-embedding-text.ts` (title, sorted tag names, summary, the note only with `includeNotes`; never URL or folder; 2,000 characters). `AiEmbedService`: the embed pass (no job rows: the derived set of live links with no vector, `stale`, another model or the other note setting, chunks of 64 newest first, links with a pending link job skipped; unchanged hash only clears flags; `ai_usage.embeds` reserved per chunk and refunded on failure; the provider call never inside a transaction; one set-based upsert that writes only still-live own links and stores a link edited meanwhile as stale; per-user lease on `ai_settings.embed_lease_until`; backoff 30 s / 2 min / 10 min via `embed_not_before`), `kick` (after saves and edits, one cheap read, then `AiBackgroundService.defer`), started also by `AiJobsService.start` after link jobs, by the tick and the sweep (`usersWithCandidates`), by turning the switch or AI on and by `includeNotes` changes. `AiSearchStatusService` (`search` in the settings and tick answers: `off`, `processing` below 80% ready, `unavailable` after a failure in the last 15 min, `quota`, `ready`). **`markEmbeddingsStale(tx, userId, { linkIds } | { tagIds })` is a duty for every write path that changes a link's title, note, tags or summary** (today: link update, bulk tag add/remove, tag rename/merge/delete, AI summary and Automatic tags, AI undo, Tidy apply and undo); folder changes never touch vectors. Turning the switch or AI off releases the lease and keeps the vectors; `DELETE /api/ai/data` deletes them and turns the switch off. Trashed links keep their vector and are excluded from every query. Demo sandboxes start with the switch on and a mock vector per seed link (`demo/seed-demo-embeddings.ts`, one set-based insert in the seed transaction, the same text the pass builds), so search by meaning is ready at once.
  - `search/` (AI-3): `MeaningSearchService` behind `GET /api/ai/search?q=&limit=` (`RATE_LIMIT.AiSearch`, always 200 with `{ status, items }`; `q` trimmed and collapsed, 3 to 200 characters, else 400): anything but a `ready` status answers no items; the query vector comes from `QueryEmbeddingCache` (per instance, LRU 500, 10 min, key = SHA-256 of user id, model and query; nothing at rest) or one `embed([q], 'query')` after reserving `ai_usage.search_queries` (none left → `quota`, failure → refund and `unavailable`); `nearestLinks` (KNN of the user's live links of the current model in one transaction with `useHnswSettings`, 20 rows), `rankMeaning` (provider `minSimilarity`, within 0.15 of the best), word matches dropped with `buildLinkWhere(userId, { q })`, `loadMeaningMatches` (links through `toLinkResponse`) and `whyForQuery` (`meaning-why.ts`: tag names, folder name and summary clauses sharing `wordStems` with the query, at most two, else tags, else folder, else the first clause; 80 characters). Logs carry counts and durations only, never the query. `RelatedLinksService` behind `GET /api/links/:id/related?limit=` (`related-links.controller.ts`, default rate limit): the user's live link or 404 (foreign, trashed, missing); off or no vector of the current model → no items with the status; else `nearestLinks` by the link's own stored vector (itself excluded), same ranking, at most 5 (10 with `limit`), `whyForRelated` (shared tag names, then the same folder, then summary clauses sharing stems with its title and summary). No model call.
  - Controllers: `ai.controller.ts` (`/api/ai/*`), `link-ai.controller.ts` (`/api/links/:id/ai*`), `related-links.controller.ts` (`/api/links/:id/related`), `ai-sweep.controller.ts` (`GET /api/cron/ai-sweep`, `@AllowAnonymous` + `CronSecretGuard`, `PUBLIC_ROUTES` entry). The sweep is the only AI code that reads every user's rows; everything else filters by the session `userId`.
  - Locks: a transaction that writes AI results takes `folders:<userId>`, then the job row `FOR UPDATE`, then `tags:<userId>` (create with `aiDraftId`, `AiApplyService`); results are written only while the job is still `running`, so turning AI off or deleting AI data discards a running job's result. `PATCH /api/links/:id` with a new page supersedes the link's queued jobs (`AiLinkHooksService.beforeUpdate`, after `folders:`, before `tags:`); Automatic mode re-counts the link's tags under `tags:` and only suggests when the user tagged it meanwhile; `stop`, turning AI off and `submit` take the settings row before job rows.
  - Logs carry job id, status, reason and counts only: never the prompt, page text, note, model output or key. Tests never reach a provider: specs get the mocks (no key, not production) and `real-client.guard.spec.ts` proves the SDK client is never built and any Voyage request throws.
- **Lock order:** a transaction that takes advisory locks takes `folders:<userId>` (`FoldersService.lockTree`) before `tags:<userId>` (`TagsService.lockUserTags`, also taken inside `resolveNames`), never the reverse. Never fetch a page inside a transaction.

## Rules

- Contract first: request/response shapes live in `libs/shared/contracts` (`@shelfmark/contracts`). A DTO class `implements` the contract interface and carries validation + `@ApiProperty`.
- Contracts: `import type` for shapes. A runtime import (`AUTH_PROVIDER`, `AUTH_ENDPOINT`) works because `webpack.config.js` and `vitest.config.mts` alias `@shelfmark/contracts` to the lib source.
- Controllers are thin; logic lives in services.
- Never use `import type` for injectables (controller/service constructor parameters): it erases decorator metadata and breaks DI.
- Every query on user data filters by `userId` from `@CurrentUser()` (`user.id`), never from body, params or query; a foreign or missing object is 404, never 403. Every user-owned resource gets a data-isolation test (`expectIsolated`, see Testing conventions).
- Every route is closed by default (`SessionAuthGuard`). The integration's package is imported only in `src/auth/**` and `src/common/auth/**` (ESLint); feature modules use `@CurrentUser()` and `@AllowAnonymous()` from `src/common/auth`. No state-changing `GET` (SameSite=Lax cookies ride along on top-level cross-site GETs).
- Errors always use `ApiError` (`{ statusCode, error, message, requestId }`), no stack traces. Validation errors have `message: string[]`.
- `@AllowAnonymous()` is the integration's decorator (key `PUBLIC`). A new public route needs an entry in `PUBLIC_ROUTES`, a comment at the use site and a justification in the PR description; never on a controller class, never `@OptionalAuth()`.
- `NODE_ENV` is fail-safe: only an explicit `development` or `test` is non-production (unset means production). Non-production drops HSTS and `upgrade-insecure-requests` from helmet; `nx serve` sets `NODE_ENV=development`.
- 5xx responses never carry internal messages (generic text); the cause and stack are logged server-side only.
- No CORS: the API is same-origin (web dev proxy `/api` -> `http://localhost:3000`).
- Strict TypeScript: no `any`, no `@ts-ignore`; one interface/type/const per file with the `.interface.ts` / `.type.ts` / `.const.ts` suffix; no TS `enum` (ADR 0024).

## Security

- Never read or create `.env*` files; configuration comes from the platform environment.
- Auth: never set Better Auth's `disableCSRFCheck` or `skipStateCookieCheck`, and never `disableOriginCheck: true` (`createAuth` sets it to `false` explicitly); it skips those checks under `NODE_ENV=test` or a truthy `TEST`, so `vitest.setup.ts` runs specs as `development` without `TEST` and `readAuthConfig` refuses `TEST` in production. Cookies are `SameSite=Lax` (the OAuth callback is a cross-site top-level GET), `Secure` + `__Secure-` exactly when `isProduction`. Never log Better Auth's extra logger arguments (they can hold tokens). A new Better Auth route needs an entry in `ALLOWED_AUTH_ROUTES` on purpose. `disableGlobalAuthGuard: true` stays: it switches off the integration's guard in favour of ours. Rate limits: `@nestjs/throttler` is the first global guard (per client IP, in memory per Vercel instance, ADR 0031); `@RateLimit(RATE_LIMIT.X)` sets a stricter per-route limit, `/api/auth/*` is limited by `createAuthRateLimitMiddleware`, health opts out. Better Auth's own limiter stays as a second layer.
- Never log secrets, tokens, request bodies or personal data. The error filter logs only method, path, status and request id.
- Outbound HTTP (link previews) only through the SSRF-safe fetcher (http/https, private IPs blocked after DNS resolve, timeout, size and redirect limits, no cookies); the exceptions are the AI provider SDK, the Voyage embeddings provider and the Sentry tunnel, each to one fixed host (next section).
- Prisma with parameterised queries only; never `$queryRawUnsafe` / `$executeRawUnsafe` (ESLint forbids both).
- Never read, print or set real database URLs; `local-db.mjs` overrides them with its own loopback URLs.

## Database rules

- Conventions: PascalCase model with `@@map` to a snake_case plural table, camelCase fields with `@map` to snake_case columns, `@default(uuid(7)) @db.Uuid` ids, `@db.Timestamptz(3)` timestamps.
- Never edit an applied migration; add a new one. Destructive changes follow expand-then-contract across deploys (add, backfill and dual-write, switch reads, then drop).
- Migrations are created locally with `nx run api:db-migrate -- --name <name>`, applied in the Vercel build (`api:migrate-deploy`, only when `VERCEL=1`), and verified in CI: CI runs `scripts/db-check.mjs` (deploy plus drift check) against the Postgres service, and `nx run api:db-check` is the local PGlite equivalent.
- Never run `migrate reset` against a non-local database.

## Outbound HTTP: the SSRF-safe fetcher

`src/fetcher/` (`FetcherModule` exports `SafeFetcherService.fetch(url, limits?)` and `fetchImage(url, limits?)`, optional per-call limit overrides that only tighten) is the only allowed way to make an outbound request. Never use `fetch`, `http.request` or an HTTP client anywhere else. Exception (ADR 0048 point 10): the official AI provider SDK `@anthropic-ai/sdk` makes its own HTTPS calls to its fixed host (`api.anthropic.com`, pinned as `ANTHROPIC_LIMIT.BaseUrl` so an `ANTHROPIC_BASE_URL` environment variable is ignored; never a URL derived from user input). Only `src/ai/providers/anthropic-ai.provider.ts` may import it (plus `real-client.guard.spec.ts`), enforced by `no-restricted-imports` in `apps/api/eslint.config.mjs`; every page fetch for AI still goes through `SafeFetcherService`. Sentry's tunnel posts to its fixed host the same way (`src/monitoring/`). Second exception (ADR 0050): the Voyage embeddings provider (`src/ai/providers/voyage-embedding.provider.ts`) calls `fetch` itself, no SDK, one POST to the pinned `VOYAGE_LIMIT.Url` (`https://api.voyageai.com/v1/embeddings`, no base-URL variable), `redirect: 'error'`, `AbortSignal.timeout` (8 s documents, 1.5 s query), the answer capped at 4 MB and narrowed by `parseVoyageResponse`. `no-restricted-globals` / `no-restricted-properties` in `apps/api/eslint.config.mjs` allow `fetch` only in that file and `monitoring.service.ts` (specs excepted); `test-utils/voyage-fetch-guard.ts`, installed by `vitest.setup.ts`, makes any request to the Voyage host throw and fails the spec in `afterEach`. The endpoint that uses it (`POST /api/links/preview` and `POST /api/links` without a title, through `LinkPreviewService`, 6 s budget) lives in `src/links/`.

- URL: http/https only, no credentials, at most 2048 characters, ports 80 and 443 only (a deliberate decision: an open port range makes the fetcher a port scanner; pages on other ports are rare).
- DNS is resolved by the fetcher itself; one blocked address in the answer rejects the host. The connection is pinned to the validated addresses through a custom `lookup` (no second lookup, so no DNS rebinding). Blocked ranges: `models/blocked-ip-ranges.const.ts` (private, loopback, link-local incl. cloud metadata, CGNAT, multicast, reserved, NAT64, 6to4, Teredo, unique-local). `ip-policy.ts` expands IPv6 and unwraps IPv4-mapped / compatible forms; anything that is not a canonical IP literal fails closed. `localhost`, `*.localhost`, `*.local` and `*.internal` are refused by name.
- Every redirect hop goes through the same validation; at most 5 hops. A malformed, empty or non-http(s) `Location` is `InvalidUrl` (or `DisallowedProtocol`), never an unhandled error. No cookies, no `Authorization`, `Accept-Encoding: identity` (a response with any other `Content-Encoding` is `UnsupportedEncoding`), no keep-alive agent (`agent: false`; proxy environment variables such as `NODE_USE_ENV_PROXY` are not honoured, a proxy would bypass the pinned lookup).
- Limits (`models/fetch-limits.const.ts`): 3 s connect, 8 s total, 2 MB body (checked on `Content-Length` and while streaming). Only `text/html` and `application/xhtml+xml` for `fetch`; `fetchImage` (image mode, ADR 0027) takes `image/*` except SVG and `application/octet-stream`, 3 MB, 5 s, 3 redirects, raw bytes, the format is decided from the magic bytes by the caller. The body is decoded with the header charset, else a `<meta charset>`, else UTF-8.
- Failures are `SafeFetchError` with a `code` (`models/safe-fetch-error-code.const.ts`); messages never carry response data. The caller maps them to a fallback preview.
- Tests inject `SAFE_FETCHER_OPTIONS` (fake resolver, loopback policy, local port) and run against a `127.0.0.1` server; unit tests never use the network.
- `src/preview/`: `extractPreview(html, finalUrl)` (parse5; og:title, twitter:title, `<title>`; only the head, first 32 K characters are parsed), `fallbackPreview(url)`; `normalizeUrl` for duplicate detection (PROJECT.md 6.1) lives in `@shelfmark/contracts`, shared with the web app. The document is cut at the first `</head>` (a `</head>` inside a comment or script ends it early; the preview then falls back to the URL data, which is acceptable). Image and favicon URLs must be http(s), without credentials, at most 2048 characters; `<base href>` is honoured only when it is http(s). `parse5` is ESM-only and must stay listed in `api/index.mjs`.

## Commands

```bash
npx nx serve api                  # http://localhost:3000/api (Swagger: /api/docs), with a local PGlite database (data in tmp/pglite/api)
# serve cold start: a production build runs first (dependsOn build), then the webpack
# watch rebuilds and node --watch restarts the server on each change.
npx nx build api                  # dist/apps/api, run with: node dist/apps/api/main.mjs
npx nx run api:prisma-generate    # regenerate the client (cached; build, typecheck, lint and test depend on it)
npx nx run api:db-migrate -- --name <name>   # create and apply a migration on the local database
npx nx run api:db-check           # apply all migrations to a fresh in-memory database and fail on schema drift
npx nx test api                   # Vitest, coverage on by default, thresholds 80%
npx nx run-many -t lint typecheck test build -p api contracts
```

## Testing conventions

- Specs sit next to the code (`*.spec.ts`).
- Integration tests build the app with `createApp()` (or `Test.createTestingModule` + `configureApp`) and call it with Supertest; close the app in `afterAll`.
- Unit-test pure helpers and filters directly; no network, no real database in unit tests. Database tests use `createTestDatabase()` (in-memory PGlite, no Docker); every user-owned resource needs a data-isolation test against it.
- Data isolation: `createAuthTestApp({ imports: [FixtureModule] })`, `createIsolationUsers(t)` and `expectIsolated(app, users, scenario)` from `test-utils/isolation`. Example:

```ts
const users = await createIsolationUsers(t);
await expectIsolated(t.app, users, {
  create: async (a) =>
    (await a.post('/api/links').send({ url: 'https://example.com' }).expect(201)).body.id,
  read: (u, id) => u.get(`/api/links/${id}`),
  update: (u, id) => u.patch(`/api/links/${id}`).send({ title: 'x' }),
  remove: (u, id) => u.delete(`/api/links/${id}`),
  list: {
    request: (u) => u.get('/api/links'),
    ids: (b) => (b as ListLinksResponse).items.map((l) => l.id),
  },
  reference: (u, id) => u.post('/api/links').send({ url: 'https://example.com', folderId: id }),
  // or skip: { reference: 'reason' } (update, remove, list, reference: provide or skip with a reason)
});
```
