Save open tabs — proposal for review (not in the build yet)

Several open tabs go to Shelfmark in one go: the popup lists the tabs of the current window, all ticked except the ones already in the library, the person picks one folder and optional tags for all of them, Save. Same popup frame as Extension.dc.html (360 × 600, footer on the bottom edge), the same folder picker and tag field, the same saving moment. No note and no Fill in with AI here: those are about one page; with AI in auto mode the server still files and tags each new link afterwards, as for any save. Reading other tabs needs Chrome's tabs permission, asked only when the person first opens this view (optional permission, so the install warning stays as it is; state 2).

2 · First time only: allow reading the open tabs

Save open tabs

Let Shelfmark see your tabs

To list the tabs in this window, Chrome asks once to let Shelfmark read their addresses and titles. They stay in your browser until you press Save, and only the tabs you tick are sent.

Continue calls chrome.permissions.request({ permissions: ['tabs'] }); Chrome shows its own prompt ("Read your browsing history" is how Chrome words the tabs permission, so the copy here explains it first). Granted: state 3. Declined: back to the form with nothing changed; the tabs button stays and asks again next time. The permission is optional in the manifest, so the install warning and the store review of the single save do not change. Removing it in Chrome's extension settings brings this screen back.

3 · Pick the tabs, one folder and tags for all, Save

Rows in tab order, the current tab first. Every tab is ticked except those already in the library (a muted "Saved" badge; ticking one saves a copy, like Save a copy). Not listed: chrome:// and other pages that cannot be saved, and the second of two tabs with the same address. The list scrolls inside; the select-all line and the fields stay put. Select-all ticks or clears everything; Space toggles the focused row, arrows move. Folder: the same picker as the single save (Unsorted by default, or the folder chosen on the form before). Domain rules still apply per link on the server, so a link whose domain has a rule lands in that rule's folder when the folder here is Unsorted. Tags go on every link. Save is disabled with nothing ticked and says the count. At most LINK_LIMIT.BatchMax (100) tabs a batch; past that the extra rows are greyed with "Up to 100 at a time".

The batch is one transaction, so it either saves or fails as a whole; only items the API skips come back in errors (an over-long address, a repeat within the batch). Then the heading counts what was saved and the list names the skipped tabs with the reason. A failed batch (no connection, rate limit, the library limit with the API's message of how many more fit) is the single save's error state with "Try again", which resends the same keys, so nothing is saved twice. Signed out on open: the usual signed-out screen.

Open questions for the author

1 · The optional tabs permission is a new permission (apps/extension/CLAUDE.md asks for your OK): Chrome words it as "Read your browsing history" in its prompt. The alternative without it is impossible: other tabs' addresses are only visible with tabs or host access to every site. 2 · Current window only, or a "This window / All windows" switch when several windows are open? The proposal is current window only. 3 · "Close saved tabs" on the done screen — keep, or leave out of v1? 4 · Reusing POST /api/links/batch as it is (5 batches a minute, up to 100 links): no API change needed, only the extension.
