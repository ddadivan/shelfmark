# 0055. Ask your shelf as a chat: Claude tool use over the user's own library, Haiku 5.5 by default with one Sonnet 5.5 escalation, client-held text history, one question per count

- Status: Proposed
- Date: 2026-11-19
- Source: issue #521, `docs/ai/IMPLEMENTATION-ASK-CHAT.md`, `docs/ai/FEATURES.md` F4 and principles 2, 5, 6, 7, `docs/PROJECT.md` 5.6 and 5.8; supersedes points 3, 5, 6 (single-turn) and 8 of [0052](0052-ask-your-shelf-streaming.md) and amends its points 2 and 4; amends [0047](0047-ai-provider-models-and-cost.md) point 2 (Ask model); reuses the shapes and rules of [0054](0054-mcp-server-personal-tokens.md) point 6

## Context

- Ask (ADR 0052, live in 2.2.1) answers one question at a time from the top 10 links that a model-free retrieval picked. On production it cannot answer follow-ups ("and what else?"), cannot count ("how many links do I have / about Angular"), and cannot simply list what it finds ("find the signals article I saved in October"): retrieval decides before the model reads the question, and nothing of the previous turn is sent.
- The author decided (Nov 19, 2026) that Ask becomes a chat over the library with tools and conversation memory, with link cards in answers, read-only tools on the session user only, a tool loop that counts as one question, deadlines inside `maxDuration`, and nothing stored server-side beyond counts. Model decision (author, Nov 19): **Claude Haiku 5.5 by default, Claude Sonnet 5.5 for complex questions.**
- Constraints that stay: one Vercel Function, `maxDuration: 30` (ADR 0049); `POST /api/ai/ask` is the only `@LongRunning()` route; SSE over a POST read with `fetch` (ADR 0052 point 1); limits Free 5 a month, AI pack 50 a day and 500 a month (ADR 0052 point 7); the mock is the only provider outside production and for demo users (ADR 0047 point 5).
- `claude-sonnet-5-5` rejects `thinking: { type: 'disabled' }` with a 400; Ask already sends `thinking: { type: 'between_tools' }` (no thinking before the first output; the model may think after tool results). Thinking blocks returned inside a tool loop must go back unchanged (with their signatures) in the next request of that loop and count as output tokens.
- Prices (Nov 2026, per million tokens): Sonnet 5.5 $2 input, $10 output, cache reads $0.10, cache writes 1.25 × input ($2.50); Haiku 5.5 $0.10 input, $0.50 output, cache writes $0.125, cache reads assumed at the same ratio as Sonnet ($0.01, to be confirmed on the price page).
- MCP (ADR 0054) already has read-only tools `search_links`, `get_link`, `list_folders`, `list_tags` with strict argument parsers, an allow-list link mapper and an untrusted-content note. Ask has no token and runs inside the app session, so it reuses the shapes and rules, not the JSON-RPC layer.

## Decision

1. **Models and escalation.** Two profiles in `AI_MODEL` / `ASK_MODEL_PROFILE` (named constants, ADR 0047 point 2): **Quick** = `claude-haiku-5-5` (effort `medium`) answers every question first; **Deep** = `claude-sonnet-5-5` (effort `medium`, `thinking: between_tools`). Each profile carries its own thinking setting, round and final `max_tokens`; the Haiku thinking setting is whatever the API accepts for "no thinking before the first output" and is pinned by a provider spec (checked on a preview before release).
   - **Who decides.** Haiku decides, through one control tool `request_deeper_answer { reason }` with `reason` from `ASK_ESCALATION_REASON` = `multi_step` (several dependent counts or filters it is not sure how to combine), `synthesis` (compare, summarise, themes across many links), `depth_requested` (the user asks for detail, "explain", "think harder"), `unsure` (it would otherwise answer with low confidence). The system prompt lists these cases with examples and says to call it before writing any text. Plain lookups, counts, lists and follow-ups stay on Haiku. No model-free classifier and no separate routing call: the first Haiku round either answers, calls library tools, or escalates.
   - **Limits.** At most one escalation per question. Honoured only while no answer text has been streamed and the elapsed time is under `ASK_LIMIT.EscalateBeforeMs` (10 s); otherwise the tool result is an error ("not available now, answer yourself") and Haiku continues. Sonnet is never offered the control tool. A daily and monthly deep allowance per user (`ASK_LIMIT.DeepPerDay` 20, `DeepPerMonth` 150 for the AI pack; Free has no separate cap inside its 5) is counted in `ai_ask_usage.deep`; when it is used up, the tool answers "deeper answers are used up, answer yourself", so the tool list (and the Haiku cache prefix) never changes.
   - **Hand-over.** Sonnet starts a fresh loop with the same system rules, the same history, the same per-question link refs (decision 4), and what Haiku's tools already returned as one fenced data block in the first user message, so no search is repeated. Haiku's own assistant blocks (thinking, tool calls) are not passed across models.
   - **Shown.** A status event `activity: deep` ("Looking closer…") while Sonnet works; `done.depth` (`quick` | `deep`) is in the contract for the web and the logs. No badge on the answer in v1 (open question to the author).
   - **Counting.** Still one question: the escalation is never counted against the question allowance, only against the deep allowance, and only when Sonnet produced text (refund rules of decision 7 apply to both counters together).
2. **Tools** (all read-only, all on the session `userId`, live links only, never another user's rows; argument parsers like ADR 0054: unknown keys, wrong types or out-of-range values are an `is_error` tool result the model can correct; descriptions end with the untrusted-content note):
   - `search_links { query?, folder?, tag?, kind?, site?, savedFrom?, savedTo?, favorite?, offset?, limit? }` — at least `query` or one filter. With a query: words (`buildLinkWhere`, notes only with "Include my notes") fused with meaning (AI-3 vector, only while search is `ready`, the shared `search_queries` allowance and query cache; words only otherwise) by RRF, filters applied to both; without a query: newest first. `limit` 1–20 (default 10), `offset` 0–100. Answer `{ total, hasMore, items: AskToolLink[] }` with `match` `words` | `meaning`.
   - `count_links { query?, folder?, tag?, kind?, site?, savedFrom?, savedTo?, favorite?, groupBy? }` — exact counts; with a query, word matches only (title, URL, summary, tag names, notes with the switch; the description says meaning matches are not counted). `groupBy` from `ASK_GROUP_BY` = `folder` | `tag` | `site` | `kind` | `month`. Answer `{ total, groups: { label, count }[] (top 20), otherCount }`. Tagged `$queryRaw` for site (host of the URL, `www.` dropped) and month (`date_trunc`), Prisma `groupBy` otherwise; never `$queryRawUnsafe`.
   - `get_link { ref }` — one link with the longer fields (summary up to 300, note up to 500 only with the switch, last opened).
   - `list_folders {}` — tree order, path, direct link count (the MCP shape, at most 200, ids replaced by paths).
   - `list_tags { limit? }` — most used first with counts (default 50, at most 100).
   - `show_links { refs }` — a display tool, no data access: 1–12 refs of this question become link cards in the answer at that point of the stream; any unknown ref is an error result.
   - `request_deeper_answer { reason }` — Haiku only, decision 1.
   - Folder and tag filters are names (paths for nested folders), resolved on the user's rows; dates are `YYYY-MM-DD`, UTC in v1, and the first user message carries today's UTC date. `kind` uses `LINK_KIND`.
3. **What the model sees of a link** (`toAskToolLink`, the only mapper, an allow-list pinned by a test): `ref`, title (200), site = host and path without query (120), folder path, tag names (10), kind, favourite, saved date, summary (200 in lists), `match`. Never ids, full URLs with queries, images, reminders, share tokens, page text, or anything of another user. Every free-text value has `<` escaped and sits inside the tool result JSON.
4. **Refs and citations, decided by the server.** A per-request `LinkRefs` registry gives each link a number the first time it reaches the model: links of the history first (in turn order, deterministic, so the history prefix stays cacheable), then tool results. The model cites `[n]` with `n` a known ref; `get_link` and `show_links` take refs only, so a forged UUID or a ref from page text resolves to nothing. `CitationStream` keeps its rules (known refs become `cite`, everything else is text, renumbered by first appearance within the answer, 4,000-character cap); card numbers share that numbering. `done.sources` lists every cited or shown link, re-read live with the session `userId`.
5. **Tool loop and deadlines** (`AskLoop`, provider-neutral; ADR 0052 point 2 amended). At most `ASK_LIMIT.ToolRoundsMax` = 4 tool rounds per profile and 4 tool calls per round (run in parallel; extras answered with an error result), so at most 5 Haiku calls plus, after an escalation, 5 Sonnet calls inside the same budget. Deadlines from the request start: the first output (text or tool call) of each model call within `RoundFirstOutputMs` 8 s of that call's start; a round's tools within `ToolRoundMs` 4 s (a slow tool returns an error result); when the rounds are used up or less than `FinalAnswerReserveMs` 8 s remains, the next call is made with `tool_choice: { type: 'none' }` so the model answers from what it has; hard stop at `StreamMaxMs` 24 s (6 s under `maxDuration` 30) with `done` `truncated: true`, or `error` `unavailable` (refunded) when no text was sent. The 30 s lease is unchanged. A client abort stops the current model call and skips pending tools. Text a model writes before a tool call streams like any other text; thinking is never sent to the client or logged, and thinking blocks are kept only inside the loop that produced them.
6. **Conversation memory: client-held, text only, nothing at rest.** The web keeps the turns of the open panel (or the phone `/ask` page) in memory and sends them back each turn: `AskRequest { question, history?: AskTurn[] }`, `AskTurn { question, answer, links: { n, id }[] }`, where `answer` is the answer text with its `[n]` markers and `links` the cited and shown links. The server writes `done.turn` (its own normalised turn) for the client to store as is. Caps: `HistoryTurnsMax` 10 (the client drops the oldest and says so), question 500, answer 4,000, `LinksPerTurnMax` 20 UUIDs; anything else is a JSON 400 before the stream. The server re-reads the history links with the session `userId` (foreign, trashed or unknown ids dropped, their markers removed) and sends each past answer as an assistant message followed by its links as a fenced `<shown_links>` data block. Tool results of past turns are not replayed. Closing the panel or reloading forgets the chat; nothing about a question, answer, history or tool call is stored or logged. Server-side ephemeral memory was rejected: the function has no shared memory between invocations and any store would be data at rest.
7. **Quotas.** One user question = one count, whatever the rounds, tools or escalation. Reserved before the first model call (advisory lock and statement of ADR 0052 point 7, extended with the deep counter); refunded when no answer text reached the client (failure, refusal, deadline, a client abort before text); once text arrived it counts. Tool rounds that end without text cost tokens but no count; the token counts in the logs let the author watch it. The fixed "not in your links" path without a model call is gone (the model decides); `done.notFound` is true when at least one search ran, every search returned nothing, and the answer cites and shows nothing. Meaning search inside the tool uses the user's `search_queries` allowance (AI pack 10,000 a month covers 4 searches per question at the 500 cap). `RATE_LIMIT.AiAsk` 10 a minute stays.
8. **Prompt injection.** Tool results, history links and history answers are data, never instructions: the system prompt says so, tool descriptions repeat it, free text is escaped and fenced. Tools cannot write, fetch a page, reach another user or take ids. The model's output stays plain text rendered by interpolation (no Markdown, no autolinked URLs, no images), so there is no exfiltration channel. Client-sent history is the user's own input: it can only address the user's own live links and is capped; a forged assistant turn cannot widen access. Specs pin the hostile cases (implementation plan, tests).
9. **Prompt caching.** Order tools → system → messages; one cache breakpoint after the system prompt (the fixed prefix of tools and instructions, about 2,500 tokens, the same for every user and turn of one profile; today's date lives in the first user message, not the system prompt), one on the last history message (the follow-up prefix), and a moving one on the last message of each loop round (rounds are seconds apart, inside the 5-minute TTL). Haiku and Sonnet caches are separate; a provider spec pins the breakpoints, and a preview check confirms both prefixes exceed the model's minimum cacheable length.
10. **Mock** (dev, unit, e2e, CI, every demo user). `MockAiProvider` plans deterministic rounds from the question and history: "how many" or "count" → `count_links` (with `groupBy` for "by folder / tag / site / kind / month"); "find", "show", "list", "which" → `search_links` with the topic words and a month name turned into `savedFrom` / `savedTo`, then `show_links`; "more" or "what else" with history → `search_links` with `offset`; "the first one" → `get_link` on the first history ref; "compare", "in depth", "explain" → `request_deeper_answer`, then the deep profile's canned answer; otherwise search and the existing canned theme or template answer. Triggers: the ADR 0052 ones (`ai-fail`, `ai-refuse`, `ai-slow`, `ai-cut`, `sourdough`) plus `ai-loop` (tools until the round limit, then the forced answer), `ai-bad-args` (an invalid call, corrected after the error result), `ai-deep-late` (escalation after text, refused) and `ai-inject` (echoes instruction-like tool text, for rendering tests). The web mock API emits the same event sequences.
11. **Contract** (`libs/shared/contracts/src/ai/`): new events `activity` (`{ activity: AskActivity; phase: 'start' | 'end'; found: number | null }`, `ASK_ACTIVITY` = `search`, `count`, `read`, `browse`, `deep`; never the tool arguments) and `links` (`{ items: AskSource[] }` cards in stream position); `meta` loses `retrieved`; `done` gains `turn: AskTurn` and `depth`; `AskRequest` gains `history`. Web and API ship together, so the change is not versioned.

## Consequences

- Follow-ups, counts and plain "find it" lists work; answers can show cards; the model chooses how to search instead of a fixed top 10.
- Typical cost per question drops from about $0.013 (ADR 0052, Sonnet) to about $0.005 blended (80% Haiku at under $0.001, 20% escalated at about $0.02); at the 500-a-month cap about $2.50 a month per heavy account, at most about $14 a month in a pathological month bounded by the deep allowance (cost section below).
- Latency rises for questions that need tools: one extra model round trip (about 1–3 s) before text; the activity line covers it. Escalated questions pay a short Haiku round before Sonnet starts.
- Answer quality depends on Haiku's tool choice; the escalation rules and an evaluation set before release (implementation plan) are the guard. If Haiku misroutes often, the default can flip to Sonnet by changing one constant.
- More code on the long-running route: the loop, its deadlines and the deep counter. One migration column (`ai_ask_usage.deep`).
- ADR 0052 stays for transport, the long-running marker, limits, refunds and nothing stored; its status line gets "partly superseded by 0055" when this ADR is accepted.
- Revisit when chats should survive a reload (needs storage and retention), when the Haiku evaluation fails, or when prices change.

## Cost

Assumptions: system prompt and tool definitions 2,500 tokens (cached); question 100 tokens; one compact search result of 10 links 1,500 tokens; a tool call 80 output tokens; thinking after tool results about 300 tokens; answer about 250 tokens; history at turn 10 about 3,700 tokens (9 short turns with their link blocks). "Cold" pays one cache write of the fixed prefix (first question in 5 minutes); "warm" reads it.

## Alternatives considered

- **Sonnet 5.5 for every question** — best tool choice, but about three times the blended cost and slower; kept as the deep profile.
- **Haiku 5.5 only** — cheapest, but weaker at synthesis and multi-step aggregation, which is what the chat is for.
- **A model-free classifier or a separate routing call** — keyword rules misroute paraphrases; a separate call adds a round trip to every question. Haiku's first round already reads the question and can route.
- **Escalation after Haiku has answered** (judge the answer, then redo) — doubles latency and shows two answers or wastes one.
- **Keep the pre-retrieved top 10 and add tools** — saves a round for simple topics, but counts and lists would carry irrelevant context, and the model could not choose filters.
- **Server-side ephemeral memory** — the Vercel Function shares no memory between invocations; Redis or Postgres would be conversation data at rest with retention duties.
- **Replay full tool results in the history** — more context for follow-ups, but several thousand tokens per past turn; the cited and shown links of each turn are what follow-ups refer to.
- **A signed or encrypted history blob from the server** — prevents forged history, but a forged history only hurts the sender's own chat and every link is re-read with the session user; a new secret for no gain.
- **Real link ids for the model (as in MCP)** — would work with user filtering, but per-question refs keep ids out of prompts (ADR 0052) and make forged references impossible by construction.
- **The MCP JSON-RPC layer for Ask** — Ask runs inside the session and needs streaming status events; sharing the mapper rules and shapes is enough.
