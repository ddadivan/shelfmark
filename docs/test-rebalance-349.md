# Test rebalance (#349): audit and plan

Goal ([#349](https://github.com/ddadivan/shelfmark/issues/349)): a full e2e run under ~3 minutes in CI with almost no flaky tests, without losing real coverage. The suite should look like a pyramid: many unit and component tests, contract and visual tests, and e2e only for user journeys. The decision is recorded in [ADR 0043](adr/0043-test-pyramid.md) (proposed).

## 0. Measured baseline

Source: the last full `stage` run, [43421179414](https://github.com/ddadivan/shelfmark/actions/runs/43421179414) (commit `3a8f6aed`). The four blob reports were merged into one JSON. Test counts come from `playwright test --list` on the current `stage` (`6a32a1ed`).

| Executed / self-skipped / flaky in the full run | 1698 / 333 / 0                                                                                                             |
| Worker-seconds (sum of test durations)          | 5657 s: desktop 2035, tablet 1566, phone 2056                                                                              |
| axe tests' share of that time                   | 1922 s (34%), because every axe scan runs in light and dark × 3 projects                                                   |
| Biggest specs (all projects)                    | a11y-app 1031 s, landing 480 s, languages 240 s, folder-style 263 s, mobile 291 s                                          |
| Shard step / job wall                           | 5.4–7.5 min / 6.6–8.9 min. Before the first test runs, ~1.2 min of setup and ~20 s of server start (the web build was cached) |
| Test duration                                   | median 2.6 s, p90 5.9 s, max 17 s                                                                                          |
| **Other CI jobs on the critical path**          | `lint-test-build` **7.4 min** (unit tests 5.7 min); `e2e storybook` **7.1 min** (886 axe stories, 6.9 min)                 |

**Key finding:** the e2e shards are not the only long jobs. Even with e2e at 3 minutes, the CI wall stays at about 7.5 minutes until the Storybook axe entry and `lint-test-build` are split up too (see 5, decision D5).

**Where the time goes.** About 60% of tablet and phone runs repeat a desktop run of the same code:

- tests that set their own viewport (`setViewportSize` / `test.use({ viewport })`) run the same way in every project;
- the overflow matrix in `mobile.spec` sets widths 360/390/768 itself, so the tablet and phone runs are the same;
- feature logic (rating, onboarding, saved views and so on) has no layout branch at all.

## 2. Phases and estimates

How the estimates are made:

- Times come from the baseline durations. Tests newer than the baseline are counted at 5 s.
- Test time per shard = worker-seconds / (shards × 4 workers).
- Job wall = test time + about 1.6 min of fixed cost (setup and server start).

| Phase                                                   | What                                                                                                                                                                                                                                     | Runs (executed)                     | Worker-s | Test time per shard               | Job wall |
| ------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------- | -------: | --------------------------------- | -------- |
| Now                                                     | 3 projects, everything                                                                                                                                                                                                                   | 1698 (+333 self-skipped)            |     5657 | 5.9 min (4 shards)                | 6.6–8.9  |
| **1. Project split + duplicates** (one PR, ~1 day)      | desktop runs the full set; tablet only `@mobile` / `@tablet`; phone only `@mobile` / `@phone`; 22 verified duplicate tests and the 390 width deleted                                                                                     | **756**: desktop 589, phone 128, tablet 39 |    ~2750 | **2.9 min (4 shards), 2.3 min (5)** | ~4.0–4.5 |
| 2. Harnesses + component tests (several PRs, no e2e loss) | CDK harnesses for the 10 libs/ui components in the issue; component specs named in the Later column; static checks to Vitest; fake-timer landing tests. E2e removes only what the new specs prove (landing timers, sign-in lanes, deploy-config) | ~700                                |    ~2150 | 2.2 min (4 shards), 3.0 min (3)   | ~3.5     |
| 3. Journeys only                                        | e2e cut to the issue's ~150 journeys + ~20 axe screens × 2 + ~60 mobile runs; each Later cell removed only when its target spec has landed                                                                                               | ~250                                |    ~1100 | ~2.3 min (2 shards)               | ~3.5     |

Shard count:

- Phase 1: 5 web shards, so the run is under 3 minutes with some headroom (4 would land at about 2.9). The extra runner is free on a public repository.
- Phase 2: back to 4.
- Phase 3: 2.

## 6. Decisions

Decided by the tech lead on Nov 13, 2026 (the ADR stays Proposed until the author accepts it):

- **D1. Yes.** Desktop runs everything; tablet only `@mobile` / `@tablet`; phone only `@mobile` / `@phone` (Playwright tags, per-project `grep`). The constant is `E2E_TAG` (`as const`) in `apps/web-e2e/src/models/e2e-tag.const.ts`. A test that sets its own viewport is never tagged (exception: the touch-only overflow matrix, `@phone`, see ADR 0043).
- **D2. Yes.** The 390px width is dropped from the overflow matrix.
- **D3. Yes.** CI retries 2 → 1.
- **D4. Yes.** 5 web e2e shards for now.
- **D5. Yes, inside phase 1.** The author's goal is the total CI wait. Storybook axe runs in 3 shards; `lint-test-build` is split into parallel jobs with an aggregate job of the same name, so the required checks (`lint-test-build`, `e2e`) still report (3.5).
- **D6.** CDK harnesses only in component tests (phase 2); e2e stays on role locators.
- **D7. OK.** The cut to ~150 e2e tests is phase 3, after the lower-level coverage exists.
