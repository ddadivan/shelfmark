# AI features — feature list

Nov 17, 2026 · approved by the author on Nov 17, 2026 (proposals included) · issue #476, parent #388

This is the product step before any AI code. It expands `docs/PROJECT.md` 5.6 (rules from day one, capability table) into features the author can accept, cut or reorder. The screens are in `docs/design/screens/Ai*.dc.html` (see `docs/design/screens/INDEX.md`, section 12). The provider, models, embeddings and cost ADR come after this document is agreed; the questions for that step are at the end.

Items marked **Proposal** are new ideas or changes to the issues #389–#395, not decisions.

## Principles

These come from 5.6 and hold for every feature below.

1. **Opt-in.** AI is off by default. One switch in Settings › AI turns it on; off means no link data leaves Shelfmark for a model provider.
2. **The app works the same without AI.** Off, quota used, provider down or not processed yet: every screen looks and behaves as it does today. No error toasts on save, ever.
3. **The user always keeps the choice** (author's decision, Nov 17, 2026). People sometimes put a link in a place on purpose, and AI never decides for them:
   - By default AI only suggests: chips inline in Add link and Paste many, applied on a tap.
   - A folder or tags the user picked are never overridden or moved by AI. A quiet suggestion may still show; nothing is applied.
   - Auto-apply is optional and off by default, set per feature in Settings › AI: folder and tags each have **Suggest** (default), **Apply automatically when I don't choose** and **Off**.
   - Anything auto-applied carries the AI mark and is undoable in one step ("Moved to Videos", Undo).
   - Learning from moves only changes future suggestions. Existing links are never re-sorted silently; re-sorting happens only through Tidy Unsorted with a preview.
   - Merges and deletions (clean-up) are never automatic; every bulk change has Undo.
4. **Background only.** Saving a link never waits for a model.
5. **Text only.** Model output is rendered as plain text, schema-validated, never as HTML or Markdown; page text is untrusted input; no tools with side effects.
6. **Privacy.** Link content is sent only to the model provider, only for the feature the user turned on, and never used for statistics: Shelfmark counts AI calls (for quotas) and nothing else.
7. **No real calls outside production.** A mock provider in dev, unit, e2e, CI and the demo; the demo seed has ready tags, summaries and canned answers.

## Disclosure and labelling

Approved by the author on Nov 17, 2026. Why: the EU AI Act (Article 50) requires telling people when they interact with AI and labelling AI-generated text; GDPR requires naming the AI provider as a processor and saying what data is sent; and trust matters. _Verify the exact dates and wording before launch; this is not legal advice._

1. **The mark on everything AI made that the user has not accepted:** tag and folder suggestions, summaries, search-by-meaning results ("why it matched") and Ask your shelf answers carry the AiMark (spark).
2. **Accepted means the user's.** An accepted tag or folder, or an edited summary, is ordinary user data and loses the mark, so the library does not fill with sparkles.
3. **Auto-applied keeps the mark while it can be undone:** "Moved by AI", Undo, in the toast and on the Folder and Tags fields in Edit link, until the user keeps or changes it.
4. **One quiet line for generated text:** chat answers and summaries carry "Generated by AI, may be inaccurate" (translation key `ai.disclaimer`). On cards the line lives in the mark's tooltip and accessible name, to keep the feed calm; it is visible wherever a summary has room (Edit link, search results) and under every chat answer.
5. **First-run intro.** Turning AI on the first time opens a short dialog (sheet on the phone): what AI does, what is sent to the model (address, title, description, extracted page text; never other users' data), that user content is not used to train models, who the provider is, and a link to Settings › AI. Screen `AiIntro`.
6. **Privacy page.** An "AI features (optional)" section names the provider as a processor (placeholder until chosen), lists the data sent, the retention period (placeholder) and how to turn AI off per feature or entirely, consistent with "only counts for statistics". Screen `Privacy`.
7. **No overdoing.** One quiet indigo for the mark, one small gradient tile in the intro, no promotional styling, no "AI-powered" badges: AI is a calm part of the app.

## What makes Shelfmark's AI different

Product choices behind the features below:

1. **AI at the moment of saving.** Suggestions inline in Add link and Paste many, one tap, visibly separate from the user's own data (F1). When the user keeps correcting the same way, offer a plain rule instead of more AI ("youtube.com → Videos?", F1b), which connects AI with Rules without AI (#398).
2. **Reviewable changes.** Clean-up and Tidy Unsorted show a diff with accept or reject per item and one Undo for the whole run (F1a, F5).
3. **Answers grounded in the library only.** Ask your shelf cites real link cards that open, go side by side or get a reminder, and it runs only when asked (F4).
4. **One search.** Meaning-based results inside the existing search, no separate mode. Exact word matches stay first, and each meaning match says why it matched (F3).
5. **Related links** on a link and in side by side (F7).
6. **Rediscover** forgotten links through reminders and Read later (#396) (F8).
7. **A generous Free tier.** Unlimited saves plus a small monthly AI allowance, so AI can be tried without paying. The quota and "limit reached" states are shown honestly.
8. **Privacy as a feature.** AI off by default, a switch per feature, a plain "what is sent" note, no training, and only counts kept for statistics. Zero-retention or EU-hosted providers are an open question.
9. **Your own assistant:** an MCP server so Claude or another assistant can search the library (F6).
10. **Later, not MVP:** OCR of images and screenshots, summaries from YouTube transcripts.

What we already have to build on: nested folders with colours and icons, side by side, reminders, rules, the design and motion language, and a free unlimited core.

## Tiers used below

Monetisation is not built yet (backlog, "Ideas to discuss"). Until it is, every signed-in user who turns AI on gets the **AI pack** limits below, and the author's spend limit in the provider console is the safety net. The tiers are the target shape so that entitlements can be modelled on the account from the start (#389).

| Tier | Price idea (from "Ideas to discuss") | AI in short |
| --- | --- | --- |
| Free | $0 | A taste: suggestions and summaries for a small number of new links per month, semantic search, a few questions |
| Pro | \~$40–50 / year | No extra model cost: the MCP server (**Proposal**), non-AI clean-up checks |
| AI pack | +\~$30–50 / year (bundle \~$80) | Fair-use suggestions and summaries, the whole library processed, Ask your shelf daily limit, AI clean-up |

The exact numbers are placeholders for the pricing discussion; the designs show them as "{n} of {limit}".

**Private phase (author's decision, Nov 17, 2026).** Shelfmark has two users today. Both accounts get everything (Pro and the AI pack) through an allowlist of emails in the environment, the same way as `ADMIN_EMAILS`; every other account stays Free. The plan and quotas are still modelled on the account from the start, so Free / Pro / AI pack can be switched on later without rework. The provider console spend limit stays the safety net.

**Model choice and cost (decided in ADR 0047, prices checked Nov 17, 2026).** Anthropic API, pay as you go (separate from any Claude subscription): Claude Haiku 5.5 ($0.10 / $0.50 per million input / output tokens) for tags, folder, kind and summary; Claude Sonnet 5.5 ($2 / $10) for Ask your shelf; the Batch API (−50%) for processing existing links; prompt caching for the fixed instructions. Embeddings need a separate provider (open question 2). For two users (\~200 new links and \~60 questions a month) that is roughly $0.10 for suggestions and summaries, \~$1.30 for chat, cents for embeddings, and \~$0.50 once to process 2,000 existing links: about **$1–2 a month**, with a spend limit of $10 a month in the console.

## Assumptions for cost

Model prices are the 5.6 estimates (Nov 2026) and are re-checked in the provider ADR. A **typical** user saves \~100 links a month, has \~1,000 links and asks \~30 questions a month. A **heavy** user saves \~500 links a month, has \~5,000 links and asks \~15 questions a day.

## Feature list

### F0. AI foundation and Settings › AI (#389)

- **Problem.** Every AI feature needs the same opt-in, quotas, background jobs, mock provider and degradation; built once, it cannot be forgotten in one feature.
- **What the user sees.** A new settings page **Settings › AI**: one main switch with a plain description of what is sent and to whom; a choice per feature for the folder and for tags (Suggest / Apply automatically when I don't choose / Off, default Suggest); switches for summaries and, later, smarter search and Ask your shelf; "Include my notes" (off by default, **Proposal**); this month's usage as a meter ("38 of 100 links"); a status row when the provider is down or the limit is reached; "Process my existing links" (backfill) with a count and a time estimate; a link to the privacy policy. The privacy policy and Settings › Privacy and data get an AI paragraph.
- **Entry points.** Desktop: settings nav item "AI" (between Library and Notifications). Phone: You › AI. A first-time hint in Unsorted and in the Add link dialog is **not** planned: discovery happens through the settings page and the landing page, so people who keep AI off never see AI.
- **Free vs AI pack.** Same page for both; the meter shows the tier's limit and, at the limit, the date it resets (and later an upgrade button).
- **Privacy.** Nothing is sent by the page itself. The switch is the consent; turning it off stops all jobs at once and keeps what was already generated (with "Delete AI data" to clear summaries, suggestions and embeddings, **Proposal**).
- **Cost.** None by itself.
- **Dependencies.** Contracts and Prisma fields, quota storage, job runner on Vercel, privacy policy text, ADR (provider and jobs).
- **Order.** 1, with F1.

### F1. Tag and folder suggestions (#390)

- **Problem.** Organising is the chore that makes people stop: most saved links sit in Unsorted with no tags.
- **What the user sees.** Under the Tags and Folder fields of Add link and Edit link, a "Suggested" row of dashed chips: up to three of the user's **existing** tags and one existing folder, plus at most one clearly marked **new** tag. Tap a chip to apply it (it turns into a normal sage tag); × dismisses it; "Add all" applies the row. While the job runs, two skeleton chips; nothing at all when AI is off, nothing found, or the provider fails. When the user has already picked a folder, the folder suggestion is only a quiet chip and is never applied for them; the same for tags. With **Apply automatically when I don't choose** on, a link saved to Unsorted (or with no tags) gets the suggestion applied in the background; a toast says so with Undo ("Moved to Videos"), and the folder or tag carries the AI mark ("Moved by AI", Undo, in Edit link) until the user keeps or changes it. On cards and rows, a link with pending suggestions shows nothing extra (no badge clutter); suggestions surface in the dialog and in "Tidy Unsorted" (F1a).
- **Entry points.** Desktop: Add link dialog (after the preview loads), Edit link dialog, Paste many (a suggested folder per link in the review list). Phone: the Add link sheet and the Edit sheet; the Share target quick form.
- **Free vs AI pack.** Free: new links up to the monthly limit. AI pack: fair use, plus processing the existing library (backfill through the Batch API).
- **Privacy.** Sent: URL, page title, the site's description, a size-limited page text excerpt (fetched through the SSRF guard), and the **names** of the user's tags and folders. Not sent: notes (unless "Include my notes" is on), other links, account data.
- **Cost.** \~$0.0004–0.001 per link (Haiku-class, structured output; one call shared with F2, see **Proposal** below). Typical \~$0.05–0.10 / month; backfill of 1,000 links \~$0.20–0.50 once with the Batch API.
- **Dependencies.** F0. Rules without AI (#398) are complementary: a domain rule applies first and the model is not asked about what a rule already decided (**Proposal**).
- **Order.** 1 (MVP).

**Proposal — one call for F1 and F2.** Tags, folder and summary are produced by the same background job with one structured response (`{ tags, newTag, folder, summary, kind }`), so a link costs one call, not two, and both appear together. The two features keep separate switches; a switched-off part is simply not requested.

### F1c. Fill in with AI (author's decision, Nov 18, 2026; extends #390)

- **Problem.** Accepting chips one by one is slow, especially on a phone.
- **What the user sees.** In Add link and Edit link, once suggestions are ready, a **Fill in with AI** button (spark) applies everything AI proposes in one click: the suggested folder, the existing tags and the summary. A new tag stays a chip; a folder or tags the user already chose are never replaced. Every field stays editable, and the applied values are ordinary user data after the click (no "Moved by AI" mark: the click is the user's choice). Desktop shortcut; on the phone the button sits in the Add link sheet. The same one-click idea already exists as "Apply to N links" in Tidy Unsorted and "Apply selected" in clean-up, and comes to the Paste many and Import review lists with AI-2 ("Use suggested folders").
- **Free vs AI pack, privacy, cost.** Nothing new: it applies F1 and F2 results.
- **Order.** AI-1.1, right after AI-1 (small: one button, one shortcut).

### F9. Links from a screenshot (author's decision, Nov 18, 2026)

- **Problem.** Many things are saved as screenshots (a post, a product, a video) because the app they came from has no shareable link.
- **What the user sees.** Paste, drop or (on the phone) share a screenshot to Shelfmark. AI reads the image and offers the addresses it finds as a review list (like Paste many); when there is no address, it offers a title and a short note (for example a product and the shop) to save as a link-less reminder or to search for. Nothing is saved until the user confirms.
- **Entry points.** Desktop: Add link (paste or drop an image), Paste many. Phone: the Share target accepts images, and the Add link sheet has "From a screenshot".
- **Free vs AI pack.** Same monthly limit as F1 (one image counts as one link).
- **Privacy.** The image goes to the model provider for this one request; **Shelfmark never stores the screenshot**, only what the user saves from it. The AI intro and the privacy page say so.
- **Cost.** One image is about $0.0002–0.0005 with Claude Haiku 5.5.
- **Dependencies.** F0, the Share target (exists), image input in the provider. No embeddings.
- **Order.** AI-2.

### F1b. Learn from corrections, then offer a rule (**Proposal**, extends #390 and #398)

- **Problem.** AI that keeps guessing wrong is annoying, and AI that keeps guessing right for the same site is wasted money.
- **What the user sees.** Shelfmark notices patterns in what the user accepts, dismisses and moves: links from one site that always end up in one folder or with one tag. Corrections feed the next suggestions for that user (the last few choices are passed as examples). Learning only changes future suggestions: links already saved are never re-sorted on their own; to re-sort, the user opens Tidy Unsorted and reviews a preview. After the same choice three times, a toast offers a plain rule: "Always put youtube.com links in Videos?" with "Create rule" and "Not now". A rule needs no model and always wins over AI.
- **Entry points.** The toast after a save or a move; the created rule shows in Settings › Library › Rules (#398).
- **Free vs AI pack.** Free: rules are not AI.
- **Privacy.** Only the user's own accept, dismiss and move events, kept with the user's data, never used for statistics.
- **Cost.** Lowers cost: every rule removes model calls.
- **Dependencies.** F1, Rules without AI (#398).
- **Order.** 2, with F1a.

### F1a. Tidy Unsorted — review suggestions in bulk (**Proposal**, extends #390)

- **Problem.** Suggestions in the edit dialog help one link at a time; the real pile is Unsorted (17 links in the demo, hundreds after an import from Pocket).
- **What the user sees.** In Unsorted, a "Tidy with suggestions" button above the feed when at least one link has suggestions. It opens a review page: one row per link with its suggested folder and tags as dashed chips, each chip toggles; "Apply" per row, "Apply all" at the top, "Skip" to leave a link. Applying moves links and adds tags in one step, with Undo in the toast (the same pattern as bulk actions). Empty state: "Nothing to tidy — every link here already has a home."
- **Entry points.** Desktop: Unsorted page header; after an import's summary ("Tidy the imported links"). Phone: Unsorted page header; the review is a full page with one card per link.
- **Free vs AI pack.** Works on whatever already has suggestions; the backfill that fills it for old links is AI pack.
- **Privacy.** No extra data; uses F1 results.
- **Cost.** None beyond F1.
- **Dependencies.** F1; bulk move and tag actions (exist); Import (#387) makes it far more useful.
- **Order.** 2 (right after F1; small, high value).

### F2. Short summaries (#391)

- **Problem.** Months later, a title like "Untitled" or "Watch this" says nothing about why the link was saved.
- **What the user sees.** One or two sentences under the title on cards (`sm-card__note` slot, two lines) and in list rows (one line), with a small spark mark until the user edits it. Kind-aware: an article's gist, a video's topic, a product's key facts (price is never invented, only taken from the page). In Edit link, a "Summary" field the user can edit, clear or regenerate; an edited summary is the user's and is never overwritten. The user's note always wins the card slot when both exist; the summary then shows in the edit dialog and in search results. Pending: a one-line skeleton on the card for a few seconds after save, then the summary fades in. Failed or off: nothing, as today.
- **Entry points.** Desktop and phone: cards, rows, Edit link, search results.
- **Free vs AI pack.** Same limits as F1 (one job).
- **Privacy.** Same data as F1, no tag names needed. Summaries are written in the user's interface language (**Proposal**).
- **Cost.** Included in the F1 call; alone \~$0.0004–0.001 per link.
- **Dependencies.** F0; `summary` and `summarySource: 'ai' | 'user'` in the contracts.
- **Order.** 1 (MVP, with F1).

### F3. Smarter search (#392)

- **Problem.** People remember what a link was about, not its words: "that talk about signals and performance", "the grey coat".
- **What the user sees.** The same search (⌘K and the phone Search tab) finds by meaning as well as words; the search field's placeholder already says "Search, or describe it". Results get no new chrome: matches by meaning are mixed in after exact word matches, with a quiet "Related by meaning" divider and the spark mark. Each meaning match shows a short "why it matched" line (the tag, folder or summary words that are close to the query), so results never feel random. When embeddings are not ready (off, quota, not processed yet), search is exactly today's. Settings show "Search by meaning: 840 of 1,000 links ready".
- **Entry points.** Desktop: ⌘K search dialog and the header search. Phone: Search tab.
- **Free vs AI pack.** Free (**Proposal**): embeddings are cheap and "find it again" is the product's core promise; it is a strong reason to turn AI on. Backfill of a large library may be AI pack only.
- **Privacy.** Sent to the embeddings provider: title, summary, tag names and the note only if "Include my notes" is on. The query text is sent at search time. Vectors are stored in Neon (pgvector) next to the link and deleted with it.
- **Cost.** Embeddings \~$0.00002 per link; queries are negligible. Typical well under $0.01 / month.
- **Dependencies.** F0, pgvector migration, ADR (embedding model, dimensions, index, ranking merge). Better with F2 (summaries make embeddings better).
- **Order.** 3.

### F4. Ask your shelf (#393)

- **Problem.** Sometimes the question is not "where is that link" but "what did I save about X": "Which ramen recipes did I save?", "Compare the two coats I liked".
- **What the user sees.** A chat panel that answers only from the user's links: the answer streams in as plain text with numbered citations, and every cited link is listed below as a real link row (favicon, title, folder) with its usual actions: open, open side by side, remind me. It runs only when the user asks; nothing in the library is read in the background for chat. Suggested starter questions built from the user's own folders. A clear daily limit line ("12 questions left today"). Refuses to answer beyond the library ("I couldn't find that in your links"). No memory between sessions for v1 (**Proposal**: keeps privacy and cost simple).
- **Entry points.** Desktop: an "Ask your shelf" item at the bottom of the ⌘K search results ("Ask: <query>") and a header button with the spark mark; the panel opens on the right as a side panel over the feed. Phone (author's decision, Nov 18, 2026): an **Ask** tab with the spark replaces **Tags** in the tab bar while AI is on (tags move into Library as their own section next to folders; with AI off the bar keeps Tags), and the chat opens full screen.
- **Free vs AI pack.** Free: a few questions a month (a taste). AI pack: fair-use daily limit.
- **Privacy.** Sent: the question and the top \~10 retrieved links (title, URL, summary, tags; notes only with the switch). Answers are not stored server-side beyond the session (**Proposal**).
- **Cost.** \~$0.013 per question (Sonnet-class). Typical \~$0.40 / month; heavy (15 a day) \~$6 / month, which is above the AI pack price, so the fair-use limit or a cheaper answer model is needed (open question).
- **Dependencies.** F0, F3 (retrieval), streaming from the API (Vercel functions stream on Node), prompt-injection tests.
- **Order.** 4.

### F5. Library clean-up (#394)

- **Problem.** Big libraries rot: the same page saved three times under different URLs, links that 404, "js" next to "javascript".
- **What the user sees.** Settings › AI or the Library page: "Clean up your library" opens a report with three groups — duplicates (keep one, the rest go to Trash), dead links (offer the Wayback copy, from #397) and similar tags (merge into one). Every group is a preview with checkboxes; "Apply selected" runs it in one step with Undo; deletions go through Trash.
- **Entry points.** Desktop: Settings › Library › "Clean up", and a quiet card on All links when the report finds something (**Proposal**: at most once a month, dismissible). Phone: You › Library › Clean up, full page.
- **Free vs AI pack.** **Proposal — split:** exact duplicates (same normalised URL) and dead links need no model and go to Pro / Free; near-duplicates (embeddings) and tag synonyms (model) are AI pack.
- **Privacy.** Tag synonyms send only tag names. Near-duplicates use stored vectors; nothing new is sent.
- **Cost.** \~$0.01 per run for 1,000 links; negligible.
- **Dependencies.** F0, F3 (vectors), dead-link check (#397), Trash (exists), Undo of a multi-change run.
- **Order.** 5.

### F6. Shelfmark MCP server (#395)

- **Problem.** People already use Claude or another assistant; they want it to search their saved links without copy-paste.
- **What the user sees.** Settings › AI › "Connect your assistant": a short how-to per client, a personal token (create, copy once, revoke) or an OAuth connection, and a list of connected clients with last use. Read-only for v1: search, read a link, list folders and tags.
- **Entry points.** Desktop and phone: Settings › AI. Landing page mention later.
- **Free vs AI pack.** **Proposal:** Pro, not the AI pack: the user's own assistant pays for its model, so Shelfmark has no model cost.
- **Privacy.** The user's assistant receives what its tools return; the token is scoped to one user and read-only; revoking stops it at once.
- **Cost.** No model cost; API compute only.
- **Dependencies.** Personal tokens or OAuth on Better Auth, rate limits, ADR (transport, auth). Independent of F1–F5.
- **Order.** 6 (can move earlier: it is the cheapest feature to run, and a good portfolio piece).

### F7. Related links (**Proposal**)

- **Problem.** A saved link is often one of several on the same topic, saved months apart in different folders.
- **What the user sees.** In Edit link (and later a link detail), a "Related on your shelf" list of up to five links close in meaning, with the spark mark. In side by side, "Show related" fills the right half's picker with related links' folders.
- **Entry points.** Desktop: Edit link, side by side. Phone: the Edit sheet.
- **Free vs AI pack.** Free once embeddings exist (no model call: a vector query).
- **Privacy.** Nothing new is sent; uses stored vectors.
- **Cost.** Negligible.
- **Dependencies.** F3.
- **Order.** After F3.

### F8. Rediscover (**Proposal**)

- **Problem.** People save far more than they come back to.
- **What the user sees.** A weekly "From your shelf" block (in the app and in the reminders digest, #275): three to five forgotten links grouped by a theme the user cares about now (from recent saves), each with "Remind me", "Read later" (#396) or "Not interested".
- **Entry points.** Desktop and phone: top of All links once a week (dismissible), the weekly digest.
- **Free vs AI pack.** Free with a plain "not opened for a long time" choice; the AI pack picks by theme.
- **Privacy.** No data is sent beyond F3 vectors; the theme is computed from the user's own links.
- **Cost.** Negligible.
- **Dependencies.** F3, reminders, Read later (#396).
- **Order.** After F4.

## Other proposals

- **Describe a view (later).** "Save this view" accepts a sentence ("videos about Angular I haven't opened") and turns it into the existing saved-view filters, shown for review before saving. Cheap (one small call), reuses saved views (ADR 0038). Not designed now.
- **Kind detection.** The F1 call also returns the link `kind` when the URL rules (ADR 0038) say "other", so saved views like Videos and Articles get more accurate. No extra cost.
- **Cut from MVP:** creating new folders from suggestions (only existing folders are suggested; new tags only as one marked chip), chat memory, write access in MCP.
- **Postpone:** AI clean-up until the dead-link check (#397) exists, so there is no second checker.

## AI identity (design summary)

Full rules are in `docs/design/BRAND.md` › AI and the component specs `AiMark`, `Suggestion`, `AiSummary`.

- **One mark, one quiet colour.** A new `spark` icon (four-point star, same 1.75px line as the set) marks everything the model produced, in a calm indigo (`ai` tokens) so AI is recognisable without loud styling. The only gradient is the small tile at the top of the first-run intro (author's choice, Nov 17, 2026).
- **Suggested ≠ yours.** The user's data is solid (sage tag chips, normal text). AI suggestions have a dashed indigo edge and no fill (dashed already means "not there yet" in "Save this view"). Accepting turns a dashed chip into a solid one.
- **Sage stays the user's signal.** AI never uses `accent` fills.
- **Quiet when absent.** Off, failed or empty: the space collapses, no placeholder, no error toast.
- **Always undoable.** Single accepts are one tap to remove; bulk applies have Undo.

## Open questions for the implementation step

Questions 1, 2, 4 (prices and limits), 7 and 9 are answered by ADR 0047 (`docs/adr/0047-ai-provider-models-and-cost.md`): Anthropic API (Claude Haiku 5.5 for link jobs, Claude Sonnet 5.5 for chat), Voyage `voyage-4-lite` embeddings in pgvector, `AI_FULL_ACCESS_EMAILS` for the private phase, keys only in the environment. Still open: 3 (job runner, in the #389 plan), 5, 6, 8, 10.

1. **Provider and models.** Anthropic (Haiku-class for jobs, Sonnet-class for chat) vs others, or a self-hosted open model; Vercel AI Gateway or a direct SDK; fallback model when the provider is down; an EU-hosted option. Zero data retention and "no training on API data" terms must be confirmed in writing for the privacy policy.
2. **Embeddings.** Which provider (Anthropic has no embeddings API; Voyage, OpenAI or an open model), dimensions, pgvector index type (HNSW vs IVFFlat) on the Neon plan, re-embedding when the model changes.
3. **Job runner on Vercel.** Where background jobs run (Vercel Queues, Workflow, a cron that drains a table, or `waitUntil` after the response), retries, and the Batch API for backfill.
4. **Cost and limits.** Real token counts per link with a page excerpt; the Free monthly link limit; the Ask daily limit and whether chat needs a cheaper model to stay under the AI pack price; the author's monthly spend cap.
